# 02. 実装方式の比較と推奨構成

## 方式の候補

| 方式 | 内容 | 長所 | 短所 | 評価 |
| --- | --- | --- | --- | --- |
| A. ソフト CPU + エミュレータ | FPGA に RISC-V（VexRiscv や PicoRV32）を載せ、C で書いたエミュレータを動かす | 実装が最も簡単。ISA の全体をソフトで再現できる | 「FPGA で動かす」意味がほとんどない。遅い（1 PE 1 サイクルに数百命令） | 練習用。主目標にはしない |
| B. ハードウェアの忠実な縮小コア | 426bit をそのままデコードする HW。PE データパス、MAU、L1BM/L2BM、MV を縮小トポロジで実装する | 狙いどおりの成果になる。段階的に機能を増やせる | 作業量が大きい | **推奨** |
| C. B + 仮想 PE | B のデータパスを時分割で使う。PE 状態は SDRAM に置き、BSRAM をワーキングバッファにする | 64〜128 PE まで広げられる | SDRAM コントローラと、メモリアクセスのスケジュールが必要 | B の後半で移行する |
| D. ホスト側で事前デコード | PC 側で 426bit を独自のマイクロコードに変換して流す | FPGA 側が単純になる | 「機械語をそのまま動かす」から外れる | 初期のデバッグ専用。P1 のデコーダで代用できる |

### 設計方針

1. **426bit 語はそのまま受け取る。** デコーダはフィールドを切り出すだけにする。
   フィールド表は P1 で作り、Python の `fields.yaml` から Verilog の `localparam` を自動生成する。
2. **4 サイクル / 1 ステップは逐次に処理する。** 物理クロック数はいくら増えてもよい。
   意味論（全入力を読んでから書く、フォワーディングの値を参照するタイミング）だけを正確に再現する。
   性能は求めない。
3. **PE データパスは 1 本から始める。** 4 PE（1 MAB）は時分割で回す。
   SIMD の精度（d/f/h）はレーンごとに逐次処理してよい。
4. **浮動小数点ユニットは 1 個を共有する。**
   - 倍精度の FMA を基本にする。仮数 53×53 の乗算は 18×18 の乗算器 9 個、または多サイクルで 4 個程度で作れる。
   - 単精度と半精度は同じユニットで MN-Core 形式に正規化して処理する。
   - 丸めとフラッシュの扱いは `float.rs` に合わせる。
5. **メモリサイズはパラメータにする。** 最初は LM を 256 長語程度に縮める。
   LM の範囲外を触るプログラムは「非対応」として検出する。
6. **ホストとのやり取りは `d set` / `d get` と同じ形式にする。**
   公式エミュレータや Rust Sim の dmp とテキストで diff を取れるようにする。
7. **MV は同期実行でよい。** ただし wait のタグは解釈する。
   非同期の競合は `assemble3` のハザード検査で弾かれる前提とする。

### 縮小トポロジでの「正解」の定義

縮小トポロジの結果が正しいかどうかは、次のどちらかで判定する。

- (a) **Rust Sim にトポロジのパラメータを足す**（L2B 数、L1B 数、MAB 数を指定できるようにする）。
  FPGA と同じ縮小構成で実行してゴールデンにする。
  → 一番正確。`viz/core` の定数を変える作業が必要になる。
- (b) 4096 PE のまま公式 / Rust で実行し、対象の PE（例: n0c0b0m0 の 4 PE）の状態だけを比べる。
  → PE をまたぐ通信（L1BM/L2BM の縮約、Bcast）がない命令列にしか使えない。

**推奨: 初期は (b) で ALU と FP を検証し、L1BM 以上を実装する段階で (a) に移行する。**

## 主なリスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| エンコード表が完成しない（まれな修飾子や MV の細部） | 一部の命令を動かせない | P1 で、手元の 959 本の `.vsm` と 1,041 語（Lean の evidence）について往復一致を必須にする。対象外の語は検出して停止する |
| FP のビット一致（独自形式、block float、RRN の丸め） | 数値がずれる | `float.rs` を基準に、ランダムベクタを数万件生成して iverilog で照合する |
| フォワーディングとハザードのタイミング | 「1 語前の値」の解釈を誤る | `hazard.rs` と Lean の `lbf-encoded` の evidence（11 ケース）をテストに取り込む |
| BSRAM の不足 | 構成が縮む | 早めに仮想 PE + SDRAM 方式（C）に移る |
| GW2A の SDRAM コントローラ | 時間がかかる | 既存の OSS 実装（Tang Nano 20K 用の sdram コントローラ例）を使う |
| 公開範囲 | 権利まわりの懸念 | バイナリは再配布しない。フィールド表の公開は別途判断する |
