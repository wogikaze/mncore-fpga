# ホストとの通信プロトコル（版 1）

Tang Nano 20K の FPGA（`brd_host_if`）と PC（`mncore/tools/host/mnhost.py`）の間で使う UART プロトコル。
契約 §7 の枠組みに従い、WP04 が詳細を決めた。

## 1. 物理層

| 項目 | 値 |
| --- | --- |
| 経路 | FPGA ↔ BL616（USB-UART）↔ PC。Windows では COM ポート（VID:PID 0403:6010、FTDI 互換） |
| ピン | FPGA 出力 `uart_tx` = **69**、FPGA 入力 `uart_rx` = **70**（下の出典） |
| 形式 | 8N1、LSB first、フロー制御なし |
| 初期速度 | 1 Mbaud（ビットストリームのパラメータ `BAUD`）。`SET_BAUD` で実行中に変えられる |
| 分周 | `div_q8` = 1 ビットあたりのクロック数 × 256（固定小数点）。27 MHz で 1M = 6912、2M = 3456（13.5 クロック）、3M = 2304。最小 1024（4 クロック） |

ピンの出典: Sipeed 公式の例 [TangNano-20K-example `uart/src/top.cst`](https://github.com/sipeed/TangNano-20K-example/blob/d8e3cfb86ac19966244cc99d12c1da84d7ba4199/uart/src/top.cst)
（`IO_LOC "uart_rx" 70; IO_LOC "uart_tx" 69;`）。同じリポジトリの `picorv32/src/fpga_project.cst` も `ser_tx` を 69 に置いている。

## 2. フレーム

```
0xA5 | cmd u8 | len u16le | payload[len] | crc8
```

- 多バイトの整数はすべて**リトルエンディアン**。64bit の長語も 8 バイトの LE で送る（長語 `0x0123456789abcdef` は `ef cd ab 89 67 45 23 01`）。
- `crc8` は **CRC-8/SMBUS**（多項式 0x07、初期値 0x00、反転なし、最終 XOR なし）。対象は `cmd`、`len` の 2 バイト、`payload`（0xA5 は含めない）。
  検査値: `"123456789"` → `0xF4`。
- 応答は `cmd | 0x80` で返す。応答の `payload[0]` は**状態コード**、`payload[1..]` が本体。
- 1 つの要求に必ず 1 つの応答を返す（フレームが途中で途切れた場合を除く）。応答は要求の順に返る。

### 受信の規則

| 状況 | FPGA の動作 |
| --- | --- |
| 待機中に 0xA5 以外のバイト | 読み捨てる |
| フレームの途中で 20 ms（`TIMEOUT_CYC`）バイトが来ない | フレームを捨てて待機に戻る。応答しない。`timeout` を数える |
| CRC 不一致 | `E_CRC` を返す（`cmd` は受け取ったもの）。**ペイロードは実行しない** |
| `len` が受信バッファ（`pbuf`、既定 2048 バイト）より大きい | ペイロードを読み捨ててから `E_LEN` を返す |

ペイロードは受信バッファに溜め、CRC が一致してから実行する。壊れたフレームがメモリを書き換えることはない。
ホストは `E_CRC` や応答のタイムアウトのとき、20 ms 以上待ってから同じ要求を再送してよい（`RUN` 以外は冪等）。

### 状態コード（応答の `payload[0]`）

| 値 | 名前 | 意味 | 本体 |
| --- | --- | --- | --- |
| 0x00 | `OK` | 成功 | コマンドごと |
| 0x01 | `E_CRC` | 要求の CRC 不一致 | なし |
| 0x02 | `E_CMD` | 未知のコマンド | なし |
| 0x03 | `E_LEN` | `len` がコマンドの形式に合わない、または `pbuf` を超える | なし |
| 0x04 | `E_BUSY` | コアが実行中（`RUN` 中の `RUN` / `WR_*` / `RD_MEM`） | なし |
| 0x05 | `E_RANGE` | メモリポートが拒否した（空間・位置・アドレスが範囲外、2^23 以上のアドレスを含む） | `index u32`: 失敗した語の番号（0 起点）。それより前の語は書き込み済み |
| 0x06 | `E_ARG` | 引数が不正（`RD_MEM` の n が大きすぎる、`SET_BAUD` の分周が小さすぎる） | なし |

## 3. コマンド

| cmd | 名前 | 要求の payload | 応答の本体（状態コードの後） |
| --- | --- | --- | --- |
| 0x01 | `PING` | 任意のバイト列（0〜`pbuf`） | 同じバイト列（エコー） |
| 0x02 | `INFO` | なし | 下の表（88 バイト） |
| 0x03 | `WR_IMEM` | `addr u16`、命令語 × k（各 56 バイト） | なし |
| 0x04 | `WR_MEM` | `space u8`、`mask u8`、`loc u16`、`addr u32`、長語 × n | なし |
| 0x05 | `RD_MEM` | `space u8`、`0 u8`、`loc u16`、`addr u32`、`n u16` | 長語 × n |
| 0x06 | `RUN` | `start u16`、`count u32` | なし（開始の受理だけ。終了は `STATUS` で待つ） |
| 0x07 | `STATUS` | なし | 下の表（27 バイト） |
| 0x08 | `RESET` | なし、または `flags u8`（bit0: リンクの誤り計数も消す） | なし |
| 0x09 | `SET_BAUD` | `div_q8 u32` | なし（旧速度で返したあと切り替える） |

### WR_MEM / RD_MEM

- `addr` は**長語単位**（契約 §6 のメモリバスと同じ）。n 語は `addr`, `addr+1`, … に書く／から読む。
- `mask` は全語に共通のバイトマスク。bit i が長語の `[8i+7:8i]` に対応する（`0xFF` で全体）。
- 1 フレームの上限: `WR_MEM` は `(pbuf − 8) / 8` 語（2048 なら 255 語）、`RD_MEM` は `pbuf / 8` 語（256 語）。ホストが分割する。
- `loc` は PE の位置（下の §4）。`space` と `loc` の組み合わせの解釈は接続先のコアが決める。

### WR_IMEM

- 命令メモリは space 0（`IMEM`）。1 エントリ = 448bit = 7 長語（レーン 0〜6）。
- `addr` はエントリ番号。エントリ e のレーン k は、IMEM 空間の長語アドレス `e*8 + k` に書く（レーン 7 は使わない）。
  `RD_MEM(space=0, addr=e*8+k)` で読み戻せる。
- 送るのはレーン 0 から 6 の順に 7 長語（各 8 バイト LE）。`len − 2` は 56 の倍数でなければ `E_LEN`。

### 命令メモリのエントリ形式（448bit）

| ビット | 内容 |
| --- | --- |
| `[447:446]` | 種類: `01` = `j` 語（PE、426bit）、`10` = `m` 語（MV、82bit）、`00` = 空（コアは `E_DECODE` で止まる）、`11` = 予約 |
| `[445:426]` | 0 |
| `[425:0]` | `j` 語。**`entry[425-pos]` が文字列の pos に対応**（契約 §2 の `jw[425-pos]` と同じ。`entry[425:0]` をそのまま `jw` に渡せる） |
| `[81:0]` | `m` 語のとき。`entry[81-pos]` が pos（上位の `[425:82]` は 0） |

`.asm` の `j` / `m` 行は、出現順にエントリ 0, 1, 2, … に積む（`d` 行は積まない）。

### RUN / STATUS / RESET

- `RUN(start, count)`: 命令メモリのエントリ `start` から `count` 個（`j` と `m` を合わせた数）を実行する。
  - 応答はすぐ返る。ホストは `STATUS` を読んで `state = 0` になるまで待つ。
  - コアは `count` 個を発行し、**発行したものがすべて完了してから**（MV を含めて）止まる。
  - PE の記憶、T、フォワーディング用のレジスタなどのアーキテクチャ状態は RUN をまたいで保つ。消すのは `RESET` だけ。
    これにより、ホストは `d get` の位置で RUN を分割したり、大きなプログラムを命令メモリに分けて積んだりできる。
- `STATUS` の本体:

| オフセット | 型 | 内容 |
| --- | --- | --- |
| 0 | u8 | `state`: bit0 = コア実行中 |
| 1 | u8 | 停止理由: 0 `OK`、1 `E_RANGE`、2 `E_UNSUPPORTED`、3 `E_DECODE`（契約 §7） |
| 2 | u16 | `pc`: 停止時のエントリ番号（次に実行するもの、または止まったもの） |
| 4 | u32 | `info`: `E_RANGE` なら語番号、`E_UNSUPPORTED` ならフィールド番号（コアが決める） |
| 8 | u32 | `steps`: 直前の RUN で実行したエントリ数 |
| 12 | u16 | `crc_err`: CRC 不一致の数 |
| 14 | u16 | `frame_err`: UART のフレーミング誤り（ストップビットが 0）の数 |
| 16 | u16 | `overrun`: 受信 FIFO があふれて落としたバイト数 |
| 18 | u16 | `timeout`: 途中で途切れたフレームの数 |
| 20 | u16 | `meas`: 最後に受けたバイトの、スタートビットの立ち下がりから最後の立ち上がりまでのクロック数。0x55 を送ると 9 ビット分になり、ホストの実際のボーレートが測れる |
| 22 | u32 | 現在の `div_q8` |
| 26 | u8 | bit0: `SET_BAUD` の仮採用中、bit1: 切り替え待ち |

- `RESET`: コアに `core_rst` を 16 クロック出す（実行中なら止める）。ボーレートは変えない。

### INFO の本体

| オフセット | 型 | 内容 |
| --- | --- | --- |
| 0 | u8 | プロトコルの版（1） |
| 1 | u8 | デザイン ID（0x01 = `board_test`、0x02 = `mn_top_1pe`（WP21）） |
| 2 | u16 | `pbuf`: 受信バッファのバイト数 = `len` の上限 |
| 4 | u32 | クロック周波数（Hz） |
| 8 | u32 | 現在の `div_q8` |
| 12 | u16 | 命令メモリのエントリ数 |
| 14 | u8 × 5 | 実装しているトポロジ: グループ、L2B、L1B、MAB、PE の数（各次元で 0 から連続。0 はその空間なし） |
| 19 | u8 | bit0: 実物のコアが接続されている、bit1: RUN スタブ |
| 20 | u32 × 16 | 空間 0〜15 の深さ（長語）。0 は「その空間はない」 |
| 84 | u16 | 受信 FIFO のバイト数 |
| 86 | u16 | 送信 FIFO のバイト数 |

### SET_BAUD

1. ホストは現在の速度で `SET_BAUD(div)` を送る。`div = round(clk_hz * 256 / baud)`。
2. FPGA は `OK` を**旧速度で**返し、送信し終わってから新しい分周に切り替え、「仮採用」に入る。
3. ホストは自分の速度を切り替え、`PING` を送る。CRC が正しいフレームを 1 つ受けた時点で確定する。
4. 1 秒（`PROBATION_CYC`）以内に正しいフレームが来なければ、FPGA は旧速度に戻る。
   ホストは失敗したら旧速度に戻し、1.5 秒待ってから `PING` で確認する（`mnhost.py` はこれを自動で行う）。

ボードの S1 ボタン（ピン 88）を押すと、`board_test` はボーレートも含めて初期状態に戻る。

## 4. 空間と位置

### 空間 ID（`space`）

| ID | 名前 | 単位 | 備考 |
| --- | --- | --- | --- |
| 0x00 | `IMEM` | 長語（エントリ × 8 + レーン） | 命令メモリ |
| 0x01 | `LM0` | 長語 | `$m` / `$lm` |
| 0x02 | `LM1` | 長語 | `$n` / `$ln` |
| 0x03 | `GRF0` | 長語 | `$r` / `$lr` |
| 0x04 | `GRF1` | 長語 | `$s` / `$ls` |
| 0x05 | `T` | 長語 | サイクル c の 2 長語のうち、MSB 側がアドレス `2c`、LSB 側が `2c+1`（0〜7） |
| 0x06 | `L1BM` | 長語 | `$lb` |
| 0x07 | `L2BM` | 長語 | `$lc` |
| 0x08 | `PDM` | 長語 | `$p` |
| 0x09 | `DRAM` | 長語 | `$d` |
| 0x0F | `TEST` | 長語 | `board_test` の試験用メモリ（64 KiB） |
| その他 | | | 予約。0x10 以上はデザインごとに自由 |

PE の記憶（LM0/LM1/GRF0/GRF1）の命令上のアドレスは単語（32bit）単位なので、長語アドレスは `単語アドレス / 2`。
単語アドレス w は長語 `w/2` の、w が偶数なら上位 32bit、奇数なら下位 32bit（SDM 3.4.4 例 3 と、公式エミュレータで確認した）。

### 位置（`loc`、u16）

チップ上の座標をそのまま詰める（実装しているかどうかに関係なく、実チップでの番号）。

```
loc = n<<10 | c<<9 | b<<6 | m<<2 | p      n: グループ 0..3, c: L2B 0..1, b: L1B 0..7, m: MAB 0..15, p: PE 0..3
```

L1BM は `m = p = 0`、L2BM は `b = m = p = 0`、PDM / DRAM は `n` だけを使う。

## 5. コア側のインタフェース（`brd_host_if` のポート）

すべて `clk` に同期。`rst` は同期・正論理。

| 群 | 信号 | 規則 |
| --- | --- | --- |
| メモリ書き込み | `mw_valid`、`mw_ready`、`mw_err`、`mw_space[7:0]`、`mw_loc[15:0]`、`mw_addr[22:0]`、`mw_data[63:0]`、`mw_mask[7:0]` | `mw_valid && mw_ready` で 1 語を受け渡す。同じサイクルの `mw_err = 1` は拒否（書かない）で、ホストには `E_RANGE` が返る |
| メモリ読み出し | `mr_valid`、`mr_ready`、`mr_err`、`mr_space`、`mr_loc`、`mr_addr`、`mr_rsp_valid`、`mr_rsp_data[63:0]` | 要求は同上。受理した要求 1 つにつき `mr_rsp_valid` を 1 回、要求の順に返す（受理と同じサイクルでもよい）。`brd_host_if` は同時に 1 つしか要求を出さない |
| RUN 制御 | `run_start`（1 クロックのパルス）、`run_pc[15:0]`、`run_count[31:0]`、`core_rst` | `core_rst` はリセット時と `RESET` コマンドで 16 クロック出る |
| ステータス | `core_busy`、`core_reason[7:0]`、`core_info[31:0]`、`core_pc[15:0]`、`core_steps[31:0]` | `core_busy` は `run_start` の次のクロックから終了まで 1。それ以外の値は `core_busy = 0` のとき有効 |

書き込みと読み出しのポートは同時には動かない（どちらか一方）。契約 §6 のメモリバスにつなぐときは、
`req_valid = mw_valid | mr_valid`、`req_we = mw_valid` とし、空間とアドレスの範囲で `*_err` を作ればよい
（例: `mncore/fpga/board_test/brd_board_test.v`）。

コアのクロックが `brd_host_if` と違う場合のクロック乗せ換えは、まだ用意していない（今は単一クロック）。

## 6. ホストツールでの `.asm` の実行

`mnhost.py run X.asm` は `assemble3 --instruction-mode flat --disable-packer` の出力を次のように実行する。

1. `RESET` し、`j` / `m` 行を出現順に命令メモリへ積む（入りきらなければ窓に分けて積み直す）。
2. `d` 行の位置で `RUN` を分割する。`d set` はその時点で `WR_MEM`、`d get` は `RD_MEM` にする。
   - 位置の指定がない階層（例: `$lm0` に `n…p` がない）は、`INFO` の実装トポロジの全範囲に広げる。実装していない位置は飛ばす。
   - 単語アクセス（`$m` など）は、長語のバイトマスク（上位 `0xF0` / 下位 `0x0F`）付きで書く。
   - 実装していない空間（`INFO` の深さが 0）の `d set` / `d get` は飛ばす。深さを超える部分は切り捨てる（`d set` で捨てた長語の数は警告で出す）。OMR（空間 0x10、16 エントリ）は PE の空間がある設計にあるものとする（WP21）。
   - `r` 行（DRAM の初期データ）は、DRAM のない設計では読み飛ばす（WP21）。
   - `RUN` が誤りで止まったら、そこで終える。E_RANGE の info は窓の中のエントリ番号なので、窓の先頭を足して語番号にする。
3. `d get` の結果を ndmp（契約 §4）で出す: `空間 位置 0x長語アドレス 値`。位置は `d get` の表記（PE 系は `n0c0b0m0p0`、L1BM は `n0c0b0`、L2BM は `n0c0`、PDM / DRAM は `n0`）。
   単位は公式エミュレータのダンプの正規化（WP02 の `norm_gpfn3.py`）と同じにする（WP21 で変更）: 単語アクセスは `LM0W` などに単語アドレスと 32bit の値で、T は `2 × サイクル + k`、`$omr` はエントリ × 4 + サイクルにフラグの 4bit で出す。同じ場所は後の `d get` が勝つ。

## 7. BL616（USB-UART ブリッジ）の制約（2026-11-24 に実測）

FPGA 側の誤り計数が 0 のままでも、ブリッジ側でデータが落ちることがある。ホストはこの節の規則を守る。

| 項目 | 実測 |
| --- | --- |
| 使えるボーレート | 1M、2M、3M。4M、5M、6M は `SET_BAUD` 後の確認に失敗する（ブリッジ側で設定できない） |
| ブリッジの実際の速度 | 1M は誤差 0、2M は +0.2 %、**3M は 3.076 Mbaud（+2.5 %）**。40 MHz を整数で割っているとみられる |
| 応答の遅延 | 小さな応答で 1〜11 ms（中央値 5 ms 前後）。空の `PING` の往復で 5〜12 ms |
| FPGA → PC の持続速度 | 約 70 KiB/s が上限（パイプライン時）で、ボーレートを上げても増えない |
| FPGA → PC のあふれ | 連続して送ると、1M で約 28 KB、2M で約 12 KB、3M で約 10 KB の後にバイトが落ちる（応答の CRC 不一致になる） |
| PC → FPGA | 落ちない（USB の流量制御が効く）。パイプライン時に 3M で 165 KiB/s 前後 |
| ブリッジの端末 | PC から **Ctrl-X（0x18）、Ctrl-C（0x03）を 1 バイトずつ別の write で**送ると、BL616 は UART の中継をやめて自分のシェル（`TangNano20K />`）に入る。`uart_info` で BL616 側の実際の速度が見える。フレームの中に 0x18 0x03 があっても入らない（実測）。フレームは必ず 0xA5 から始めて 1 回の write で送ること |
| ブリッジの停止 | **シェルに入ったあとは、`choose uart` を送っても FPGA → PC の中継が戻らない**（実測。PC → BL616 のシェルは応答し、FPGA を書き直しても直らない）。BL616 のシェルで `reboot` すると直る（USB の抜き差しと同等。FPGA の Flash には触れない）。`mnhost.py bridge reboot` がこれを行う |

ホストの規則（`mnhost.py` の `_pipeline` が実装している）:

- 応答を待たずに次の要求を送るのは、次のどちらかが成り立つときだけにする。
  - (A) 未応答の要求の合計バイト数が FPGA の受信 FIFO（`INFO` の rxfifo）以下
  - (B) 未応答の応答の合計バイト数が FPGA の送信 FIFO（txfifo）以下
- どちらの場合も、**未受信の応答の合計を 6 KB 程度以下に保つ**（ブリッジのあふれを防ぐ）。既定は 6300 バイト。
- 3M を使うときは、`STATUS.meas` でブリッジの実際の速度を測り、FPGA の分周を合わせる（`mnhost.py` の `set_baud` は既定でこれを行う）。

## 追記（lead、WP05 の報告から）

- PC が読んでいないのに FPGA が送り続けると、BL616 の FPGA→PC 中継が止まり、`bridge reboot` まで戻らない。FPGA は要求への応答以外を一方的に送り続けない。
- `bridge reboot` は FPGA を Flash の内容で読み直す。SRAM に書いたデザインは書き直すこと。

- 設計固有の空間 ID: 0x10 OMR、0x11 BAR（`` / ``）（WP14）。

- デザイン ID 0x03: `mn_top_mab`（1 MAB、4 PE の時分割）。INFO のフラグは bit 3..2 = FPALU、bit 4 = MAU、bit 5 = BFN（WP30）。

- INFO のフラグの bit 6 = MAT（行列。WP36）。停止理由 4 = WAIT（info = タグ。WP33）。
