# FPU の仕様

この文書は `mncore/rtl/fpu/` の RTL が実装する浮動小数点演算の定義をまとめる。
WP12（FMA と MAU のベクトル演算）と WP13（FP 系 ALU 命令）が自分の節だけを書く。

**正解は公式エミュレータ `gpfn3_package_main`**（契約 §1）。
Rust Sim（`third_party/mncore/viz/core/src/float.rs`）と食い違う所は、この文書に公式の挙動と根拠を書く。

## WP12: FMA と MAU のベクトル演算

対象: `mn_fp_fma`（1 要素の FMA）、`mn_fp_mul53`（仮数の積）、`mn_fp_f2h`（単精度 → 半精度の丸め）、`mn_mau_vec`（ベクトル命令 1 スロット分）。
行列 MAU（mfma/mmul）とブロックフロートは対象外（WP30）。

### 1. 形式（SDM 1.3、4.1）

| 形式 | 符号 | 指数 | 仮数 | バイアス | 1.0 |
| --- | --- | --- | --- | --- | --- |
| 半精度 h | 1 | 6 | 9 | 31 | `0x3e00` |
| 単精度 s | 1 | 8 | 23 | 127 | `0x3f800000` |
| 倍精度 d | 1 | 11 | 52 | 1023 | `0x3ff0000000000000` |

- 非正規化数と NaN はない。**指数部が 0 ならゼロ、全 1 なら無限大**で、仮数部は見ない（入力の仮数が 0 でなくても同じ）。
- 出力の正規化（SDM 4.1）: ゼロと無限大の仮数は 0、ゼロの符号は +。
- 以下、有限値を `(-1)^s × 1.m × 2^U` と書き、`U` を不偏指数と呼ぶ。

### 2. 基本関数 `z = round(a × b + c)`（`mn_fp_fma`）

| prec | a, b | c | z（rnd = 0） | z（rnd = 1、出力の精度縮減） |
| --- | --- | --- | --- | --- |
| `00` d | 倍精度 | 倍精度 | 倍精度 | 単精度 |
| `01` f | 単精度 | 単精度 | 単精度 | 半精度 |
| `10` h | 半精度 | 単精度 | 単精度 | 半精度 |
| `11` g | f と同じ（ベクトル命令の gv* はアセンブラが受理しない） | | | |

vfma は c、vmul は c = +0、vadd は b = 1.0、vpassa は b = 1.0 と c = +0 を与えた同じ演算である（SDM 3.6.9.1）。

#### 2.1 積

- a か b がゼロなら積はゼロ（∞ × 0 もゼロ）。そうでなく a か b が ∞ なら積は ∞。符号は `sa ^ sb`。
- 有限値どうしの積は、仮数（hidden bit 込み）の整数積 `Sa × Sb`、指数 `Ep = Ua + Ub`。
- 部分積の省略（SDM 4.3、式 4.6〜4.9）:
  - 倍精度: 仮数の下位 16 ビットどうしの積 `(Sa mod 2^16) × (Sb mod 2^16)` を引き、それが 0 でなければ `2^30` を足す（積の LSB を単位として）。
  - 単精度: 下位 5 ビットどうし、補正は `2^8`。
  - 半精度: 省略しない（正確な積）。
- 精度拡張（`e`）した a・b は、**拡張後の形式で**掛ける（拡張後の仮数の下位ビットは 0 なので、省略は効かない）。Rust Sim は拡張前の短い仮数に省略をかけるので公式と食い違う（WP03 の `ext_mul`）。RTL は公式どおり。

#### 2.2 加数 c の位置合わせ（積と c がともに有限のとき）

`Ep = Ua + Ub`（積の指数。実際の積の最上位ビットは `Ep` か `Ep + 1`）、`d = Uc - Ep` とする。

1. **積を捨てる**: `d >= T` なら積をゼロとして扱う（結果は c を出力形式に丸めた値）。T は d で 55、f と h で 26。
2. **c を格子に揃える**: そうでなければ、c を格子 `2^(Ep - K)` に揃える。K は d で 88、f で 41、h で 28。
   - 格子より下の c のビットは切り捨て、切り捨てたビットに 1 があれば格子のビット（`2^(Ep - K)`）に 1 を立てる（sticky のジャム）。
   - c の最上位ビットが格子より 2 桁以上下（`Uc <= Ep - K - 2`、すなわち `d <= -(K + 2)`）なら c をゼロとして扱う。
3. 積と c の和を正確に求める（積の値は格子の倍数なので、和は格子の上で正確）。

| | d | f | h |
| --- | --- | --- | --- |
| 積を捨てる `d >=` | 55 | 26 | 26 |
| 格子 `Ep - K` の K | 88 | 41 | 28 |
| c を捨てる `d <=` | -90 | -43 | -30 |

- d と f の格子は Rust Sim（`align_c`、`docs/dataflow-viz/NUMERICS.md`）と同じ。
- **h の格子と、積を捨てる規則は Rust Sim にない。** 公式エミュレータで調べて確定した（§4）。
  - 出力丸めのない形では、ほとんどの場合結果に表れない（積や c は出力の精度に収まっているので、捨てた量は丸めの境界をまたがない）。
  - 例外: c がちょうど 2 の冪で、積の符号が逆、仮数積が 2 を超え、`d = T` のとき、正確な和は c より 1 ulp 小さい値に丸まるが、公式は c を返す（例: `dvfmau` で a = `a6459c860b63a7b1`、b = `561fffffffffffff`、c = `3fd0000000000000` → 公式 `3fd0000000000000`、正確な丸め `3fcfffffffffffff`。`fvfma`、`hvfma` でも、`d = T` で積を捨てるかどうかで結果が変わる行を探査で確認した）。
  - 出力丸め（`r`）のある形では、縮減後の精度でちょうど同点になる値で見える。WP03 が `round_twice` と呼んだ食い違いはこれである（「もとの出力精度の 2 ビット下までを残す」という WP03 の説明は、確かめた範囲の観察で、規則としては上の表が正しい。§4）。

#### 2.3 和と丸め

- ∞ + ∞ は、両方が -∞ のときだけ -∞、ほかは +∞。∞ + 有限 = その ∞。ゼロ + ゼロ = +0（出力は常に +0）。
- 和がちょうど 0 なら +0。
- 出力形式の仮数長（d 53、s 24、h 10 ビット、hidden bit 込み）に**最近接偶数丸めで 1 回だけ**丸める。精度縮減（rnd = 1）でも、縮減後の形式へ直接 1 回丸める（SDM 4.3）。
- 丸めの後の指数が出力形式の範囲を超えたら符号付きの ∞、下回ったら +0（非正規化数にしない）。

### 3. MAU ベクトル命令（`mn_mau_vec`、SDM 3.6.9）

1 スロット = 1 PE の 1 サイクル分。入力は 2 長語（128 ビット）のバス 3 本、出力は 2 長語と 4 ビットのマスクフラグ。

| 欄（デコード済み） | 意味 |
| --- | --- |
| `dmode` | `pe_mauc_dmode`。レーン数は d 1、f 2、h 4 |
| `round_out` | 出力の精度縮減（命令名の `r`） |
| `passa` | b = 1.0（vadd、vpassa） |
| `zeroc` | c = +0（vmul、vpassa） |
| `mdw_side` | dvfma/dvmul の `d`（1）/`u`（0）。`dmode = d` かつ `passa = 0` のとき、`u` なら PE 0・1、`d` なら PE 2・3 だけが掛け、残りの PE は積をゼロとして c だけを丸める |
| `signa`〜`signc` | 入力の符号反転（`-`） |
| `exta`〜`extc` | d・f: 1 段低い精度からの拡張（`e`）。h の a・b: 単精度からの丸め（`r`、`mn_fp_f2h`）。h の c: 半精度からの拡張（`e`） |
| `pe_sub` | MAB 内の PE の位置（bit 1 だけを使う） |

- 要素はバスの MSB 側から詰める。読む幅: d は 64（e なら 32）、f は 32（e なら 16）、h の a・b は 16（r なら 32）、h の c は 32（e なら 16）。
- 処理の順: 要素の取り出し → 拡張・丸め → 符号反転 → passa / zeroc / u・d の置き換え → FMA。
- h の `r` は `mn_fp_f2h`（公式の `r_round` の式: 符号 | clamp(E - 96 + 繰り上がり, 0, 63) | 仮数 23 → 9 ビットの最近接偶数丸め）。値としては通常の丸め（下にあふれたらゼロ、上にあふれたら ∞）と同じ。
- 結果は MSB 側から詰め、残りは 0。要素の幅は d 64（r なら 32）、f 32（r なら 16）、h 32（r なら 16）。
- マスクフラグは結果の符号ビットの反転（SDM 3.6.9.26）。ビット 3 が MSB 側:

| 形 | flags[3:0] |
| --- | --- |
| d | `{p0, p0, p0, p0}` |
| d r | `{p0, p0, 0, 0}` |
| f | `{p0, p0, p1, p1}` |
| f r | `{p0, p1, 0, 0}`（公式。Rust Sim は `{p0, p0, p1, p1}`。WP03 の `fvr_flags`） |
| h、h r | `{p0, p1, p2, p3}` |

（`pi` は要素 i が負でない＝符号ビットが 0）

### 4. 根拠（公式エミュレータとの照合）

- WP03 のベクタ（seed 1、`--official-expect` 済み）: fp 25 ファイル 62,340 行、mau 28 ファイル 52,480 行。参照モデル `mncore/sim/tb/fpu_tools/mnfp_ref.py`（この節の規則を Python で書いたもの）と RTL の両方が全行一致。
- 境界の探査（`mncore/sim/tb/fpu_tools/probe_align.py`）: fma の 6 形（d、dr、f、fr、h、hr）で、積を捨てる境界（d = T-3〜T+2）、c の格子の境界（c の最上位が格子の前後、積が出力の同点にちょうど乗る場合を含む）、打ち消し、ランダムの計 39,669 行を公式で実行し、参照モデルと全行一致した。
  - T と K をそれぞれ ±1、±2 ずらしたモデルは、どれも数十行以上で公式と食い違う（表に記録）。
  - 積を捨てる判定も c の格子も、実際の積の最上位（`Ep` か `Ep + 1`）ではなく `Ep` で決まる。仮数積が 2 以上の行で区別した（最上位を基準にしたモデルは、T・K を 1 ずらしたものを含めて 91〜244 行で食い違う）。

| 変えたもの | 公式と食い違う行（探査 39,669 行中） |
| --- | --- |
| K(d) = 86 / 87 / 89 / 90 | 229 / 119 / 114 / 226 |
| T(d) = 53 / 54 / 56 / 57 | 186 / 84 / 51 / 86 |
| K(f) = 39 / 40 / 42 / 43 | 256 / 134 / 120 / 249 |
| T(f) = 24 / 25 / 27 / 28 | 237 / 101 / 49 / 87 |
| K(h) = 26 / 27 / 29 / 30 | 87 / 38 / 56 / 98 |
| T(h) = 24 / 25 / 27 / 28 | 225 / 96 / 61 / 94 |

- そのうち規則の境界を分ける 1,904 行は `mncore/sim/tb/fpu_fp/probe/` に置いた（期待値は公式の出力）。

### 5. RTL の構成

#### `mn_fp_mul53`（積、レイテンシ 5）

- 仮数を hidden bit 抜きで 52 ビットに MSB 揃えする（d: そのまま、f: `{m23, 29'b0}`、h: `{m9, 43'b0}`）。
- `a = A2:A1:A0`（16、18、18 ビット、b も同じ）に分け、`(2^52 + a)(2^52 + b) - A0·B0 = 2^104 + 2^52(a + b) + （A0·B0 以外のタイル 8 個）`。
  - d では A0·B0 がちょうど省略する部分積、f では A1·B1 がちょうど省略する部分積（MSB 揃えのため。f の A1·B1 は入力を 0 にして使わない）、h では A2·B2 以外のタイルが 0。
  - したがって **DSP は 8 個**（`mn_mul_pipe` 18×18 / 16×18、前後にレジスタ）。省略の補正 `2^30`（d）、`2^66`（f、MSB 揃えの単位）は別に足す。
- 積は 2^16 の倍数になるので、ビット [105:16] の 90 ビットだけを出す。タイル（2 クロック）＋加算木 3 段。

#### `mn_fp_fma`（1 要素、毎クロック 1 個、レイテンシ 14）

入力を取り込んだクロックエッジ（c0）から 14 エッジ後（c14）に結果が出る。

| レジスタ段 | 内容（その段のレジスタに入る値） |
| --- | --- |
| c0 | 入力 |
| c1 | 分解（符号、指数欄、仮数、ゼロ・∞ の判定）。積のタイルの入力もここから |
| c2 | `Ep = Ua + Ub`、`Uc`、`d = Uc - Ep`（指数欄から直接）、c の仮数の 8 ビットごとの末尾の 0 の数 |
| c3 | 積と c を捨てるかの判定、c の右シフト量 `54 - d`、格子より下に落ちる仮数ビットの境界 `nj = g - 36 - d`、c の仮数の末尾の 0 の数 `tz`、結果の指数の基準値 |
| c4 | c の右シフト（16 単位）。ジャムの有無 `tz < nj` |
| c5 | c の右シフト（1 単位） |
| c6 | 格子より下を消してジャムのビットを立てた c（減算なら反転済み）、積（`mn_fp_mul53` の出力） |
| c7 | 145 ビットの加減算（下位 90 ビットの加算と、上位 55 ビットの +0 / +1 を選ぶ桁上げ選択）と、結果が負か |
| c8 | 絶対値（72 ビットずつ） |
| c9 | 16 ビットごとの先頭の 0 の数 |
| c10 | 正規化（16 単位）の上位 80 ビットと、その下の sticky |
| c11 | 正規化（1 単位）の上位 56 ビットと sticky、先頭の 0 の数 |
| c12 | 最近接偶数丸め（仮数の加算）、指数 |
| c13 | 丸めの繰り上がりを足した指数、あふれ・下にあふれ・∞ の判定 |
| c14 | 出力形式に詰めた結果（出力のレジスタ） |

- 窓は 144 ビット。窓のビット i の重みは `2^(i + Ep - 88)`。積の最上位は 88 か 89、c の最上位は `88 + d`（-1〜142）、格子は窓のビット 0（d）、47（f）、60（h）。
- 積を使わない場合（ゼロ、捨てた）は c を `d = 0` の位置に置き、`Ep` の代わりに `Uc` を使う。

#### `mn_mau_vec`

- スロットを受けるレジスタ 1 組と、レーン番号のカウンタ。レーンを 1 クロックに 1 個 `mn_fp_fma` に流す。
  その前に 2 段: w1 で要素を取り出し、w2 で拡張・丸め（`mn_fp_f2h`）・符号反転・passa・zeroc・u/d を当てる。
- 最後のレーンを出すクロックで次のスロットを受けられる（`in_ready`）。結果はタグ（レーン、最後か、dmode、round）で集め、16 ビットずつその場に書き、最後のレーンで `out_valid` を 1 クロック出す。
- スロットを受けたエッジから結果まで: d 18、f 19、h 21 エッジ。スループットは 1 レーン / クロック。

## WP13: FP 系の ALU 命令（`mn_fp_alu*`）

正解は公式エミュレータ（契約 §1）。下の規則は、公式エミュレータで照合済みのベクタ（WP03 の unit `fpalu`、`--official-expect` 後の全 151,856 行）とすべて一致する。
Rust Sim（`viz/core/src/machine.rs` の `alu_lanes`、`float_*`、`float::block_float`）とは、入力の精度縮減（`r`）だけが違う。

### モジュール

| モジュール | 内容 |
| --- | --- |
| `mn_fp_alu` | PE 1 個分。rsqrt、relu0〜3、lrelud / lreluo / ilrelud、max / min（浮動小数点）、floor、ftoi（符号あり・なし）。passa と packbit も実行できる（振り分けでは `mn_alu_int` に行く）。入力の `r`（rounda / roundb） |
| `mn_fp_alu_lane` | `mn_fp_alu` の要素ごとの部分（形式 W / EB / M をパラメータで持つ。倍精度 1、単精度 2、半精度 4 個を並べる） |
| `mn_fp_alu_bfn` | MAB 1 個分のブロックフロート化（dbfn、fbfn、gbfn、hbfn/n、hbfe/n） |
| `mn_fp_alu_bflane` | `mn_fp_alu_bfn` の要素ごとの前処理 |
| `mn_alu_rnd`（WP11、`rtl/alu`） | `r` の単精度→半精度の丸め。整数 ALU と共有する |
| `mn_alu_cls`（WP11、`rtl/alu`） | 振り分け。`cls_fp` がこの 2 モジュールの担当で、`mn_fp_alu` の `cls_bf` がどちらかを決める |

### 形式とバス

- 倍精度 1/11/52（バイアス 1023）、単精度 1/8/23（127）、半精度 1/6/9（31）。指数 0 はゼロ、全 1 は無限大（仮数は問わない）。非正規化数と NaN はない（SDM 1.3）。
- ALU の入出力は 2 長語（128bit、bit 127 が 1 語目の MSB）。要素は MSB 側から詰まる。
- 要素ごとの命令は **MSB 側の長語の要素だけ**を計算する（倍精度 1、単精度 2、半精度 4 個）。結果の LSB 側の長語は x の LSB 側の長語（`r` を付けたときは 0）。
- マスクフラグは 4bit で、bit 3 が MSB 側の要素。倍精度の要素は 4 ビット、単精度は 2 ビットを同じ値にする。
- dmode 11（疑似単精度）は bfn でだけ意味を持つ。要素ごとの命令では単精度として扱う。

### 入力の精度縮減（`r`、rounda / roundb、SDM 3.6.12.19）

公式エミュレータの式（WP03 の `r_round`）。Sim の通常の丸めとは違う。

```
入力の単精度 4 語 w0..w3（バスの bit 127:96 から順）→ 半精度 4 個を MSB 側の長語へ。LSB 側の長語は 0。
E = 単精度の指数欄、m = 仮数 23bit
m9 = RNE(m >> 14)   （保持 9bit、丸めビット m[13]、スティッキー m[12:0]、偶数丸め）
c  = m9 の桁上がり（m9 = 0x200 のとき 1）
h  = 符号 | clamp(E - 96 + c, 0, 63) << 9 | (m9 & 0x1ff)
```

- 0 への切り捨てをしない。-0 は 0x8000、下にあふれた値は指数 0 のまま丸めた仮数が残る。∞ と上にあふれた値は指数 63 で仮数が残る。
- エミュレータは半語（dmode 10）以外の `r` を実行時エラーにする。`mn_alu_cls` がそれを `cls_bad`（E_UNSUPPORTED）にするので、このユニットには来ない（来れば dmode を見ずに丸める）。
- 実装は WP11 の `mn_alu_rnd`（整数 ALU と同じモジュール）。

### 要素ごとの命令（x の要素 a、y の要素 b、幅 W）

| 命令（aluop） | 結果 | フラグの条件 |
| --- | --- | --- |
| passa（01010） | a（バス全体が x） | a == 0（ビット列として。-0 は 0 ではない） |
| packbit（10011） | (a << 1) \| b の MSB | b の MSB == 0 |
| relu0〜3（10100〜10111、k = aluop[1:0]） | a の bit (W-1-k) が 0 なら b、1 なら -0（符号ビットだけ） | その bit == 0 |
| lrelud / lreluo / ilrelud（11000〜11010） | a ≥ 0（符号 0）なら b。負なら b の指数を -1 / -3 / +1 する。b が ∞ ならそのまま。下にあふれる（指数 ≤ 1 / ≤ 3）と -0（b の符号によらない）。ilrelud は指数 emax-1 から ∞（仮数は残る）、ゼロから最小の正規化数（仮数は残る）になる | a の符号 == 0 |
| max / min（11011 / 11100） | 下の比較で a を選べば a、そうでなければ b | a を選んだか |
| floor（11110、iselb 110） | 下の規則 | 常に 0 |
| ftoi（11110、iselb 111、is_unsigned） | 下の規則 | 常に 0 |
| rsqrt（10000） | 下の近似 | a の符号 == 0 |

**max / min**: 符号と大きさの鍵 key(v) = (符号 ? -1 : 1) × (指数と仮数の欄をつないだ整数)、ただし指数が 0 なら key = 0。max は key(a) ≥ key(b)、min は key(a) ≤ key(b) のとき a。
等しいとき（±0 どうし、指数 0 どうしを含む）は a。∞ どうしは仮数の大小で比べる。

**floor**（E = 指数欄 − バイアス）:
- 指数 0、指数全 1、E ≥ M（整数）: a のまま。
- E < 0（0 < |a| < 1）: 正なら +0（0）、負なら -1.0。
- 0 ≤ E < M: 小数部の下位 M−E ビットを 0 にする。負で小数部が 0 でなければ、さらに 2^(M−E) を指数・仮数の欄に足す（繰り上がりで指数が 1 増えることがある）。

**ftoi**（0 方向への切り捨て。整数の幅は要素の幅 W）:
- 大きさ mag = (1.仮数) × 2^E の整数部。E < 0（ゼロを含む）なら 0。
- 符号あり: E ≥ W−1（∞ を含む）なら飽和（正 0x7f..f、負 0x80..0）。そうでなければ負は −mag。
- 符号なし: **符号を無視する**。E ≥ W（∞ を含む）なら全 1、そうでなければ mag（負の数も大きさを返す）。

**rsqrt**（近似逆数平方根。SDM 3.6.12.9 は「約 5bit」とだけ書く。規則は公式エミュレータから抽出したもので Sim の `float_rsqrt` と同じ。照合で全行一致）:

```
e     = a の指数欄（符号は無視。ゼロと ∞ も特別扱いしない）
t     = a の仮数の上位 4bit
out_e = BIAS + (BIAS + 1) / 2 − 1 − ceil(e / 2)      （倍精度 1534、単精度 190、半精度 46 から引く）
out_m = MANT5[e & 1][t]  を仮数の上位 5bit に置き、残りは 0
結果  = 0 | out_e | out_m          （符号 0）

MANT5[0]（e が偶数）= 13 11 10  9  8  7  6  5  4  4  3  2  2  1  1  0
MANT5[1]（e が奇数）= 31 30 28 26 25 23 22 21 20 19 18 17 16 15 14 13
```

### ブロックフロート化（bfn / bfe、SDM 3.6.12.12、4.4）

MAB の 4 PE の同じサイクルの入力から、次のブロックを作る（公式エミュレータと Sim の `compute_bfn` で同じ）。

| 命令 | dmode | ブロック | 残す仮数（keep） |
| --- | --- | --- | --- |
| dbfn | 00 | 各 PE の MSB 側の長語（倍精度 4 個） | 52 |
| fbfn | 01 | 各 PE の MSB 側の長語の 1 語目（4 個）と 2 語目（4 個）の 2 ブロック | 23 |
| gbfn | 11 | 各 PE の MSB 側の長語の 2 語（8 個） | 18 |
| hbfn/n、hbfe/n | 10 | 各 PE の MSB 側の長語の半語（16 個）と LSB 側の長語の半語（16 個）の 2 ブロック。iselb = 9 − n | n |

dbfn / fbfn / gbfn の結果の LSB 側の長語は 0。フラグは常に 0。aluop は bfn が 11110、bfe（拡張表現、半精度だけ）が 11101。

ブロックごとに（dr = M − keep、半精度は 9 − n、疑似単精度は 5）:

```
max_e  = ブロックの指数欄の最大
common = max_e + (指数が max_e の要素に「仮数の上位 keep bit が全 1」のものがあれば 1) + (半精度なら dr)
要素ごと（s = 符号、e = 指数欄）:
  common ≥ emax              → s | ∞（仮数 0）
  max_e == 0                 → s
  e == 0                     → bfe ? s : s | common
  d     = common − e
  flag  = bfe && (d > 6 + dr || (d == 6 + dr && 上位 keep bit が全 1 でない))
  shift = (flag ? d − 6 : d) + 1 + (半精度でなければ dr)
  r     = RNE((1.仮数) >> shift)     （疑似単精度は r << 5 を仮数とする）
  r == 0                     → bfe ? s : s | common
  それ以外                   → s | (flag ? 0 : common) | r
```

`r`（rounda、半精度だけ）は、各 PE のバスを上の式で丸めてから変換する（LSB 側の長語は 0 になるので、2 つ目のブロックは全部ゼロ）。

### インタフェースとレイテンシ

- `mn_fp_alu`: `mn_alu_int`（WP11）と同じ形。ALUC の欄 `pe_aluc_dmode`、`_aluop`、`_is_unsigned`、`_rounda`、`_roundb`、`_isela` に `pe_aluc_iselb` を加え（floor / ftoi / bfn の区別に使う）、`imm32` はない。`x`、`y`（128bit、丸める前の値）→ `z`（128bit）、`flags`（4bit）、`out_err`（このユニットが実行しない ALUC。z = 0、flags = 0）。`cls_bf`（組み合わせ回路、in_valid と無関係）は ALUC が bfn / bfe（`mn_fp_alu_bfn` へ送る）かどうか: aluop 11101、または 11110 で iselb が 11x でないもの。valid / ready、毎クロック 1 本。サイクル t に受け付けた要求の結果はサイクル t + 5 に出る。出力が受け取られないと全段が止まる。パラメータ `RND = 0` で入力の丸めとその段を外せる（呼び出し側で丸める場合。レイテンシは 4）。
- `mn_fp_alu_bfn`: ALUC は `pe_aluc_dmode`、`_aluop`、`_rounda`、`_iselb`。`x[128*p +: 128]` が PE p の入力、`z[128*p +: 128]` が結果、`flags[4*p +: 4]` は 0、`out_err` は bfn / bfe でない ALUC を受け付けたとき 1。valid / ready で 1 件ずつ。サイクル t に受け付けた要求の結果はサイクル t + 15 に出る（`r` 付きは t + 19）。
- 振り分け: `mn_alu_cls` の `cls_fp` のうち、`cls_bf` = 1 なら `mn_fp_alu_bfn`、0 なら `mn_fp_alu`。zero（aluop 11101、is_unsigned = 1、isela = 0101）は `mn_alu_cls` が `cls_int` にする。
