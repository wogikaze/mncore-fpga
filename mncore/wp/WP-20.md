# WP20 PE コアの統合（1 PE モード）

- 依存: WP10、WP11、WP14、WP02。WP12/13 は未完了ならスタブで進める。
- 担当: `mncore/rtl/pe/mn_pe_core.v`、`mncore/rtl/core/`、`mncore/sim/tb/core/`、`mncore/sim/regress/`
- 参照: SDM 3.6.3（ハザード）、3.6.4〜3.6.6（nop、wait、noforward）、`viz/core/src/hazard.rs`、`proofs_lean/evidence/lbf-encoded/`

## 作業

1. `mn_core` を作る。
   - 命令メモリからの取り出し、`j` 語と `m` 語の振り分け
   - `nop/n`、`wait`（MV が未実装の段階では、待つ対象がなければ即座に通過する）
   - 停止条件とステータス
2. PE パイプライン: デコード → オペランドの読み出し（4 サイクル）→ ALU / MAU / FP → 書き込み。
3. フォワーディング用のレジスタ（`aluf`/`mauf`/`mreadf`/`lbf`）と noforward。
   参照のタイミングは `hazard.rs` と Lean の evidence の 11 ケースに合わせる。
4. 固定値オペランド（`$peid`、`$subpeid`、`$l1bid`、`$l2bid`、`$mabid`、`$msb1`）。
5. 回帰ランナー `sim/regress/run.py`。
   - `corpus.tsv` の「1 PE で比較できる」もの全件について、Verilator（遅ければ iverilog）で実行する。
   - ndmp で公式の結果（p0 だけ）と比較し、合格率を表にする。

## 受入基準

- 整数だけの「1 PE で比較できる」ものが全件一致する。FP が入った後は FP の分も一致する。
- 合格しなかったものは理由ごとに分類して報告する。
