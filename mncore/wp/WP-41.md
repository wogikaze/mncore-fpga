# WP41 デモ

- 依存: M2、WP34、WP38
- 担当: `mncore/demo/`（新規）だけ。RTL と既存のツールは変えない。必要な機能は `demo/` の中で、既存のツールを import して作る。
- 参照:
  - `mncore/tools/host/mnrun.py`、`mnhost.py`
  - `mncore/fpga/top_m2/`、`fpga/multi/`、`fpga/top_vpe/`
  - `mncore/status/WP-37.md`、`WP-38.md`、`WP-34.md`（各 WP41 への申し送り）

## 作業

1. `demo/hello.py`: 公式の hello_world を実機で実行し、DRAM から "Hello, world!" を読み出して端末に表示する。
   - ビットストリームの用意、書き込み、`mnrun.py --rule replica` を 1 本にまとめる。
   - 公式エミュレータの結果との一致も表示する。
2. `demo/fizzbuzz.py`: FizzBuzz を実機で実行し、DRAM の出力を文字列として端末に表示する。
   - まず実機で最後まで動く `problems/challenge/23.fizzbuzz-pe` を使う。
   - 64 PE（`fpga/top_vpe`）で動く FizzBuzz 系の本があれば、それも使う。
   - 解答（`20.fizzbuzz/answer.vsm`）は WP39 の後に扱うので、今は扱わない。
3. `demo/README.md`: 手順、所要時間、必要なもの（ボード、OSS CAD Suite、WSL の公式ツールは正解の表示にだけ使う）、出力の例。
   - 公式ツールがなくても FPGA で実行して表示できる経路を用意する。正解との比較は省略してよい。
4. 実機での実行のログを `demo/logs/` に置く。

## 受入基準

- `hello.py` と `fizzbuzz.py` が、実機でそれぞれ 1 コマンドで動き、出力が正解と一致する。
- 手順書どおりに、きれいな環境から実行できる。ビルド済みのビットストリームがなければ作る手順も含める。
- ボードロックを守り、SRAM にだけ書き、最後は LED の方針に従ったデザインを書いた状態で残す。
