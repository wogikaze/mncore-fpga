# WP01 ISA スキーマと Python デコーダ

- 依存: WP00
- 担当: `mncore/spec/isa/`、`mncore/tools/mnisa/`、`mncore/sim/tb/mnisa/`（必要なら）
- 参照:
  - Scrapbox [mncore/機械語](https://scrapbox.io/mncore/機械語)。API で全文を取れる: `https://scrapbox.io/api/pages/mncore/%E6%A9%9F%E6%A2%B0%E8%AA%9E/text`
  - `mncore/04-encoding-probe.md`
  - SDM 3.5〜3.7（`third_party/mncore/docs/mncore_llm`）

## 目的

flat の `j`（426bit）と `m`（82bit）について、全フィールドの位置、幅、意味を機械可読なスキーマにする。
あわせて Python の decode / encode を作る。後続の RTL デコーダ（WP10）と全テスト基盤の土台になる。

## 作業

1. `assemble3 --instruction-mode flat --disable-packer --print-csv` のヘッダとデータ行から、フィールドの並び、幅、開始位置を自動で求める。
   - ヘッダの列数は 95、j 行は 110 列で、合計 426bit になる。差の 15 列は cycle1〜3 のアドレス欄と思われるので、名前を付けて確定させる。
   - MV 行（82bit）も同様に処理する。
2. `spec/isa/j_flat.yaml` と `spec/isa/m.yaml` を作る。各フィールドに次の項目を持たせる。
   - `name`、`pos`、`width`
   - `group`（mrc / trc / rfc0 / … / l1bm / l2bm / wd / addr_c1..3）
   - `desc`（Scrapbox と SDM の節番号）
   - `enum`（判明している値の表。例: aluop、isel、mmode、tmode）
   - `notes`（即値がほかの欄を再利用すること、など）
   - **即値の 32bit の散らばり方**（Scrapbox「即値ペイロードの配置」の j 列）は、`imm_layout` として別に記述する。
3. `tools/mnisa/` に Python パッケージを作る。
   - `decode(bits) -> dict`、`encode(dict) -> bits`
   - `asm_io`: `.asm` の読み書き。`j`/`m`/`d` 行を扱う。
   - `csv_import`: assemble3 の CSV を取り込む。
   - CLI: `python -m mnisa.dump file.asm` で、語ごとに 0 でないフィールドを一覧表示する。
4. **往復検証**: `third_party/mncore` の全 `.vsm` を flat でアセンブルし、assemble3 の CSV の値と `decode()` の結果が全フィールドで一致することを確かめる。
   - 約 960 本ある。アセンブルに失敗するものは除外し、件数を記録する。
   - `encode(decode(w)) == w` も確かめる。
   - スクリプトは `tools/mnisa/verify_corpus.py`。
5. 「意味が未確定のフィールド」の一覧を `spec/isa/UNKNOWN.md` にまとめる。
   - コーパスで 0 以外の値が出るのに、意味が不明なもの。
   - 必要なら `tools/probe_bits.sh` を拡張して追加でプローブしてよい。

## 受入基準

- コーパスの全語で CSV と decode が一致する（不一致 0）。encode も往復一致する。
- yaml に全 426bit と 82bit が隙間も重なりもなく載っている。これを機械的に検査するテストがある。
- UNKNOWN.md に「未確定の欄」と、その欄が使われている命令の例が書いてある。
