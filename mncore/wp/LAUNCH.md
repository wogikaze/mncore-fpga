# subagent の起動と統合の手順（lead 用）

## 起動前に確認すること

- [ ] ユーザーが Wave の開始を了承している。
- [ ] 依存する WP が「完了」になっている（`mncore/status/BOARD.md`）。
- [ ] 該当する WP 指示書（`mncore/wp/WP-xx.md`）が最新になっている。

## 起動

1 Wave の WP は、**1 つのメッセージで複数の Agent 呼び出しとして同時に起動する**。

- `subagent_type: general-purpose`
- `isolation: "worktree"`（WP00 と WP42 以外は必須）
- 実機を使う WP（04、05、21、40、41）は、同じ Wave に 2 つ以上あってもかまわない。
  ボードロック（契約 §9）で直列になる。

プロンプトのテンプレート:

```
あなたは nano20k プロジェクトの WP-xx 担当です。
リポジトリ直下の CLAUDE.md、mncore/06-contracts.md、mncore/wp/WP-xx.md をこの順に読み、指示書に従って作業してください。
担当外のファイルは変更しないこと。最後に mncore/status/WP-xx.md に報告書を書き、変更をコミットしてください。
報告の要約（成果物、テスト結果、未解決の点、契約変更の要望）を最終メッセージとして返してください。
```

## 統合（Wave の終わりに lead が行う）

1. 各 worktree の報告書を読む。主張されているテストを、lead が少なくとも 1 本は自分で再実行する。
2. 依存順にブランチを main にマージする。衝突があるときは担当の外を触っていないか確認する。
3. 「契約変更の要望」をまとめて `06-contracts.md` に反映する。影響を受ける WP の指示書も直す。
4. `status/BOARD.md` を更新し、ユーザーに次の 3 点を短く報告する。
   - 完了した WP
   - 実際に確認したテスト結果
   - 次の Wave に進めてよいか
5. 不合格や部分的な完了のものは `WP-xxf`（修正用 WP）として起票する。

## 規模の目安

- 同時に動かす subagent は **最大 7 個**。セッションの既定ガイドラインでは workflow を 10 agent 未満に抑えることになっている。
- 指示書 1 つで終わらない大きさになった WP は、lead が `WP-xxa` / `WP-xxb` に分割する。
