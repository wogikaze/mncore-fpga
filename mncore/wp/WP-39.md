# WP39 演算器の共有化: 64 PE で全機能を 1 本に載せる（M3）

- 依存: WP34（仮想 PE）、WP38（自動切り替え）
- 担当:
  - `mncore/rtl/fpu/`、`mncore/rtl/alu/`、`mncore/rtl/pe/`、`mncore/rtl/mab/`、`mncore/rtl/vpe/`、`mncore/rtl/core/`
  - `mncore/rtl/l1bm/`、`rtl/l2bm/`、`rtl/mv/`、`rtl/board/`（面積を減らすための変更）
  - `mncore/fpga/top_m3/`（新規）、`mncore/sim/tb/` の該当 unit、`mncore/sim/regress/`
- 参照:
  - `mncore/status/WP-34.md`、`WP-38.md`（残る 27 本の内訳）、`WP-35.md`、`WP-12.md`、`WP-13.md`、`WP-36.md`
  - `mncore/rtl/fpu/SPEC.md`
  - 契約 §6（LUT4 75%、桁上げ鎖の数え方）

## 目的

回路を入れ替えずに、全プログラムを 1 本のビットストリームで実行する。

- WP38 の切り替えでも救えない 27 本は、1 つの語で MAU / FP ALU と L1BM / L2BM / MV を同時に使う。
- FizzBuzz の解答も同じ理由で、実機では最後まで動かない。

## 方針

時分割で実行しているので、速度は落としてよい。面積を最優先にする。

1. **FP の演算器を 1 本の共通データパスにまとめる。** 次の 3 つは、どれも「位置合わせのシフト → 加算 → 正規化 → 丸め」でできている。
   - ベクトル MAU（`mn_mau_vec` / `mn_fp_fma`）
   - FP ALU（`mn_fp_alu`）
   - ブロックフロート化（`mn_fp_alu_bfn`）
   - 共通の部品を逐次に使い回す形にする。行列 MAU（`mn_mab_mat`）も載せられるなら同じ考えで共有する。
2. 使う頻度が低い命令（rsqrt、floor / ftoi、bfn など）は、マイクロコードの逐次処理でよい。
3. 各部品のパラメータの既定値と、既存のビットストリームの構成は壊さない。共有版は新しいパラメータで選ぶ。
4. 目標の構成「M3」: 仮想 PE 64（N_MAB=16、LM 2048）+ L1BM（縮約あり）+ L2BM + MV + MAU + FP ALU（全命令）+ BFN。
   - 行列も入れば入れる。入らなければ、行列だけは WP38 の切り替えで補う。
   - 64 PE で載らなければ、まず 1 MAB（4 PE、LM 2048）の M3 を目指す。

## 受入基準

- M3 が LUT4 75% 以下で配置配線でき、27 MHz で動く。
- RTL の回帰で値の食い違いが 0 本。
  - `run.py --vpe 16` と `--vpe 1 --m2`、M2 の 247 本、行列、1 PE、4 PE。
  - 共有化した FP の unit テスト（fp、mau、fpalu の全ベクタ）も全件一致する。
- 実機で、M3 1 本で M2 の 247 本の回帰を回す。ユニットの不足による E_UNSUPPORTED が 0 本になる。行列を外した場合は、行列の語だけ残ってよい。
- FizzBuzz の解答（`problems/challenge/20.fizzbuzz/answer.vsm`）が、実機の 1 本のビットストリームで最後まで動き、正解と一致する。
- 速度（1 語あたりのクロック数）の低下を、部品ごとに報告する。
