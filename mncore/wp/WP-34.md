# WP34 仮想 PE（SDRAM に置く PE の状態）

- 依存: M2（WP37）
- 担当: `mncore/rtl/vpe/`（新規）、`mncore/rtl/core/`、`mncore/rtl/pe/`、`mncore/rtl/mab/`、`mncore/fpga/top_vpe/`（新規）、`mncore/sim/tb/vpe/`、`mncore/sim/regress/`（新しいモードの追加）
- 参照: `mncore/status/WP-37.md`（Wave 5 への申し送り）、`WP-30.md`、`WP-35.md`（`mn_pe_lsu` / `mn_pe_store` の NPE）、`WP-05.md`（SDRAM の帯域）、`WP-33.md`（SDRAM の配置。0xA0000 以降の 3 MiB が空き）

## 目的

1. **LM の深さを実チップと同じ 2048 長語にする。** E_RANGE になっている 26 本（FizzBuzz の解答を含む）を比べられるようにする。
2. **1 L1B の 16 MAB（64 PE）まで広げる。** L1BM の縮約をゼロ規則でなく実際の 16 MAB 分で行えるようにし、複製規則に頼る範囲を減らす。

## 作業

1. PE の状態（LM0/LM1/GRF0/GRF1、必要なら T / OMR / BAR も）を SDRAM に置く。
   - BSRAM は、いま実行している PE（または MAB）のキャッシュにする。
   - 置き場所は 0xA0000 以降の 3 MiB。64 PE × LM 2048 × 2 + GRF 256 × 2 = 約 2.3 MiB で収まる。
   - SDRAM のバスは MV と共有するので、`mn_core` の中で調停する。
2. 実行の順序: 1 命令語ごとに、PE（または MAB）を順に入れ替えて実行する。
   - 入れ替えのコストを測る。命令語の列をまとめて実行するなど、速くする工夫は任意。
   - 正しさを優先する。
3. パラメータ `N_MAB`（1 または 16）と `LM_AW`（8〜11）で構成を選べるようにする。既存の構成（M1 / M2 / 1 MAB）は退行させない。
4. 正解:
   - N_MAB=16 では L1BM の縮約が 16 MAB 分になる。縮小トポロジの Rust Sim（1 L2B・1 L1B・16 MAB）と比べる。
   - データが閉じる本は公式とも比べる。
   - `run.py` に新しいモードを足す。
5. 実機: `fpga/top_vpe/` に機能別のビットストリームを作り、回帰の一部と FizzBuzz の解答（`problems/challenge/20.fizzbuzz/answer.vsm`）を実機で動かす。
   - FizzBuzz が MAU を要るため載らない場合は、WP38 の自動切り替えと組み合わせる前提で、RTL シミュレーションでの一致までを示す。

## 受入基準

- LM 2048 で、E_RANGE だった 26 本が正解と一致する（RTL シミュレーション）。
- N_MAB=16（64 PE）で回帰が正解と一致する。合格率の表と速度（クロック数）を報告する。
- 既存の回帰（1 PE、4 PE、行列、M2）が退行しない。
- 実機で 64 PE 構成が動き、回帰の一部が一致する。資源と周波数を報告する。
