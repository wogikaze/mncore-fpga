# WP33 MV ユニット（PDM / DRAM を SDRAM に置く）

- 依存: WP32（L2BM。main にマージ済み）、WP05（SDRAM。main にマージ済み）
- 担当: `mncore/rtl/mv/`、`mncore/sim/tb/mv/`。実機での確認に使う `mncore/fpga/mv_test/`（新規）。
- 参照:
  - SDM の MV の章（25 モード、mvid / wait、priority、間接参照）
  - `j_flat.yaml` / `m.yaml` と `UNKNOWN.md`（`@n.m`、indirect=1 のときの adra）
  - `mncore/rtl/l2bm/README.md`（ポート B、DAR の読み出し、間接参照のアドレス式）
  - `mncore/rtl/sdram/README.md`
  - `mncore/status/WP-06.md`（MV の DRAM の歩き方の修正 `5f0ceb1`）
  - `viz/core/src/mv.rs`

## 作業

1. m 語（MV）を実行するユニットを作る。
   - 対象: L2BM ⇔ PDM ⇔ DRAM の転送の全モード、mvid の発行と `wait` の完了、priority、DRAM の間接参照（`$di`）。
   - DRAM の番地は、各グループの DRAM を `16i+k` の順に歩く（WP06 の修正）。
2. PDM と DRAM は SDRAM（8 MiB = 2^20 長語）に置く。
   - 縮小トポロジでの配置（グループ 1 個分の PDM / DRAM の深さ）を決め、`PDM_DEPTH` / `DRAM_DEPTH` を契約に提案する。
   - 範囲外は E_RANGE（契約 §3）。SDRAM 側の `err_addr` は最後の安全策として扱う。
3. L2BM へは `mn_l2bm` のポート B、DAR へは `dar_re` / `dar_raddr` でアクセスする。
   - 間接参照に DAR が要るなら、L2BM の `DAR=1`（BSRAM +3）を使う。M2 で要るかどうかは hello_world で判断して報告する。
4. 境界のポートを `rtl/mv/README.md` に定義する。
   - `wait` との連携: 発行したタグと完了。PE コアの `wait` が待つための信号。
   - `mn_core` への組み込みは WP37 が行う。
5. 正解は公式エミュレータ（4096 PE を実行し、範囲を切り出す）。
   - `d get $p` は PDM ではなく DRAM の内容を出すので、PDM は比較から外す（契約 §1）。
   - 確かめられていない間接参照の一致（契約 §1）も、ここで公式と照合する。
6. 実機: `mn_l2bm` + MV + `sdr_bus64` を載せた小さな試験デザインで、SDRAM 越しの転送が公式と一致することを確かめる。

## 受入基準

- MV を使う命令列のテスト（公式を期待値にしたもの 30 本以上。hello_world の MV の部分を含む）が、ユニットのテストベンチで全件一致する。
  - テストベンチは `mn_l2bm` と SDRAM のモデル（`sim/tb/sdram` のモデル）を含める。
- 合格条件の 3 つ（iverilog、lint、synth）を通し、資源を報告する。
- 実機の試験デザインで、SDRAM 越しの MV が一致する。
