# WP38 自動切り替えの実行器（全プログラムを実機で最後まで）

- 依存: M2（WP37）
- 担当: `mncore/tools/host/mnrun.py`（新規）とその補助ファイル、`mncore/fpga/multi/`（新規。ビットストリームの組の定義とビルド）、`mncore/sim/tb/multi/`
  - `mnhost.py` は読むだけ。必要な変更は最小限にし、既存のテスト（`test_mnhost.py`）を通し続けること。
- 参照: `mncore/fpga/top_m2/hello_hw.py`（手での切り替えの見本）、`mncore/status/WP-37.md`、契約 §7（BL616 の注意、`bridge reboot` で FPGA が Flash に戻ること）

## 目的

1 本のビットストリームに全機能が載らないので、ホストがプログラムを区間に分ける。区間ごとに、必要なユニットを含むビットストリームを SRAM に書き、状態を引き継ぎながら最後まで実機で実行する。

## 作業

1. ビットストリームの組を決めてビルドする（`fpga/multi/`）。
   - M2 の系統（L1BM / L2BM / MV + MAU / FP ALU / 行列 / BFN のどれか）で、組み合わせると全命令を覆えるようにする。
   - 例: M2a（整数）、M2 + MAU、M2 + FPALU + BFN、M2 + MAT。載らない組み合わせは分ける。
   - INFO のフラグで、載っているユニットを判定する。
2. 区間への分け方: 命令語ごとに必要なユニットをデコーダの情報（`mnisa` / WP10 の `grp`）から求める。同じビットストリームで実行できる最長の区間にまとめ、切り替えの回数を減らす。
3. 状態の引き継ぎ:
   - 切り替えの前に、PE（4 PE 分の LM/GRF/T/OMR/BAR）、L1BM、L2BM、DAR、行列レジスタ、フォワーディングレジスタ、MV のタグなど、次の区間に要る状態をすべて読み出す。切り替えた後に書き戻す。
   - ホストから読み書きできない状態（行列レジスタ、`$lbf`、フォワーディングレジスタなど）は、デザインに読み書きの口を足すか、区間の境目をそれらが生きていない位置に置く。
   - 足す口は、デバッグ用の空間 ID として PROTOCOL.md に追記する案を報告する。RTL の変更は `rtl/core/` に及ぶので、最小限にし、変更点を報告書に列挙する。WP34 と同じファイルを触る場合は、衝突を避けるため `rtl/core/` の外に置けないか先に検討する。
   - DRAM / PDM は SDRAM にあり、SRAM への再書き込みでは消えない。消えるかどうかを実機で確かめ、消えるなら引き継ぐ。
4. 実機で、公式の hello_world（MAU を使う）と FizzBuzz（`problems/challenge/20.fizzbuzz`、LM の深さで E_RANGE になるなら、そうなることを確かめて報告）を、`mnrun.py` 1 回で最後まで実行する。
5. 回帰: M2 の回帰（`run.py --m2` の対象 247 本）を `mnrun.py` で実機で回す。E_UNSUPPORTED で止まっていた本が、正解と一致するようになることを示す。

## 受入基準

- 公式の hello_world が `mnrun.py` 1 回で実機で最後まで実行され、正解と一致する。正解はゼロ規則なら縮小 Rust、REPLICA なら公式。
- M2 の回帰で、ユニットの不足による E_UNSUPPORTED が 0 本になる。値の食い違いも 0 本。切り替えの回数と所要時間を報告する。
- ビットストリームは SRAM にだけ書く。最後は LED の方針（契約 §7）に従ったデザインを書いた状態で残す。
