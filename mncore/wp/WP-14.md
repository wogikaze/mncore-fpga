# WP14 PE のローカル記憶とオペランド経路

- 依存: WP01（スキーマ）、WP07（RAM のレシピ）
- 担当: `mncore/rtl/pe/`（`mn_pe_core.v` を除く）、`mncore/sim/tb/pemem/`
- 参照: SDM 3.6.1（オペランド全般）、3.6.2（マスク）、3.6.3（ハザード）、3.7、Scrapbox「語長・アドレス・ストライド」「マスク適用」「ALU 結果の出力先」、`viz/core/src/machine.rs`

## 目的

1 PE 分の LM0/LM1/GRF0/GRF1/T の読み書きを、命令語のフィールドから正確に作る。

## 作業

1. アドレス生成 `mn_pe_agen`。
   - adr/adri/wl（単語、長語、2 長語）、cycle1〜3 の明示アドレス（flat）
   - T 間接（tregadr）、`$mb`/`$nb`、maadj/madpe
   - 4 サイクル分のアドレス列
2. 記憶 `mn_pe_store`。
   - BSRAM、もしくは仮想 PE 用の外部バス版（契約 §6 のバス）に差し替えられる構造にする。容量はパラメータ。
3. 書き込みの経路。
   - isel（ALU / MAU / L1BM / 転置読み出し）
   - 複数出力（同じステップで複数のメモリへ書く）
   - 書き込みマスク（imr、/xxxx、$imr）、ゼロフラッシュ、omr への書き込み
4. ステップ内の意味を実装する: **全入力を読み終えてから書き込む**。4 サイクル分の読み出しをバッファし、書き込みを後でまとめて行う。
5. 範囲外アクセスを検出して `E_RANGE` を出す。
6. テスト: 単一 PE のロードとストア（`lpassa` / `ipassa` 系だけ）の命令列を Python でデコードし、期待値は WP02 の Rust 出力を使う。
   WP02 が未完了なら、手書きの期待値で始めてよい。

## 受入基準

- passa 系を中心に、アドレスモードとマスクを網羅した 50 本以上の VSM で、メモリの最終状態が一致する。
