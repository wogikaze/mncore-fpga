### 動作（WP20 向けのインタフェースの要約。詳細は `mn_pe_lsu.v` の冒頭）

1 語（1 ステップ）を次の 3 段で処理する。ステップ内の読み出しはすべてステップ前の状態を見る（SDM 3.6.3.9、Rust Sim の 3 段と同じ）。

1. **start**（`idle` のとき受理）: 4 サイクル分の LM アドレスを計算して保持し、すべてのアクセスの範囲を検査する。範囲外なら何も読み書きせず `trap`（E_RANGE）と `done`。
2. **READ**: `rd_use`（{LM1, LM0, GRF1, GRF0}）のメモリを 4 サイクル分読み、LUT RAM の読み出しバッファにバス形式（未使用の語は 0）で置く。
3. **EXEC**: `opr_valid` の間、`opr_cycle` で任意のサイクルのオペランド（`opr_grf0/grf1/lm0/lm1/t`、各 128bit）が読める。コアはサイクル 0〜3 の順に演算器の出力（`res_mau/alu/l1bm/mread`、ALU/MAU のフラグ）を `res_valid`/`res_ready` で渡す（`res_cycle` が期待するサイクル。`res_*` は `res_ready` まで保持）。各結果について、最初のクロックで書き込む内容をマスクから決めて保持し、続く「ビート」で書く。1 ビートは「1 つの演算器出力の 1 長語（MSB 側→LSB 側）」を、それを選ぶ全出力先へ同時に書く。

- バス形式: `[127:96]` 語 0（MSB）… `[31:0]` 語 3。単語アクセスは語 0、長語は語 0〜1、2 長語は全部。
- `zf_en`/`zf_sel`/`zf_mask`: そのサイクルのゼロフラッシュ（フォワーディングレジスタ用。`res_ready` のクロックで有効）。
- ホストポート（WR_MEM / RD_MEM、PROTOCOL.md §5 の mw_*/mr_* と同じ形）: 空間 ID は PROTOCOL.md 版 1（1 LM0、2 LM1、3 GRF0、4 GRF1、5 T）。設計固有の 0x10 OMR（エントリ 1〜15、16bit）、0x11 BAR（0 `$mb`、1 `$nb`）。範囲外は `hp_req_err`（書かない、応答なし）。
- ストア: `mn_pe_lsu` は 4 チャネルの契約 §6 バス（valid/ready、応答は順序どおり、遅延は任意）だけでメモリに触れる。仮想 PE（WP34）は `mn_pe_store` を差し替えればよい。
- `rst` は順序制御と `$mb`/`$nb` を消す。メモリ、T、マスクレジスタは RAM なのでホストポートで消す（実機の d set と同じ扱い）。

### 公式エミュレータで確かめた挙動（Rust Sim と食い違うもの。RTL は公式に合わせた）

| 項目 | 公式エミュレータ | Rust Sim（viz/core） |
| --- | --- | --- |
| T への書き込みに長語マスクがかかり、そのサイクルの 4 フラグがすべて 0 | 何も書かない（LSB 側の長語も書かない） | LSB 側の長語を書く（`word_enabled` が i ≥ 2 で常に真） |
| `$mb` / `$lmb`（`$nb` 同様）にマスク | 12bit が入っている半語のフラグで決まる（`$mb` は `[111:96]`、`$lmb` は `[79:64]`。長語マスクなら f[2] / f[0]） | フラグが 1 つでも 1 なら書く |
| 同じステップで `$omr<n>` に書き、`/$imr<n>` を使う | マスクはステップ前の値（SDM 3.6.2「直後のステップから利用可能」） | 書いた後の値（書き込みループの順序による） |

- 根拠: 試験プログラムのうち `mask_t_pat`、`t_mask_zero_cycles`、`omr_bar_mask`、`bar_imr_lmb_hi`、`bar_imr_mb`、`omr_same_step` の 6 本で、公式と Rust Sim の結果が異なる（残り 80 本は一致）。加えて単発のプローブ（フラグのパターン 10 通り × `$mb`/`$lmb`、T に固定パターン / `$imr` / 複数行マスク）で規則を確かめた。
- そのほかの確認（公式と Rust Sim で一致）: 長語マスクは MSB 側長語の半語単位（`spassa` の 16bit レーンのフラグで半語ごとに書き分けられる）、`$mb` は語 0、`$lmb` は語 1 の下位 12bit、T 間接は語 1 を加算、`d set/get $lt` の番号はサイクル、`imm` は LM0 に出力できない（assemble3 が拒否）。

## 未解決の点

1. **論理の量が多い**（LUT4 の場所で約 5,500、うち SSRAM 分が約 1,300）。最初の版（約 10,000 + SSRAM）から、書き込み経路を 64bit の共有データパスにする、オペランドを読み出しバッファの書き込み時に整形する、agen の加算を 2 入力に分ける、などで減らした。主な内訳は、読み出しバッファ（4 メモリ × 4 サイクル × 2 長語、RAM16SDP4 128 個 = LUT4 の場所 1,024）、128bit × 4 演算器の選択とゼロフラッシュ、4 チャネル分の書き込みデータ（語の複製、read-modify-write の合成、ホスト）、READ / EXEC / ホストのアドレス選択。削減案:
   - ステップ内で書かれないメモリは読み出しバッファを通さずに EXEC で直接読む（バッファが要るのは「読んで書く」メモリだけ）。
   - 演算器の出力を 64bit ずつ受ける（コア側で半分ずつ渡す）。
   - E_RANGE を 4 サイクル並列でなく 1 サイクルずつ検査する（agen とトラップ報告を 1/4 に）。
2. **Fmax は約 62 MHz**（最初の版は 45 MHz。ストアの要求レジスタと、ビートの選択を 1 クロック前に決める変更で上げた）。残りのクリティカルパスはサイクルの最初のクロック（マスクフラグ → 書き込む内容 → 最初のビートの選択）。100 MHz が要るなら、ここを 2 クロックに分ける（1 ステップ 4 クロック増）、またはマスクフラグを前のサイクルで先読みする。
3. **MAU / L1BM / 行列読み出しからの書き込み**（isel = 00 / 10 / 11）は、それらの演算器がまだないので、テストベンチの乱数値で「取り違えがないこと」しか確かめていない。データの経路は ALU と同じ（isel で選ぶだけ）。
4. **`mn_pe_rduse` の MAU / L1BM / 行列書き込みの規則は未検証**（試験は ALU の passa / imm / zero だけ）。特に `mw=1`（?mwrite）で読むメモリを isela とみなしたのは推定。WP20 がデコーダ（WP10）の出力から作るなら不要。
5. **同じステップで T（または `$mb`）に書き、T 間接（または BAR）でアドレスを作る場合**、RTL は読み書きともステップ前の T / BAR でアドレスを作る。Rust Sim は書き込みの順序しだいで書いた後の値を使う。公式エミュレータでは確かめていない（assemble3 が受理するかも未確認）。
6. 語長の欄が 11 のアクセスは 2 長語として扱い、`unsup` を出す（assemble3 は出さない値）。コアが `E_UNSUPPORTED` にするかは WP20 が決める。
7. `ll=11`（noforward）の語でも記憶への書き込みは通常どおり行う（フォワーディングの扱いは WP20）。VSM から ll=11 の語を作る試験はしていない。
8. 試験のレコードは生成物（約 7.5 MB）なのでコミットしていない。`simrun.py pemem` の前に `gen_tests.py` を一度実行する必要がある（WSL と公式バイナリが要る）。

## 契約変更の要望

1. **§1 と UNKNOWN.md に、Rust Sim と公式の食い違い 3 件を記録し、WP06（viz/core のブランチ）で直してほしい。** 上の表のとおり（T の長語マスクで全フラグ 0、`$mb`/`$nb` のマスク、同じステップの `$omr`/`$imr`）。
2. **§3 の E_RANGE の条件を明記してほしい**: 「実際に行われるアクセスだけを検査する。読み出しは演算器の入力として使うメモリだけ、書き込みはマスクで 1 語以上書かれるものだけ」。assemble3 は使わないメモリのアドレス欄にも値を置くので、欄の値だけで判定するとトラップが誤って出る。
3. **§7 / PROTOCOL.md に、PE の設計固有の空間を加えてほしい**: 0x10 `OMR`（アドレス = エントリ 1〜15、値の下位 16bit。ビット 4c+3..4c がサイクル c、4c+3 が MSB 側）、0x11 `BAR`（0 `$mb`、1 `$nb`、下位 12bit）。ndmp の `OMR`（エントリ × 4 + サイクル）とはホストツールで変換する。
4. **§6 の資源予算に LUT の目安を加えてほしい**: PE の記憶は LUT4 の場所で約 5,500（SSRAM 約 1,300 を含む）、Fmax 約 62 MHz。FPU などと合わせて 20,736 に収まるかを WP20 / WP21 の段階で見積もる必要がある（削減案は上の未解決 1）。
5. **rd_use（どのメモリを入力として読むか）の担当を決めてほしい**: WP10 のデコーダの派生信号とするのが自然（`mn_pe_rduse` を参考実装として渡す）。

## 次の WP への申し送り

- **WP20（PE コア）**
  - 使い方: `idle` のとき `start` と `jw`、`rd_use` を出し、`done` まで `jw` と `rd_use` を保持する。`opr_valid` になったら `opr_cycle` で各サイクルのオペランドを読み、演算器の出力を `res_cycle` の順に `res_valid` で渡す（`res_ready` まで保持）。`done` で次の語へ。`trap` なら停止して E_RANGE（`trap_wr`、`trap_mem`、`trap_cycle`、`trap_addr` は報告用）。
  - nop（ll=00）の語も処理できる（何も書かない）が、約 11 クロックかかる。コアで飛ばすとよい。
  - フォワーディングレジスタ（`$aluf` など）は WP20 の担当。ゼロフラッシュは `zf_en`/`zf_sel`/`zf_mask` を使って同じ値にすること（公式・Rust Sim ともフラッシュ後の値をフォワードする）。
  - `$omr` に書くフラグ（`res_alu_flags`、`res_mau_flags`）は 4bit / サイクル、bit 3 が MSB 側の要素（SDM 3.6.12.1、3.6.9.26）。マスクで落とされたフラグは 0 として書かれる（Rust Sim と公式で一致）。
  - 固定値オペランド（`$peid` など）、`$lbf` などのフォワーディング入力は WP20 側で選ぶ（この unit は記憶だけを出す）。
  - ホストポートは d set / d get にそのまま使える（空間 ID は PROTOCOL.md 版 1 と同じ）。
- **WP34（仮想 PE）**: `mn_pe_lsu` のストアチャネル（4 本の契約 §6 バス、任意の遅延・待ちに対応済み。乱数で待たせるストアで全件一致）に SDRAM / 共有 BSRAM のアダプタをつなぐ。書き込みは常に 32bit 語単位のマスク。
- **WP02 / WP06**: 試験プログラム 86 本（`gen_tests.py` の `TESTS`）は記憶とマスクの細かい規則を突く。Rust Sim を直したら `build/emu/*.vsm` で再確認できる。
- 試験の追加は `gen_tests.py` の `TESTS` に 1 行足す（期待値は自動で公式から取る）。範囲外の試験だけはトラップの期待値（語、メモリ、サイクル、読み書き、語アドレス）を書く。
