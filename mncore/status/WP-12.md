### インタフェース

`mn_fp_fma #(TAGW)`: `in_valid, prec[1:0], rnd, a[63:0], b[63:0], c[63:0], in_tag` → 入力を取り込んだエッジの 14 エッジ後に `out_valid, z[63:0], out_tag`。
a・b は演算の形式（d は 64、f は下位 32、h は下位 16 ビット）、c は d なら倍精度、ほかは単精度（下位 32）。z は出力の形式で下に詰める。

`mn_mau_vec #(TAGW)`: `in_valid / in_ready`、`dmode[1:0], round_out, passa, zeroc, mdw_side, signa..c, exta..c, pe_sub[1:0], a_bus, b_bus, c_bus[127:0], in_tag` → `out_valid`（1 クロック）、`z_bus[127:0]`（`out_valid` の間だけ有効）、`flags[3:0]`、`out_tag`。
欄の名前は `j_flat.yaml` の `pe_mauc_*` に合わせた。スロットを受けたエッジから結果まで d 18、f 19、h 21 エッジ。1 レーン / クロックで流れる（d は毎クロック 1 スロット、f は 2 クロック、h は 4 クロックに 1 スロット）。

## 未解決の点

1. **Rust Sim と公式エミュレータの食い違い（新しく確定した規則）**
   - 公式の加算器には、Sim にない規則が 2 つある（SPEC.md §2.2）。
     - 積を捨てる: `Uc - Ep >= T`（T = 55（d）、26（f、h））なら積をゼロとして扱う。
     - h の加数の格子: c を `2^(Ep - 28)` の格子に揃える（d の 88、f の 41 と同じ扱い）。
   - WP03 の `round_twice`（「もとの出力精度の 2 ビット下までを残して小さい加数を捨てる」）は、この 2 つの規則が出力丸めのある形で見えたもの。WP03 の説明は確かめた範囲の観察で、規則としては正しくない（加数が積より大きいか小さいかで規則が違い、h は格子、d・f は積の指数で決まる）。
   - **出力丸めのない形（`dvfmau`、`fvfma`、`hvfma` など）でも境界で表れる**: c がちょうど 2 の冪、積の符号が逆、仮数積が 2 を超え、`d = T` のとき。例: `dvfmau` で a = `a6459c860b63a7b1`、b = `561fffffffffffff`、c = `3fd0000000000000` → 公式 `3fd0000000000000`、Sim（正確な丸め）`3fcfffffffffffff`。seed 1 のベクタには該当する行がなく、disputed の印もない。別の seed で生成すると、印のないファイルに食い違いが出うる。
   - RTL は公式どおり。Sim の修正案: `float::vfma` に (1) a・b・c が有限で `Uc - Ep >= T` なら積をゼロにする、(2) `HALF` にも `align_c(c, Ep - 28)` をかける、(3) WP03 の `ext_mul` の修正（拡張したオペランドを演算の形式に直してから掛ける）を入れる。`mnfp_ref.py` の `vfma` がその形で、ベクタと探査の全行で公式と一致する。
2. Fmax は `mn_mau_vec` 全体で中央値 127 MHz、最小 120 MHz（DSP 以外）。コアのクロックをこれより高くするなら、丸め（c12）、正規化（c10）などの段をさらに分ける必要がある。レイテンシは増えてよい（スループットは変わらない）。
3. LUT は `mn_mau_vec` 全体で LUT 3,763 ＋ ALU 972（デバイスの LUT4 20,736 の約 23%）。c の位置合わせを 143 ビットの窓で行っているのが大きい。大きい方の演算数を窓の上に置く方式（窓 約 92 ビット）にすれば減らせる見込みだが、検証済みの今の形を優先した。
4. 疑似単精度 g（dmode = 11）のベクトル命令はアセンブラが受理しないので、RTL では f と同じに扱い、検査していない。
5. 行列 MAU（mfma/mmul）とブロックフロートは対象外（WP30）。

## 契約変更の要望

1. **§1・§5**: 上の「未解決の点」1 の規則（積を捨てる T、h の格子 K = 28）を、WP03 の FORMAT.md の `round_twice` の説明と置き換えてほしい（WP03 の担当ファイルなので変えていない）。あわせて、vecgen に出力丸めのない形の境界（c が 2 の冪で `d = T`）を足すと、Sim の修正の確認にもなる。Sim の修正は WP06 か後続の作業で、修正案は上のとおり。
2. **§5 のベクタの置き場所**: `mncore/sim/tb/fpu_fp/probe/`（境界の固定サンプル 1,904 行、87 KB、全行を公式で照合済み）をコミットした。`vectors_fixed` と同じ扱い（生成物だが小さな固定サンプル）として認めてほしい。`vectors_fixed/fp_probe/` のような場所に移すべきなら指示がほしい。

## 次の WP への申し送り

- **WP20（PE コアの統合）**: `mn_mau_vec` の使い方。
  - MAUC の欄（`pe_mauc_dmode`、`round_out`、`passa`、`zeroc`、`mdw_side`、`signa`〜`signc`、`exta`〜`extc`）をそのまま入れる。`mmode = 1`（行列）や `enfma = 0` の語では使わない。
  - 1 命令は 4 サイクル = 4 スロット。スロットごとに `in_valid` を出し、`in_ready` を待つ。結果は順番どおりに `out_valid` で 1 クロックずつ出る（`z_bus` はそのクロックだけ有効なので受け取る側でレジスタに取る）。`in_tag` に宛先やサイクル番号を入れておける。
  - `pe_sub` は MAB 内の PE の位置（dvfma/dvmul の u/d に使う）。1 PE モードでは PE 0。
  - h 命令の 1 スロットは 4 レーンで 4 クロック、1 命令で 16 クロックかかる（d は 4 クロック）。
- **WP13（FP 系 ALU）**: `mn_fp_f2h` は公式の `r_round` の式そのもの（WP03 の `cvt_f2h` 1,442 行で一致）。ALU の `rounda` / `roundb` に使える。`rtl/fpu/SPEC.md` は WP12 の節だけを書いた。WP13 の節を足してほしい。
- **WP30（行列 MAU）**: 行列の加数の格子（NUMERICS.md の K = 86 / 39 / 34）と、ここで見つけた「加数が大きいとき積を捨てる」規則の行列版があるかを、公式で確かめる必要がある。`probe_align.py` の作り方（境界の行を作って `vecgen --check-official --in` にかけ、規則のパラメータをずらしたモデルと比べる）が使える。`mn_fp_mul53` のタイル分けは 53 ビットの仮数に 8 個の DSP で足りる。
- **WP03（vecgen）**: FORMAT.md の `round_twice` の説明（上の契約変更の要望 1）。`probe_align.py` の境界の作り方を vecgen の edge 行に取り込むとよい。
