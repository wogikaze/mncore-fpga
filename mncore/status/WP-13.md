### インタフェース

`mn_fp_alu`（`mn_alu_int` と同じ形。違いは `imm32` がないことと `pe_aluc_iselb` があること）:

```
mn_fp_alu #(.RND(1)) (
  clk, rst,
  in_valid, in_ready,
  pe_aluc_dmode[1:0], pe_aluc_aluop[4:0], pe_aluc_is_unsigned, pe_aluc_rounda, pe_aluc_roundb,
  pe_aluc_isela[3:0], pe_aluc_iselb[2:0],        // mn_dec_j の出力をそのままつなぐ
  x[127:0], y[127:0],                            // 入力元を選んだ後、丸める前の 2 長語
  cls_bf,                                        // 組み合わせ回路: bfn / bfe（mn_fp_alu_bfn へ）
  out_valid, out_ready, z[127:0], flags[3:0], out_err
)
```

- 振り分け: `mn_alu_cls` の `cls_fp` のうち、`cls_bf` = 1 なら `mn_fp_alu_bfn`、0 なら `mn_fp_alu`。passa / packbit は `mn_alu_cls` が `cls_int` にする（d / f / h と l / i / s で機械語が同じ）。
- 要素ごとの命令は MSB 側の長語だけを計算し、結果の LSB 側の長語は x の LSB 側の長語（`r` を付けたら 0）。公式と Sim の挙動のとおり。
- 全段が同時に進む（`in_ready = !out_valid || out_ready`）。サイクル t に受け付けた要求の結果はサイクル t + 5 に出る。
- このユニットが実行しない ALUC は `out_err` = 1（z = 0、flags = 0）。
- `RND = 0` で入力の丸めとその段を外せる（呼び出し側で丸める場合）。

`mn_fp_alu_bfn`: ALUC は `pe_aluc_dmode`、`_aluop`（11110 = bfn、11101 = bfe）、`_rounda`、`_iselb`（h は 9 − n）。`x[128*p +: 128]` が PE p（subpeid p）の入力、`z[128*p +: 128]` が結果、`flags[4*p +: 4]` は常に 0、`out_err` は bfn / bfe 以外を受け付けたとき 1。in_ready はアイドルのときだけ。

- LUT は LUT1〜LUT4 の数、ALU は桁上げ鎖のセル数（1 個が LUT 1 個分の場所を使う）、MUX2 は MUX2_LUT5〜8。`mn_alu_rnd` は `mn_fp_alu` に 2 個、`mn_fp_alu_bfn` に 1 個入る（WP11 の測定で 1 個 LUT 112、ALU 60）。
- ハーネスごとの配置配線（`-nowidelut`、シード 1）: `mn_fp_alu` は LUT4 3,082 / 20,736（14%、ハーネスの入力シフトレジスタと XOR の木を含む）、DFF 1,587。`mn_fp_alu_bfn` は LUT4 3,308（15%）、DFF 2,174。
- WP11 と同じく `-nowidelut` のほうが LUT が少なく（`mn_fp_alu_bfn` で 9%）、Fmax も高い。
- 経緯: 最初の版は 61 MHz（入力の丸めと要素ロジックが同じ段）と 76 MHz（ブロック指数の木が 1 段に 2 レベル）、LUT 3,401 + ALU 953 だった。丸めの段を分け、丸めの式をキャリーの鎖を直列にしない形にし（WP11 の `mn_alu_rnd` と同じ考え方）、最終段の選択を前の段で決めた one-hot にし、木を 3 段にし、安い命令の結果を 64bit で 1 回だけ組み立てる形にして、上の値になった。

## 未解決の点

1. **面積が大きい。** `mn_fp_alu` は PE 1 個あたり LUT 2,514 + ALU 499 + FF 1,127（`-nowidelut`。LUT と ALU でデバイスの約 15%）、`mn_fp_alu_bfn` は MAB 1 個あたり LUT 2,667 + ALU 401 + FF 956。
   - `mn_fp_alu` の内訳はおおよそ、7 個の要素ロジック（倍精度 1、単精度 2、半精度 4）約 450、入力の丸め 2 個 約 220、SIMD の右シフタ 約 400、各段の組み立てと選択。FF は 5 段のパイプライン（LSB 側の長語を各段で運ぶ分を含む）。
   - 丸めを ALU の外で行えば（`RND = 0`）LUT 約 300、ALU 121、FF 269 が減る。
   - 1 MAB（4 PE）を実体で持つなら、4 個は重い。仮想 PE（WP34）で物理 PE を 1 個にする前提なら許容範囲と考える。
2. **ブロックフロート化は MAB の 4 PE の入力を同時に要る。** 1 PE モード（初期の RTL）では正しく計算できない（ほかの 3 PE の値がない）。WP20 / WP30 で、MAB 単位の入力をどう集めるかを決める必要がある。
3. **Fmax は `-nowidelut` で 100 MHz を少し超える程度**（最小 101〜103 MHz。既定の合成では 94〜97 MHz）。コアの周波数が決まっていないので、これ以上は段を増やしていない。足りなければ、`mn_fp_alu` の段 3 と `mn_fp_alu_bfn` の変換の段 P / S にレジスタを 1 段ずつ足す（FF がそれぞれ 200〜260 増え、レイテンシが 1 増える）。
4. passa / packbit は `mn_alu_cls` が `mn_alu_int` に送るので、`mn_fp_alu` の中の実装は統合では使われない（fpalu のベクタを通すために残した）。外せば段 3 の選択が 2 入力減る（資源の差は測っていない）。
5. `mncore/rtl/fpu/SPEC.md` は WP12 と共有する。このブランチではファイルを新規作成した（WP13 の節だけ）ので、WP12 もファイルを作っていればマージで衝突する。中身は節ごとに独立しているので、両方の節を並べればよい。
6. zero と `uhbfe/9 $peid ...`（もし書けるなら）は機械語で区別できない。`mn_alu_cls` は is_unsigned = 1 かつ isela = 0101 を zero とする。この WP も同じ規則に従う（`cls_bf` は aluop 11101 を常に bfe とするが、`mn_alu_cls` が先に zero を `cls_int` にする）。

## 契約変更の要望

1. **§6 ALU ユニットの共通インタフェース**: `mn_alu_int` の形（ALUC は `pe_aluc_*` の名前、`x` / `y` / `z` 128bit、`flags` 4bit、valid / ready、`out_err`、振り分けの組み合わせ回路の出力）を ALU 系の共通の形として書いてほしい。`mn_fp_alu` はこれに `pe_aluc_iselb` を足した形にした。
2. **MAB をまたぐ ALU 命令の受け渡し**（bfn / bfe、WP30 の msl / msr と共通）: PE p の値を `x[128*p +: 128]` に並べる形を提案する。

（「`r` を dmode ≠ 10 に付けた語を E_UNSUPPORTED に」と「`r` の丸めを整数 ALU と共有」は、作業の途中で WP11 のマージにより契約に入った / 実現したので、要望から外した。）

## 次の WP への申し送り

- **WP20（PE 統合）**
  - つなぎ方は `mn_alu_int` と同じ。ALUC の欄は `mn_dec_j` の出力をそのまま、`x` / `y` は入力元を選んだ後の丸める前の値。`mn_alu_cls` の `cls_fp` のうち `cls_bf` = 0 を `mn_fp_alu` に、1 を `mn_fp_alu_bfn` に送る。
  - 結果の LSB 側の長語は x の LSB 側の長語がそのまま入る。`r` を付けた入力は LSB 側の長語が 0 になる。
  - マスクフラグは `flags`（ブロックフロート化は常に 0）。
  - ブロックフロート化は 4 PE の同じサイクルの入力が要る。1 PE モードでは扱えない（未解決 2）。
  - 丸めを ALU の外で 1 回だけ行うなら、`mn_fp_alu` は `RND = 0` の構成を使える（資源は「資源と Fmax」の表。`mn_alu_int` には同様の切り替えはなく、中で丸める）。
- **WP30（MAB）**: ブロックフロート化の結果は行列演算の入力になる。`mn_fp_alu_bfn` は MAB 単位で 1 個置けばよい。
- **WP03**: `vectors_fixed/fpalu` の 79 ファイルと、生成の全 133 ファイルがそのまま使えた。追加の要望はない。
