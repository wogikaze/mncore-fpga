### 境界のポート（詳細は `mncore/rtl/mv/README.md`）

- 発行: `start` + `mw[81:0]`（命令メモリの `[81:0]` をそのまま）→ `acc` + `acc_st`（0 OK / 1 E_RANGE / 2 E_UNSUPPORTED）+ `acc_field`（`MN_M_<欄>_IDX`）。OK なら転送は裏で続き、`busy` が 0 になったら完了（タグも数え終わっている）。
- wait: `wt_tag`（j 語の `wd`）→ `wt_cnt`（0 / 1 / 2 以上、`busy` = 0 で有効）、`wt_take`（消費）。
- L2BM: `cb_*` を `mn_l2bm` のポート B に、`dar_*` を DAR の読み出しポートにそのままつなぐ。SDRAM: `sd_*` を `sdr_bus64` に。
- ホスト: `hw_*` / `hr_*`（`brd_host_if` の mw / mr と同じ形）で空間 0x07 L2BM、0x08 PDM、0x09 DRAM（loc 0）。`busy` = 0 のときだけ。

### 公式エミュレータで確かめた意味（要点）

プローブは全チップの全ユニットに別々の値を置き、全 L2BM・全 DRAM・全 PDM を読んで全チップのモデルと照合した（`probe.py`。アセンブラが作らない組み合わせは、アセンブル後に欄を手で変えた語）。

1. **欄の割り当て**: adra は DRAM のアドレス ÷ 16（DRAM のある形）、PDM ⇔ L2BM の PDM 側、PDM → PDM の転送元。adrb は L2BM のアドレス ÷ 16、PDM ⇔ DRAM の PDM 側、PDM → PDM の転送先。destid / srcid はグループ × 2 + L2B（PDM / DRAM では bit 0 を見ない、並列ではグループを見ない、mvb2 などでは両方を見ない）。縮約は {destid[0], srcid} が演算、destid[2:1] が PDM のグループ。**UNKNOWN.md A 節の `destid` / `srcid`、`adra` / `adrb`、`indirect` の答え**。
2. **L2BM のアドレスは 64 長語単位**（adrb の bit 1..0 を使わない）。PDM / DRAM は 16 長語単位。
3. **チップの大きさでの折り返し**: L2BM 2^15、PDM 2^19、DRAM 2^29 長語（MV の番地）。公式の `d get $d` と `r` 行は 2^29 以上で異常終了する。
4. **形**: アセンブラの 24 形のほかに、PDM → DRAM / DRAM → PDM / PDM → PDM の並列（各グループ）と、PDM → L2BM の tmode 010（グループ g の PDM → g の L2BM 2 つ）を公式は動かす。mmode 111 と tmode 110 / 111 は何もしない（MV は完了し、タグは数える）。残りの 14 組は異常終了。
5. **nw**: 0 は異常終了。b2 / b4 / b の形と DRAM → PDM の mvd は 4 の倍数でないと異常終了、ほかはチャンク（16 長語）単位で nw 個（mvd の PDM → L2BM / L2BM → PDM / PDM → DRAM も）。
6. **DRAM の歩き方**: 各グループのチャンク i（WP06 の修正 `5f0ceb1` と同じ）。mvb4 / mvr4 は 2i + c。
7. **間接参照**: チャンク i は `16 × (DAR[(M + i / N) mod 1024] + i mod N)`、M = adra[9:0]、**N = adra[14:10]（5bit。bit 15 以上は見ない）**。**nd を省略（N = 0）すると N は無限大: `16 × (DAR[M] + i)`**。DAR はグループごと。全 17 種の DRAM の形で確認（`probe.py ind ndw`）。
8. **順序**: 公式は MV を発行の時点で完了させる（直後の L2BM 命令が MV の結果を見る。直前の L2BM 命令の結果を MV が見る）。MV の中ではすべての読み出しが書き込みの前（PDM → PDM の重なりは写し）。
9. **タグと wait**: wait は「完了して、まだ wait していない MV」が 1 つなら消費して通る。0 なら止まったまま終わる（後の語は実行されない。d get はその時点の状態）。2 以上なら異常終了（`PE waits for double asserted DT done flag`）。タグを付けた MV を wait しなくても誤りではない。何もしない形もタグを数え、`valid` = 0 は数えない。ll = 11 の語の wait も同じ。
10. **縮約**: N_L2B = 1 では x と 0 の縮約（`mn_l2bm` の RRN = 2 と同じ規則）で、全演算・全精度・特殊値で公式と一致（`red_*` 試験）。
11. **priority**: 結果に影響しない。dmode は縮約でなければ見ない（11 でもよい）。

## PDM / DRAM の配置と深さ（提案）

| SDRAM の長語アドレス | 大きさ | 内容 |
| --- | --- | --- |
| 0x00000〜0x7FFFF | 2^19 長語（4 MiB） | DRAM（グループ 0）。`DRAM_DEPTH` = 524,288 |
| 0x80000〜0x9FFFF | 2^17 長語（1 MiB） | PDM（グループ 0）。`PDM_DEPTH` = 131,072 |
| 0xA0000〜0xFFFFF | 393,216 長語（3 MiB） | 空き（WP34 の仮想 PE の状態、命令の先読みなど） |

- 根拠: コーパス（`third_party/mncore` の全 .vsm）の MV / `r` 行 / `d get` が触る最大の番地は、DRAM 208,064 長語（`viz/core/benchmarks/mnist_train_step.vsm`。ほかの 332 本は 32,768 以下）、PDM 32,768 長語（210 本）。上の深さはすべてを含む。
- `mn_mv` のパラメータ（`PDM_AW`、`DRAM_AW`、`PDM_BASE`、`DRAM_BASE`）で変えられる。WP34 がもっと要るなら DRAM 2^18・PDM 2^16（5.5 MiB 空き）でもコーパスは全部入る。
- 存在するグループは 0 だけ（N_L2B = 1）。グループ 1〜3 の PDM / DRAM は存在しない（読むと 0、書き込みは捨てる）。

## DAR は M2 で要るか

**要らない。** hello_world の MV は `mvp/n64 $lc64@0.0 $d0@0`（直接参照）だけで、`l2bmdars` / `l2bmdarw` も `$di` も使わない。`mn_l2bm` の `DAR` = 0 で BSRAM が 3 減る（WP32 の表で LUT 927 / ALU 196 / FF 120 / BSRAM 8）。
`DAR` = 0 の `mn_l2bm` は `dar_rdata` = 0 を返すので、`mn_mv` の間接参照は DAR = 0 として動く。DAR を書く `l2bmdars` は E_UNSUPPORTED で止まるので、それより前（DAR を書かないプログラム）では公式の DAR も 0 で、結果は一致する。
間接参照を使うのはコーパスの 19 本（problems では `48.matmul-tra-pkg-lmdram-16-256-1024/answer.vsm`、`challenge/16.count-up` の 2 本）で、これらには `DAR` = 1 のビットストリームが要る。

## 未解決の点

1. **Rust Sim（viz/core）と公式の食い違い**（契約 §1。RTL は公式に合わせた。Sim は直していない）。
   - **nd を省略した DRAM 間接参照**: 公式はチャンク i を `16 × (DAR[M] + i)` にする（N 無限大: エントリ M を使い続け、オフセットが増える）。Rust の `mv.rs` は `16 × DAR[(M + i) mod 1024]`（エントリを進め、オフセット 0）。
     SDM 3.5.6 の本文の「アドレスは DAR[M + i]」も Rust と同じ読み方だが、公式は式 `DAR[(M + i/N) % 1024] + i % N` に N = ∞ を入れた形で動く。`rust_check.py` の 3 本（上の 4.）で食い違い、nd あり・直接参照・PDM の重なりは一致する。
     WP32 の「nd の省略形は確かめていない（viz の記録では公式は DRAM にアクセスしない）」への答え: アクセスする。
   - 間接参照の `mvb` / `mvd` / `mvr`（契約 §1 の「公式との一致が未確認」）は、nd を付けた形では Rust と同じ番地で、全チップの 4 グループの DAR を別々にしたプローブで公式と一致した。
2. **hello_world は縮小トポロジでは公式と同じ値にならない**（M2 の目標に関わる。WP37・lead へ）。
   公式の 4096 PE では、`l1bmrhfadd` が 16 MAB の同じ値を、`l2bmrhfadd` が 8 L1B の同じ値を足すので、L2BM n0c0 の 0x40 番地は GRF の値の 128 倍になる:
   GRF0 m0p0 の `3a65…`（半精度の指数 29）→ L1BM n0c0b0 の 0x30 番地 `4265…`（指数 33、×16）→ L2BM n0c0 の 0x40 番地 `4865 6c6c 6f2c 2077` = "Hello, w"（指数 36、×8）。
   契約 §3 の「存在しないユニットからの縮約の入力は 0」のままでは、1 MAB・1 L1B の縮小トポロジの和は ×1 で、DRAM n0 に "Hello, world!" は出ない（`3a65…` 系の値になる）。
   MV の部分は、公式の 4096 PE の L2BM を初期値にした `hello_mv` で一致する。L1B 0 にだけ hello_world の L1BM を置いた `hello_l2mv`（`l2bmrhfadd` + MV）も一致するが、値は ×1 の方。
3. **wait の停止理由**: 発行していない（または消費済みの）タグを待つと、公式は止まったまま終わる。試験のコアは停止理由 **4（WAIT、info = タグ）** で RUN を止める（「契約変更の要望」3）。完了が 2 つ以上たまったタグの wait は公式が異常終了するので E_UNSUPPORTED `wd`（91）にした。
4. **アセンブラが作らない形**: PDM ⇔ DRAM / PDM → PDM の並列と PDM → L2BM の tmode 010 は公式が動かすので実装した。公式が異常終了する 14 組、nw = 0、nw が 4 の倍数でない b2 / b4 / b と DRAM → PDM の mvd、縮約の表にない演算と dmode 11 は E_UNSUPPORTED。
5. **`mn_dec_m`（WP10）の `mv_unsup_vec` は公式と合わない**: mmode 111、tmode 110 / 111 を E_UNSUPPORTED にするが、公式は何もしない（タグは数える）。dmode 11 も縮約でなければ無視される。`mn_mv` は自分で判定する（`acc_st`）。
6. **公式の DRAM の上限**: MV の DRAM の番地は 2^29 長語で折り返すが、`d get $d` と `r` 行は 2^29 以上で異常終了する（`offchip_memory: out-of-range access`）。縮小トポロジでは 2^19 以上が E_RANGE なので影響はない。
7. **PDM の `d get`**: 公式の `d get $p` は DRAM を出す（契約 §1）。ホストの空間 8 は本当の PDM を読むので、`mnhost.py run` の `$p` の行は公式のダンプと比べられない（比較から外す）。試験は PDM を MV で DRAM に写して比べた。
8. **性能**: チャンクごとに読みと書きを重ねない（16 長語を読み終えてから 16 長語を書く）。L2BM ⇔ SDRAM で 1 長語あたり約 2.3〜2.8 クロック（27 MHz のコア）。重ねれば 2 倍近く速くなるが、M2 には不要と判断した。
9. **トポロジ**: N_L2B = 1 だけ（グループ 0 と L2B n0c0）。N_L2B > 1 には、L2BM ごとのポート、多入力の縮約、グループごとの DRAM / PDM / DAR が要る。
10. **実機の SDRAM のクロックの余裕**: 配置配線の見積もりで、SDRAM 側（99 MHz）の Fmax は 100.12 MHz（`--freq 27` のとき）。@@PNRNOTE@@

## 契約変更の要望

1. **§3 に PDM / DRAM の容量と SDRAM の配置を入れる**: `PDM_DEPTH` = 2^17 長語、`DRAM_DEPTH` = 2^19 長語と、上の「PDM / DRAM の配置と深さ」の表。
   あわせて「アドレスは折り返しの後で比べる」のチップの大きさ: L2BM 2^15、PDM 2^19、**DRAM 2^29 長語**（MV の番地。公式で確認）。L2BM のアドレスは 64 長語単位（adrb の bit 1..0 は使われない）。
2. **§1 の食い違いの一覧に、nd を省略した DRAM 間接参照**（「未解決の点」1）を加え、「`$di` を使う mvb / mvd / mvr は公式との一致が未確認」を「nd を付けた形は一致（WP33）。nd を省略した形は Rust が食い違う」に改める。
3. **§7 / PROTOCOL.md に停止理由 4（WAIT）**を加える: 「待つタグに完了した MV がない wait。公式はそこで止まったまま終わる（後の語は実行されず、d get はその時点の状態）。info = タグ、pc = その語」。
   ホスト（`mnhost.py run`）は WAIT の後の RUN を実行せず、`d get` だけを行う。完了が 2 つ以上たまったタグの wait は E_UNSUPPORTED `wd`（91、公式は異常終了）。
4. **§6 の資源予算に MV を加える**: `mn_mv` は BSRAM 0、LUT 約 1,070、ALU 約 210、FF 約 230、SSRAM 32。`sdr_bus64`（ASYNC）は WP05 の値（LUT 約 1,060、BSRAM 0）と rPLL 1 個。
5. **UNKNOWN.md / m.yaml（WP01）と `mn_dec_m`（WP10）の更新案**（`spec/isa/`、`rtl/dec/` は担当外なので変更していない）:
   - A 節の m 語の 3 行（`destid` / `srcid`、`adra` / `adrb`、`indirect` と `adra`）を、確定した意味として C 節へ（上の「公式エミュレータで確かめた意味」1、2、7）。nd は adra[14:10] の 5bit（アセンブラも nd ≤ 31 しか受け付けない）。
   - m.yaml の `mmode` の notes「111 は未観測」→「111 は何もしない（MV は完了し、タグは数える）」。`tmode` に 110 / 111（何もしない）を加える。`dmode` は縮約でなければ見ない。`nw` は 16 長語のチャンク数（形によって 4 の倍数が必要）。
   - `mv_unsup_vec` の mmode 111 / tmode 110・111 / dmode 11 の判定を外す（または WP37 が m 語にデコーダの判定を使わない）。
6. **M2 の目標の見直し**（「未解決の点」2）: 「存在しないユニットからの縮約の入力は 0」のままでは、hello_world の DRAM の出力は公式（4096 PE を実行して切り出したもの）と一致しない。lead の判断が要る
   （例: M2 の正解を縮小トポロジの Rust Sim（契約 §3 (a)）にする、縮約で存在しないユニットを存在するユニットの写しとみなす規則を足す、M2 の題材を変える）。

## 次の WP への申し送り

- **WP37（統合）**
  - ポートと手順は `mncore/rtl/mv/README.md`。順序制御の見本は `mncore/fpga/mv_test/mvt_core.v`（m 語の start / acc、wait の判定、L2BM 命令の前の `busy` 待ち、RUN の終わりの `busy` 待ち、ホストの空間の振り分け）。
    - m 語: `ready` を待って `start`（`mw` = 命令メモリの [81:0]）、`acc` を待つ。`acc_st` 1 → E_RANGE（info = エントリ番号）、2 → E_UNSUPPORTED（info = 0x80 | `acc_field`）。`valid` = 0 は読み飛ばす。m 語では `mn_l2bm.skip` を出さない。
    - wait（j 語の `wd` ≠ 0、ll = 00 の語も）: `busy` = 0 を待って `wt_cnt` を見る。1 なら `wt_take` を出して語を実行、0 なら停止理由 WAIT（提案 4）、2 なら E_UNSUPPORTED 91。
    - L2BM 命令のある j 語（`l2bmdars` / `l2bmdarw` も）: `busy` = 0 を待ってから `mn_l2bm` を start する。PE と L1BM の語は MV の転送中に実行してよい（共有する状態がない）。
    - RUN の終わり（停止も）: `busy` = 0 を待ってから `core_busy` を下ろす。
  - `mn_l2bm` のポート B は `mn_mv` だけにつなぐ（ホストの空間 7 は `mn_mv` の `hw_*` / `hr_*` 経由）。空間 8 / 9 も `mn_mv`。DAR は `dar_*` を直結。

  - SDRAM: `sdr_bus64` を `ASYNC` = 1 で、コアは 27 MHz、SDRAM は rPLL の 99 MHz（IDIV 2 / FBDIV 10 / ODIV 8、PSDA 8、CL2、`cfg_rdx` = 1）。`mvt_top.v` の形がそのまま使える。`rst`（コア側）と `srst`（SDRAM 側）は同時に入れる。RESET コマンドではコアだけをリセットし、SDRAM（PDM / DRAM の中身）は残す。nextpnr は `--freq 99`（2 つのクロックに同じ目標。コア側は 27 MHz あればよい）で、`sclk` の Fmax を確かめること。
