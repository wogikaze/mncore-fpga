### 時分割の動作（`mn_mab`）

物理的なデータパス（デコーダ、整数 ALU、FP ALU、MAU、収集、`mn_pe_lsu`）は 1 組で、1 語を PE 0〜3 の順に実行する。

1. **検査だけのパス**（`prechk` = 語が LM0 / LM1 を読み書きする、または msl / msr / bfn / bfe）: PE 0〜3 のそれぞれで、`mn_pe_lsu` が範囲を検査し、何も書かない（`mn_pe_lsu` に ll = 00 の語を渡す）。msl / msr / bfn / bfe なら、4 サイクル分の ALU の入力 x を集めて受け渡しバッファに置く。どの PE かが範囲外なら、**どの PE も書く前に** E_RANGE で止まる。未対応の語は 4 PE の範囲検査の後で E_UNSUPPORTED。
   - LM のアドレスは PE ごとに違いうる（`$mb` / `$nb`、T 間接、`j<madpe>`）。GRF のアドレスは語だけで決まるので、LM を使わない語ではこのパスを省き、通常のパスの PE 0 の検査で代える。
2. **bfn / bfe**: サイクル c ごとに、4 PE の x を `x[128*p +: 128]`（契約 §6）に並べて `mn_fp_alu_bfn` に渡し、結果でバッファを置き換える（1 サイクル約 24 クロック）。
3. **通常のパス**: PE 0〜3 で語を実行する。msl / msr / bfn / bfe の ALU の結果はバッファから取る（msl: PE p に PE p−1 の x、msr: PE p+1 の x。どちらも {x の MSB 側の長語, 0}、フラグ 0。bfn / bfe: PE p の変換結果）。これらも `$aluf` に入る。

語の中の読み出しはすべて語の前の状態を見る: 各 PE は自分の状態だけを書き、他の PE の入力（msl / msr / bfn / bfe）は 1. で集めてある。

### PE ごとの状態

| 状態 | 置き場所 |
| --- | --- |
| LM0 / LM1 / GRF0 / GRF1 | `mn_pe_store`（NPE = 4）: {PE, 長語} の BSRAM。LM_AW = GRF_AW = 8 で 16 ブロック（契約 §3 の LM_DEPTH 256） |
| T、`$omr1..15`、`$mb` / `$nb` | `mn_mab_mem` のコンテキストストア（BSRAM 2）。`mn_pe_lsu` の中の 1 PE 分は作業用の写し（下記） |
| `$aluf` / `$mauf` | `mn_pe_core` の LUT RAM を {PE, サイクル} に（16 深さに収まるので RAM16SDP4 は増えない） |
| 固定値オペランド、MAU の PE 位置、`j<madpe>` の subpe | ステップの PE 番号から |

`mn_pe_lsu` は WP35 の担当で変えられないので、その中の T / マスク / ベースレジスタは「ステップの前に要る分だけ書き込み、ステップで書いた分を読み戻す」ことで PE ごとにした。

| 条件 | 動作 | クロック |
| --- | --- | ---: |
| いつも | `$mb` / `$nb` を書き込む | 2 |
| T を入力に使う、T 間接、マスク付きで T に書く | T（8 長語）を書き込む | 8 |
| マスクが `$imr<n>` | `$omr<n>` を書き込む | 1 |
| T に書いた | T を読み戻す | 16 |
| `$omr` に書いた | そのエントリを読み戻す | 2 |
| `$mb` / `$nb` に書いた | 両方を読み戻す | 4 |

マスクなしの T の書き込みは T の全体（4 サイクル × 2 長語）を、`$omr` の書き込みはエントリの 16bit 全部を書く（`mn_pe_lsu`）ので、その前の書き込みは要らない。

### 速さ

4 PE の回帰（260 本、j 語 2,715 語。nop 305 語を含む）で 594,093 クロック、**1 語あたり平均 219 クロック**（4 PE 分）。1 PE（今の RTL）は同じ語で 85,111 クロック、約 31 クロック / 語。nop を除く 1 PE ステップあたりでは 4 PE が約 62 クロック、1 PE が約 35 クロックで、差は検査だけのパスとコンテキストの書き込み・読み戻し。27 MHz で約 12 万語 / 秒（実機ではホストの UART の転送のほうがずっと長い）。

### 5. 公式エミュレータで確かめたこと

小さなプローブを公式の assemble3 と `gpfn3_package_main` で実行した（`gen_mab.py` の試験にも入れた）。

1. **msl / msr の結果は {隣の PE の x の MSB 側の長語, 0}**（`msl $llr0v $llr16v` で LSB 側の長語は 0。他の ALU 命令のように x の LSB 側の長語にはならない）。フラグは 0（`$omr` に 0）。結果は `$aluf` に入り、次の語の `msr $aluf` は隣の PE の `$aluf` を受け取る。Rust Sim（`machine.rs`）と同じ。
2. msl / msr は精度を付けられない（`hmsl` は assemble3 がエラー）。`msl $lr0vr`（`r`）は assemble3 は通すがエミュレータが InvalidArgument で止まる。RTL では `mn_alu_cls` が cls_bad（E_UNSUPPORTED rounda）にする。
3. `msl $ls16v $t` の直後に `$t` を読むと assemble3 がハザードとして拒否する（nop が要る）。bfn に `/1010` のマスクを付けると bfn/N と解釈されて拒否される。

## 未解決の点

1. **全部の演算器と bfn を 1 本のビットストリームに載せられない。** 4 PE の全部入り（FPALU = 1、MAU = 1、BFN = 1）は yosys で LUT 換算 21,731（104.8 %）、FPALU = 3 と MAU の組み合わせでも 78.8 %。実機には機能別のビットストリーム（WP-3x の方針）を使った（「実機」）。WP35 の削減が入れば組み合わせを増やせる。
2. **時分割のための追加の論理は LUT 換算で約 570（コアだけ）〜 650（トップ全体）、BSRAM 2（コンテキストストア）。** 大半は `mn_mab_mem` のコンテキストの書き込み・読み戻しとホストポートの切り替え（LUT 495 + ALU 42）。`mn_pe_lsu` が T / マスク / ベースレジスタに PE 番号を持てば（契約変更の要望 1）、コンテキストストアと書き込み・読み戻しが要らなくなり、1 PE ステップあたり 3〜35 クロックも減る。
3. **速さ**: 1 語あたり平均 219 クロック（4 PE 分、nop を含む）。検査だけのパスは LM を使う語と msl / msr / bfn / bfe だけに付けている。さらに速くするなら、`mn_pe_lsu` に「範囲の検査だけ」の開始を足す（READ / EXEC を回さずに済む）か、PE 番号付きの `mn_pe_lsu`（要望 1）。
4. **E_RANGE の PE 番号は STATUS に載らない。** `mn_mab` の `trap_pe` にあるが、`mn_core` のポートは `brd_host_if` に合わせて増やしていない（ポートを足すと `mn_top_1pe` の lint が PINMISSING で落ちるため）。info は語番号のまま。
5. **ホストからの T / OMR の部分書き込み**: コンテキストストアは 32bit の半分単位なので、T の MSB 側の長語を 16bit レーンだけ書く `WR_MEM`（マスク 0x03 など）は、その 32bit の半分ごと書く。OMR は `wmask[1:0]` のどちらかが 1 なら 16bit 全部を書く（`mn_pe_lsu` は 8bit 単位）。`mnhost` は T と OMR を長語単位（マスク 0xFF）でしか書かないので、回帰と実機には影響しない。
6. **LM は 4 PE で 256 長語**（LM_AW = 8、BSRAM 16。契約 §3 の LM_DEPTH）。512 長語にすると PE の記憶が 24 ブロックになり、L1BM / L2BM と合わせて 46 を超える。初期データが 256 長語を超える `10.gather-easy` の 2 本は実行できない。
7. **`mncore/sim/tb/mab/fixed/all.scr` は 1.7 MB**（21 本 × 4 PE × 535 か所の期待値と初期値）。WP20 の 627 KB より大きい。減らすなら、整数 / FP ALU の 2 本（4 PE の値が PE ごとに違う 174 本が回帰で通っている）を外すか、照合を長語の列の形（1 行に複数の値）にする。
8. 回帰の `pe1` の列は「1 MAB で比較できる」と同じ条件（L1BM / L2BM / MV / 行列なし、LM 256 長語以内、実行時の LM アドレスなし）なので、新しい列は作らず `pe1` を使った（`corpus.py` は WP02 の担当）。名前を `mab1` に変えるかは lead の判断。
9. 縮小トポロジの Rust Sim は使っていない。公式エミュレータの 4096 PE の結果を MAB 0 で切り出して比べた（契約 §3 (b)）。msl / msr の LSB 側の長語が 0 になる点は、Rust Sim（`machine.rs` の注記）と公式で一致している。食い違いは見つかっていない。

## 契約変更の要望

1. **`mn_pe_lsu`（WP35 の担当）に PE 番号を持たせてほしい**（WP30 では変えていない）。パラメータ `NPE` と入力 `pe[1:0]`（start で取る）を足し、
   - T（`mn_pe_treg` の LUT RAM）のアドレスを {pe, サイクル} にする（16 深さに収まるので RAM16SDP4 は増えない）。T 間接用の写し `tind` は 4 PE 分（FF 48 → 192）にするか、pe で選ぶ。
   - マスクレジスタ（16 エントリ × 4bit × 4 面）のアドレスを {pe, エントリ} に（RAM16SDP4 4 → 16）。
   - `$mb` / `$nb` を 4 組に。ホストポートにも PE 番号（`hp_pe`）。
   これで `mn_mab_mem` のコンテキストストア（BSRAM 2）と書き込み・読み戻し（LUT 約 500）が要らなくなり、1 PE ステップあたり最大 35 クロック速くなる。あわせて「範囲の検査だけ」の開始（READ / EXEC をしない）があれば、検査だけのパスも速くなる。WP30 の `mn_mab_mem` はそのとき `mn_pe_mem` と同じ薄い包みに戻せる。
2. **§6 の BSRAM の予算**: 1 MAB（4 PE、時分割）は 命令メモリ 12 + PE の記憶 16 + コンテキストストア 2 + host_if 3 = 33/46（今の構成、実測）。L1BM 4 + L2BM 8 を足すと 45/46。要望 1 が入ればコンテキストストアの 2 が空く。
3. **§3 の E_RANGE**: 「4 PE（時分割）では、どれかの PE が範囲外なら、どの PE も書く前に止まる。info は語番号」と書いてほしい（WP30 で実装し、PE 1 / 2 / 3 だけが範囲外になる試験で、どの PE も書いていないことを照合）。
4. **§7 / PROTOCOL.md**: デザイン ID 0x03 = `mn_top_mab`（トポロジ 1/1/1/1/4）。INFO のフラグ（オフセット 19）の bit 3..2 = FPALU（0〜3）、bit 4 = MAU、bit 5 = BFN（デザイン 0x03 から。機能別のビットストリームのどれが載っているかをホストが知るため。WP-3x「INFO で、載っているユニットを報告する」）。`mn_top_1pe`（0x02）は 0x01 のまま。`hwrun.py`（top_mab）はここからユニットを読む。
5. **§6 の MAB をまたぐ ALU 命令**: 「msl / msr の結果は {隣の PE の x の MSB 側の長語, 0}、フラグ 0 で、`$aluf` に入る（公式で確認、WP30）」を足してほしい。bfn / bfe は「PE p の値を `x[128*p +: 128]` に並べて受け渡す」のとおりにした。
6. **§6 の LUT の実測**: 4 PE（時分割）は 1 PE より LUT 換算で +570（コアだけ）〜 +648（トップ全体、FPALU = 0）、BSRAM +10（PE の記憶 +8、コンテキストストア +2）。`mn_fp_alu_bfn` の追加は LUT 換算 約 3,500（`mn_mab` の 4 PE 分の入力の組み立てを含む）。実機の 4 PE 構成 B（FPALU = 3、MAU = 0、BFN = 1）は LUT4 71 %、49.4 MHz。
