### 境界のポート（詳細は `mncore/rtl/l2bm/README.md`）

- 語の欄: `mn_dec_j` の `ll`、`l1bm_gwrite`、`l1bm_gadr`、`l2bm_*` 10 欄と、同じ語の L1BM の欄 5 つ（`l1bm_bmode`、`l1bm_lwrite`、`l1bm_me`、`l1bm_ladr`、`l1bm_wl`。L1BM への書き込みの順序に使う）。start から done まで保つ。
- 欄からの組み合わせ出力: `act`（= デコーダの `grp[MN_J_GRP_L2BM]`）、`chk_trap`（E_RANGE）、`chk_unsup` / `chk_field`（E_UNSUPPORTED と欄番号）。
- 手順: `start`（`mn_l1bm` と同時）→ `mn_l2bm` が前半（L1BM の読み出し、L2BM への書き込み、DAR）を進めて `pre_done` → `mn_l1bm` の commit → done → `mn_l2bm` の `commit` → 後半（L1BM への書き込み）→ `done`。
  さらに、`mn_l2bm` を start しない j 語（ll = 00 も）ごとに `skip` を 1 クロック出す（m 語では出さない）。
- L1BM マスタポート `lb_*`: 契約 §6 のバスに L1B 番号 `lb_req_l1b` を足したもの。L1B ごとの `mn_l1bm` のポート B につなぐ。
- ポート B `b_*`: L2BM を契約 §6 のバスで（MV 側の WP33、ホストの空間 7）。ユニットがメモリのポートを使うクロックは待たせる。
- DAR の読み出しポート `dar_re` / `dar_raddr` → `dar_rdata`（1 クロック後）: MV の間接参照（WP33）用。

### 機械語の符号化（assemble3 で確かめたもの）

既定値は `l2bm_dmode` = 11、ほかの欄は 0。`gadr` は L1BM アドレス ÷ 8、`ladr` は L2BM アドレス ÷ 16。

| 命令 | gwrite | lwrite | bdmode | l1adr / immode | dmode / opcode | ほか |
| --- | --- | --- | --- | --- | --- | --- |
| `l2bmb[@set] $lc $lb` | 1 | 0 | 01 | 集合（省略時 000 / 111） | 11 / 0000 | |
| `l2bmb2[@set]` | 1 | 0 | 10 | 集合 | 11 / 0000 | |
| `l2bmd[@set] $lc $lb`（分配） | 1 | 0 | 00 | 集合 | 11 / 0000 | |
| `l2bm@n $lb $lc` | 0 | 1 | 01 | n / 000 | 00 / 1100（bor） | |
| `l2bmr<op>[@set]` | 0 | 1 | 01 | 集合 | 精度 / 演算 | |
| `l2bmr2<op>` | 0 | 1 | 10 | 000 / 111 | 精度 / 演算 | 集合は書けない |
| `l2bmd $lb $lc`（結合） | 0 | 1 | 00 | 000 / 111 | 00 / 1100 | 集合は書けない |
| `l2bmi@set $lb<a0> $lb<a1>` | 1 | 1 | 00 | 集合（immode = 111 は拒否） | 11 / 0000 | 読み出し元 a0 は `gadr`（÷ 8）、書き込み先 a1 は `ladr`（÷ 16） |

| `l2bmdarw` | | | | | | `darwrite` = 1（ほかの L2BM 命令と同じ語に置ける） |

### 公式エミュレータで確かめた意味（要点）

プローブは 143 本（`probe.py` の 12 セット。全 8 L1B の L1BM と L2BM を比べる。アセンブラが作らない組み合わせは、アセンブル後に欄を手で変えた語）。
最終的に、試験の 105 本すべてで参照モデルが公式と一致する（N_L1B = 1 の 79 本は、L1B 1〜7 を存在しない（0）とするモデルでも一致）。

1. **転送の表**（README の表）: L2BM → L1BM（bcast / bcast2 / distrib）は集合の L1B に書く。L1BM → L2BM の bdmode 01 / 10 は 8 入力 / 2 入力の縮約、00 は結合。gwrite = lwrite = 1 は `l2bmi`。
2. **`l2bm@n` は集合 {n} の bor の縮約**（opcode 1100、dmode 00）。opcode と集合を手で変えるとその縮約になる。**UNKNOWN.md A 節の `l2bm_opcode`（「縮約でない転送で 1100 が入る理由」）の答え**。結合、L2BM → L1BM、`l2bmi` は opcode / dmode を見ない（表外の値でもよい）。
3. **集合**は `l2bmr2` にも効き（外の L1B は単位元）、結合は immode = 111 のときだけ動く（ほかは何も書かない）。`l2bmi` で immode = 111 にすると結合になる。gwrite = 1 で bdmode = 11 は何もしない。
4. **単位元**: fadd / iadd / bor / or は 0、max と band は全ビット 1、min は符号以外の全ビット 1、and は 1（全演算・全精度で確認）。
5. **`l2bmi`**: 読み出し元の L1B は書かない（d ≠ s）。書き込み先 L1B d の読み出し元は (l1adr & ~immode) | (d & immode)。書き込み先は 8192 で折り返さない。
6. **アドレスの揃え**: 16 長語/サイクルで L1BM を読み書きする形は `gadr[0]` を使わない。8 長語/サイクルの形と L2BM 側はそのまま足す。
7. **DAR / DAR バッファ**: `l2bmdars` は L2BM の 256 長語を DAR バッファ 512 エントリに（上位 32bit が偶数番地）写し、DAR の書き込みアドレスを w、DAR バッファの読み出しアドレスを 0 にする。同じ語の `l2bmdarw` はその後に 4 エントリを写す。w は 1024、読み出しは 512 で折り返す。L2B 番号は bit 0 だけを使う。初期値は 0。
   **連続する j 語の `l2bmdars` は、DAR バッファを書き直すだけで、2 つのアドレスと L2B は連続の最初の語のものを保つ**（m 語は連続を切らず、ll = 00 の語を含むほかの j 語は切る）。SDM 3.6.7.10 に記述がない（「未解決の点」1 (a)）。
   DAR は `d get` で読めないので、DRAM に目印を置いて MV の間接参照（`mvp/n..nd1 $di<a>@0 $lc..@0.0`）で読んだチャンクから求めた。間接参照のアドレス `16 × (DAR[M + i] + …)` もこれで確かめた。
8. **語の中の順序**（L1BM の欄と L2BM の欄が同じ L1BM アドレスに触れる語。アセンブラは受け付ける）: **読み出しはすべて語の前の状態を見る。L1BM への書き込みはサイクルごとに PE → L1BM のサイクル c、L2BM → L1BM のサイクル c の順**（プローブ 28 本で確認）。
   RTL は L2BM 側の書き込みを `mn_l1bm` の commit の後に行い、PE 側が同じアドレスを後のサイクルで書くときだけ捨てる。
9. **公式が異常終了する組み合わせ**（RuntimeError）: lwrite = 1 で bdmode = 11、`l2bmi` で bdmode ≠ 00、縮約で dmode = 11 または表外の opcode。E_UNSUPPORTED にした。
10. noforward（ll = 11）は L2BM 命令に影響しない。ll = 00 の語は何もしない。

### 2. 命令列の試験（公式エミュレータを期待値にしたもの）

- 各試験: splitmix64 の初期データ（L2BM 2048 長語、L1BM 1024 長語 × 初期化する L1B、PE を使う試験は MAB 0 の 4 PE の GRF0 / GRF1 32 長語、LM0 / LM1 64 長語、T 8 長語）→ 命令列（1〜130 語）→ L2BM、8 L1B の L1BM、PE の `d get`。

### 3. 試験の感度（変異を入れた RTL）

RTL を 1 か所ずつわざと壊して試験を流し、すべて検出されることを確かめた（scratchpad の作業。リポジトリには入れていない）。

| 変異 | 失敗した試験 |
| --- | --- |
| 語の中の順序の規則を外す（L2BM 側が常に勝つ） | `w_*` 11 本（両方の N_L1B = 1 環境） |
| min の単位元を全ビット 1 にする | `red_f16 / f32 / f64`、`b8_red_f32 / f64` |
| 連続する `l2bmdars` の規則を外す | `dar_consec*` 4 本、`dar_odd`、`e_dars_l2b2` |
| `l2bmb2` の L1B 番号の使い方を変える | `b8_bcast2`、`b8_no_trap`（N_L1B = 8 だけで見える） |
| `gadr[0]` を使う | 縮約・`l2bm@`・`l2bmb` などの約 20 本 |

- BSRAM は L2BM 8（契約 §6 の予算どおり）+ DAR 2 + DAR バッファ 1。DAR の 3 個は予算にない（「契約変更の要望」2）。
- Fmax は測っていない（ユニット単体の配置配線はしていない）。逐次の制御で、最も深いのは 15bit のアドレスの加算と比較、64bit の 0 判定。

## 未解決の点

1. **Rust Sim（viz/core）と公式の食い違い**（契約 §1。RTL は公式に合わせた。Sim は直していない）。
   - (a) **連続する j 語の `l2bmdars`**: 公式は 2 語目以降で DAR の書き込みアドレス、DAR バッファの読み出しアドレス、L2B を変えない（DAR バッファは書き直す）。Rust の `blocks.rs` の `l2_dar` は毎回設定する。上の `x_dars_consec` で再現。
   - (b) **語の中の L1BM への書き込みの順序**: 公式はサイクルごとに PE → L1BM、L2BM → L1BM の順。Rust の `machine.rs` は命令式を .vsm に書いた順に処理し、後に書いた命令式が常に勝つ（機械語には順序がないので、公式の結果は書いた順によらない）。上の `x_ww_*` で再現。
   - 読み出しが語の前の状態を見ること、単位元、存在しない L1B の扱い、`l2bmi` で読み出し元を書かないことは、Rust と公式で一致する。
2. **BSRAM**: DAR と DAR バッファで 3 個増える（L2BM の予算 8 に対して 11）。M2 の hello_world は DAR を使わないので `DAR` = 0 にできる（「契約変更の要望」2）。
3. **N_L1B > 1 の `l2bmi`** は L1BM の読み出しを commit の後に行うので、同じ語の PE → L1BM の書き込みが読み出し元の範囲と重なる語を E_UNSUPPORTED にした（公式は書き込み前の値を読む）。N_L1B = 1 では起きない（L1B 0 を読むことがない）。
4. **実チップの大きさの構成**（AW = 15、L1AW = 13）では、末尾を越えるアクセスを E_RANGE にする（公式は折り返す）。縮小構成では起きない。
5. **MV の間接参照の `nd` の省略形**は確かめていない（viz の記録では公式は DRAM にアクセスしない）。`nd1` は公式と一致。WP33 の範囲。
6. **公式が異常終了する組み合わせ**（「意味」9.）と、`darsend` を `gwrite` / `lwrite` と同じ語に置くもの（アセンブラが作らない）は E_UNSUPPORTED にした。後者は公式では DAR を正しく書き、転送も何かをするらしいが、調べていない。
7. **`skip` の入力**は、`l2bmdars` の連続の規則のために増えた。WP37 が act でない j 語ごとに出さないと、`l2bmdars`・（L2BM 以外の j 語）・`l2bmdars` の並びで 2 つ目の `l2bmdars` が DAR のアドレスを設定しない（それ以外には影響しない）。

## 契約変更の要望

1. **§1 の食い違いの一覧**に、「未解決の点」1 の (a)（連続する `l2bmdars`）と (b)（語の中の L1BM への書き込みの順序）を加えたい。
2. **§6 の資源予算**: L2BM の BSRAM を「8（L2BM）+ 3（DAR 1024 × 32bit、DAR バッファ 512 × 32bit。`DAR` = 0 で 0）」としたい。M2 は `DAR` = 0 を既定にし、MV の間接参照を使うビットストリームだけ `DAR` = 1 にする案。
3. **§3 に DAR を加える**: DAR と DAR バッファはグループごと・実チップと同じ大きさ（縮小しない）。N_L2B = 1 では L2B 0 の `mn_l2bm` が持ち、`l2bmdars $lc..@.1` は存在しない L2B 1 を読むので 0。
4. **UNKNOWN.md / j_flat.yaml（WP01）の更新案**（`spec/isa/` は WP01 の担当なので変更していない）:
   - A 節 `l2bm_opcode`: 「縮約でない転送の 1100」は、`l2bm@n` が集合 {n} の bor の縮約であるため（opcode と集合が効く）。結合（`l2bmd $lb $lc`）、L2BM → L1BM、`l2bmi` は opcode / dmode を見ない。→ 確定した意味として C 節へ。
   - A 節 `l2bm_ladr` と `l2bmdars`: `l2bmdars` では `l2bm_l1adr`〜`l2bm_opcode` の 12bit が {DAR アドレス 10bit, L2B 番号 2bit（bit 0 だけ使う）}、`ladr` は L2BM アドレス ÷ 16。→ C 節へ。DAR の書き込みは 16 長語単位のアドレス（`mvp nd1` で確認）。
   - `l1bm_gadr` の desc に「16 長語/サイクルの形（`l2bmb`、`l2bmb2`、`l2bm@`、`l2bmr`、`l2bmr2`、`l2bmi` の読み出し元）は bit 0 を使わない」、`l2bm_ladr` の desc に「`l2bmi` では書き込み先の L1BM アドレス ÷ 16」を加えたい。
   - `l2bm_opcode` の enum は縮約（lwrite = 1、gwrite = 0、bdmode 01 / 10）にだけ当てはまる（`enum_when`）。`l2bm_bdmode` = 11 は gwrite = 1 では何もしない。
     今のデコーダ（WP10）の `unsup_vec[83]` / `[88]` は語の種類によらず立つので、`l2bmdars $lc..@.0 $dar1`（opcode = 0100）などの正しい語を E_UNSUPPORTED にしてしまう。yaml を直してデコーダを作り直すか、WP37 が L2BM の欄（80〜90）にはデコーダの判定を使わないこと（`mn_l2bm` の `chk_unsup` が公式に合わせてある）。
   - C 節に「連続する j 語の `l2bmdars` の規則」と「語の中の L1BM への書き込みの順序」を加えたい。
5. **§3 の E_RANGE**: `l2bmi` の書き込み先（16 × `ladr`）は 8192 で折り返さない（公式）ことを、「アドレスは折り返しの後で比べる」の例外として書き添えたい。
