### M2 のコア（`mn_core`、N_PE = 4、M2 = 1）

```
brd_host_if ── mn_core ─┬─ 命令メモリ（448 bit × 512、BSRAM 12）、順序制御
                        ├─ mn_mab（4 PE の時分割、WP30）── mn_pe_core（BM = 1）── mn_mab_mem（mn_pe_lsu / mn_pe_store NPE = 4）
                        ├─ mn_l1bm（N_MAB = 1、RRN 2、L1BM 1024 長語、$lbi、$lbf）
                        ├─ mn_l2bm（N_L1B = 1、RRN 2、DAR 0、L2BM 2048 長語。L1BM へは mn_l1bm のポート B）
                        └─ mn_mv（m 語、タグ、PDM / DRAM）── sd_* ── sdr_bus64（ボードのトップ、ASYNC）── SDRAM
```

**M2 の 1 語**（j 語。WP31〜33 の申し送りの順序。`mn_core.v` の冒頭にも書いた）:

| 段 | 状態 | すること |
| --- | --- | --- |
| 1 | `S_DEC` → `S_WT` | wd ≠ 0 なら、MV が終わる（`busy` = 0）のを待ってタグの完了数を見る。1 なら `wt_take` で取って進む、0 なら**停止理由 4 WAIT**（info = タグ。公式はここで止まったまま）、2 以上なら E_UNSUPPORTED `wd`（公式は異常終了） |
| 2 | `S_JX` | ll = 00 なら `mn_l2bm` に `skip` を出して次へ。ユニットの範囲の検査（`chk_trap`）が失敗なら E_RANGE（何も実行しない）。L2BM の部分がある語は MV が動いていないことを待つ（公式は MV を発行時に終える）。ユニットが空くのを待って `mn_mab` を始める |
| 3 | `S_PE` | ユニットの部分がある語は必ず検査だけのパス（4 PE の E_RANGE と、ユニットの `chk_unsup` を含む E_UNSUPPORTED）を通る。通れば `mn_mab` が `ugo` を 1 クロック出し、`mn_core` は `mn_l1bm` / `mn_l2bm` を start する。通常のパスでは、PE ごとに PE → L1BM のオペランドを渡し（`ls_*`）、L1BM → PE の値を受け（`lr_*`。isel 10 の書き込み先と `$lbf`）、`$lbf` を読み書きする（`lb_*`） |
| 4 | `S_L2P` → `S_L1C` → `S_L2C` | `mn_l2bm` の前半（L1BM の読み出し、L2BM の書き込み）の終わり（`pre_done`）→ `mn_l1bm` の commit（L1BM / `$lbi` の書き込み）→ `mn_l2bm` の commit（L1BM への書き込み）。公式の語の中の順序（各 README） |
| 5 | | ユニットの部分のない j 語でも、実行したら `mn_l2bm` に `skip` を出す（DAR の連続の判定、WP32） |

- **m 語**: `mn_mv` の `ready` を待って start し、検査の結果（`acc`）を待つ。0 なら次へ（転送は裏で続く）、1 は E_RANGE（info = エントリ番号）、2 は E_UNSUPPORTED（info = 0x80 | 欄）。valid = 0 は読み飛ばす。
- PE / L1BM だけの語は MV の転送中も実行する。RUN の終わり（停止も）は MV の転送が終わってから `core_busy` を下ろす（PROTOCOL.md の「発行したものがすべて終わる」）。
- **ホストの空間**（RUN 中でないとき）: 0x01〜0x05 / 0x10 / 0x11 は PE p0〜p3（`mn_pe_lsu` のホストの口）、**0x06 L1BM**（loc = L1B n0c0b0、`mn_l1bm` のポート B。RUN 中は `mn_l2bm` が使う）、**0x07 L2BM / 0x08 PDM / 0x09 DRAM**（loc 0、`mn_mv` の `hw_*` / `hr_*`）。ほかの場所は `mw_err` / `mr_err`。
- **リセット**: ユニットはそれぞれ L1BM / `$lbi`、L2BM、MV のタグを消す。`SDCLR = 1`（ボード）では、`mn_core` が DRAM（2^19 長語）と PDM（2^17 長語）の範囲の SDRAM に 0 を書く。その間、空間 8 / 9 のホストの読み書きと RUN は待つ。SDRAM の制御器はコアのリセットでは初期化しない（システムのリセットだけ）。

### 複製規則 `REPLICA`（作業 4）

`mn_l1bm` / `mn_l2bm` / `mn_core` / `mn_top_m2` のパラメータ（既定 0 = ゼロ規則）。1 のとき、存在しない MAB m を MAB m mod N_MAB の、存在しない L1B b を L1B b mod N_L1B の複製とみなす（WP-3x）。

- L1BM: l1bmm@m / l1bmm4@i / l1bmd の結合と l1bmr / l1bmr4 の縮約の入力は複製元の値。`$lbi` の持たない位置は複製元の位置として読む。存在しない MAB への書き込みは捨てる。
- L2BM: 縮約（l2bmr、l2bmr2、l2bm@）の入力、結合のスロット、`l2bmi` の読み出し元は複製元の L1B の L1BM。範囲の検査も複製元のアクセスとして行う。
- RRN = 2 の縮約は、n 個の同じ値の縮約を 1 つの値から作る: fadd は指数に log2 n を足す（あふれは無限大、指数 0 は 0、出力の丸めは 1 値と同じ）、iadd は n 倍（レーンで折り返す）、max / min / band / bor はそのまま、and / or は 0 でなければ 1。
- 公式との照合: `directed/replica_forms.vsm`（L1BM の l1bmm@3、l1bmm4@1、l1bmr4ffadd、l1bmrffadd、L2BM の l2bm@3、l2bmrffadd、l2bmr2ffadd、l2bmd。4 PE に別々の値、L1BM に乱数）で、REPLICA = 1 の RTL は公式の 1,536 長語すべてと一致（ゼロ規則の RTL は 768 長語が公式と違い、縮小 Rust とは全部一致）。

## 判断と理由

1. **ボードの M2 には MAU を入れられなかった（指示書の最低構成と違う）。** MAU を含む M2（FPALU 0、MAU 1、BFN 0、MAT 0）は yosys の LUT 換算で 19,825（**95.6 %**）で、上限 75 %（15,552）を約 4,300 超える。MAU なし（**M2a**: FPALU 0、MAU 0、BFN 0、MAT 0）は 14,605（70.4 %、LED の方針の版。配置配線で LUT4 72 %）。WP30 の時点で 1 MAB の構成 A（MAU あり、L1BM / L2BM / MV なし）がすでに LUT4 75 % で、L1BM + L2BM + MV（LUT 換算 約 4,000）を足す余地はない。WP-3x の「機能別のビットストリーム」に従い、M2a（整数 ALU + L1BM + L2BM + MV）を作り、MAU を使う hello_world は **2 本のビットストリームで、ホストが状態を引き継いで**実行した（`hello_hw.py`: 語 0〜3 を MAU のある `mn_top_mab` A で実行し、PE p0〜p3 の GRF0 / GRF1 / LM0 / LM1 / T / OMR 1〜15 / BAR を読み出し、M2a に書き戻して語 4〜8 を実行する）。引き継ぎが正しいのは、後半の語がフォワーディングレジスタ（`$aluf` `$mauf` `$lbf` `$mreadf`）、`$lbi`、MV のタグ、DAR を読まないときだけなので、スクリプトがそれを語の欄で確かめる。ゼロ規則では縮小 Rust と、複製規則では公式と、プローブの全長語が一致した。1 本に載せるには面積の作業が要る（申し送り）。なお、参照リポジトリのコンパイラが出した MAU を使わない hello_world（`mncompile/.../21.hello-world/kernel.vsm`）は M2a 1 本で動く（実機の項）。
2. **`sdr_bus64` は `mn_core` の外（ボードのトップ）に置いた。** `mn_core` は単一クロックのまま（契約 §6 の内部のメモリバス `sd_*` をポートに出す）にし、2 つのクロック（コア 27 MHz、SDRAM 54 MHz。判断と理由 15）と PLL はボードのトップに置いた（WP33 の `mvt_top` と同じ形）。テストベンチは同じバスに振る舞いモデル（`tb_sdmem`。受け付けと応答の遅れは乱数）をつなぐ。
3. **RESET で DRAM / PDM を 0 にする（`SDCLR`、ボードでは 1）。** WP33 の申し送りは「RESET はコアだけ、SDRAM の中身は残す」だったが、公式はプログラムごとに DRAM / PDM が 0 から始まり、`mnhost.py run` / `hwrun.py` は 1 本ごとに RESET するので、前の本の DRAM が残ると、初期化しない DRAM を読む本と DRAM のプローブが公式と合わない。RESET の後に `r` 行（WR_MEM の空間 9）で DRAM を置く手順は変わらない。消去は DRAM 2^19 + PDM 2^17 長語で、その間はホストの空間 8 / 9 と RUN が待つ。`mn_core` の既定は 0（テストベンチは `C` で `tb_sdmem` を消す。`m2_sdclr` は `SDCLR = 1` を小さな容量で確かめる）。
4. **L1BM の isel = 111 は `$lbf`（WP31 の誤りを直した）。** M2 の回帰の 14.exp 系の本で、`l1bmm@0 $lbf $lb64` の形の語が公式と合わなかった。公式で `l1bmp $lb0 $lr8` → `l1bmm@0 $lbf $lb64` を実行すると L1BM に `$lbf` が書かれる（`directed/lbf_src.vsm`）。WP31 は「isel = 111 なら値は 0」としていたが、単体試験では `$lbf` が 0 の場面しかなかった。`mn_l1bm` は PE → L1BM の値をコアから受けるだけなので、`use_src` を lwrite = 1 の語すべてにし、`mn_pe_core` は isel 111 で `$lbf`（収集の源 13）を渡す。`tb_l1bm_env` / `tb_l2bm_env` も同じに直し、L1BM / L2BM の単体試験は通る。
5. **デコーダの L1BM / L2BM の欄（68〜90）の E_UNSUPPORTED は、ユニットがある構成（`BM = 1`）では使わない。** 縮約の演算などの可否は語の組み合わせで決まり（WP32: L2BM の opcode は縮約のときだけ意味がある）、ユニットの `chk_unsup` がそれを判定する。yaml の修正（`enum_when`、作業 3）はデコーダ自身の出力を正しくするためで、ユニットのない 1 PE / 4 PE の構成では、L1BM / L2BM の語はどちらにしても E_UNSUPPORTED（`l1bm_bmode` / `l2bm_lwrite`）になる。
6. **m 語の判定はデコーダから外した**（`m.yaml` に「何もしない」値を足し、`mv_unsup_vec` = 0）。判定は `mn_mv` の `acc_st` / `acc_field`（WP33）。m.yaml に判定が 1 つもなくなったので、`gen_dec.py` の `err_field` の連鎖と `gen_vectors.py` の網羅の条件（m 語の err_kind は {0} だけ）を直した（WP10 の試験は通る）。
7. **停止理由 4 WAIT**（WP33 の提案）を `mn_core`、`tb_core`、`run.py`、`mnhost.py` で扱う。公式はそこで止まったまま終わり、最後に `d get` を出すので、`mnhost.py` は WAIT の後の RUN と d set をやめ、d get は読む（回帰も同じ）。
8. **デザイン ID 0x04 と INFO のフラグ bit 7 = REPLICA** を提案として使った（契約変更の要望）。bit 2〜6 は `mn_top_mab`（0x03）と同じ。
9. **tb_core の DRAM / PDM の裏口**: M2 のシミュレーションは、プローブの DRAM 8,192 長語などのホストの読み書きで遅かった（約 1,000 クロック / 秒）。番地 64 以上の DRAM / PDM の `W` / `R` は `tb_sdmem` の配列を直接読み書きし、先頭の 64 長語はホストの口（`mn_mv`）を通す（WP33 の `tb_mv` と同じ考え）。hello_world の回帰の 1 本が 22 秒になった。
10. **`mn_mab_mem` は `mn_pe_lsu` / `mn_pe_store` の NPE = 4 だけにした。** 状態（T、マスク、`$mb` / `$nb`）は PE ごとに `mn_pe_lsu` の中にあり（WP35）、`subpe` に PE の番号を渡すだけでよい。WP30 のコンテキストの保存・復元（T の読み戻しの待ちなど）がなくなり、BSRAM 2 と 1 語あたりのクロック数が減った（下の表）。
11. **L1BM / L2BM の RRN = 2（N_MAB = 1 / N_L1B = 1 専用の小さな縮約）に複製規則を入れた。** n 個の同じ値の縮約を、1 つの値から直接作る（fadd は指数に log2 n を足す。2 のべき個の同じ値の和は正確なので丸めは 1 回）。RRN = 1（任意の N）では、存在しない MAB / L1B の値として複製元を読む形にした（単体の lint と RTL の構成だけ。M2 の構成は RRN = 2）。
12. **M2 の回帰の対象**: pe1 から L1BM / L2BM / MV の群だけの理由（と、その LM の番地の理由）で外された 247 本（行列の群を含む本は `--matrix`）。LM が 256 長語を超える本は E_RANGE で止まる（4 PE の LM の深さ。縮小 Rust も同じ語で範囲外にする）。
13. **縮小トポロジの Rust Sim は submodule のまま使った**（`topo_rs` は viz/core を path 依存で使う小さなバイナリ。viz/core は変えていない）。
14. `pemem`（WP35 の `mn_pe_mem` / `mn_pe_lsu` の単体）は、試験の生成に WSL の `gen_tests.py` が要り、回していない。`mn_pe_lsu` / `mn_pe_mem` / `mn_pe_store` は変えていない。
15. **ボードの SDRAM のクロックを 54 MHz にした**（WP05 の推奨は 99 MHz）。M2a を 99 MHz で配置配線すると、SDRAM の制御器の中の経路が 88.67 MHz で目標に届かなかった（資源の表）。種を変えて試す（1 回 約 50 分、届く保証はない）より、WP05 が実機で確かめた設定（54 MHz、CL2、p = 11、`cfg_rdx` = 1、8 MiB 全域試験 100 回で誤り 0）に下げるほうが確実と判断した。`mn_top_m2` のパラメータ（`SDR_HZ`、`IDIV_SEL` / `FBDIV_SEL` / `ODIV_SEL`、`PSDA`、`CL`、`RDX`）だけで変えられ、RTL は変えていない。コアは 27 MHz で、MV の転送の律速はコア側なので、速さへの影響は小さい。99 MHz のまま（タイミング違反）のビットストリームでも実機の回帰を 1 回回した（実機の項）。
16. **LED（lead の指示、ユーザーの要望）**: main の `0e55633`（LED 0 だけを最小の明るさで常時点灯）を取り込み、`mn_top_m2` も同じ LED の節にした（活動表示の伸長カウンタを外した分、LUT4 が約 250 減り、M2a-R が上限の 75 % に収まった）。それまでの実機の回帰は前の LED のビットストリーム（コアは同じ）で行い、LED の方針の M2a / M2a-R を作り直して最後に確かめ、M2a を SRAM に書いた状態でボードを残した（実機の項）。

## 未解決の点

1. **MAU を含む M2 はボードに載らない**（判断と理由 1）。M2a（MAU なし）との差は LUT 換算 約 5,000（`mn_fp_fma` 2,471、`mn_mau_vec` 1,062、`mn_fp_mul53` 453 など）で、上限 75 % まで約 4,300 を削る必要がある。M2 の大きな部分は `mn_pe_lsu` 2,611、`mn_l1bm` 1,765、`mn_pe_core` 1,430、`brd_host_if` 1,372、`mn_alu_int` 1,366、`mn_mv` 1,132、`mn_l2bm` 1,131、`mn_core` 1,003（階層を残した合成、MAU ありの構成で）。
2. **MAU を使う hello_world（`problems/challenge/21.hello-world`）は 1 本のビットストリームでは動かない**（2 本と状態の引き継ぎ。引き継げるのはホストが読み書きできる状態だけ）。MAU を使わない版（`mncompile/.../21.hello-world/kernel.vsm`）は M2a 1 本で動く。
3. **複製規則のビットストリーム M2a-R は上限ぎりぎり**: LUT4 74.7 %（上限 75 %）、コアの Fmax 27.78 MHz（余裕 3 %）。LED の伸長カウンタを外す前の版は 76 %、26.84 MHz で超えていた。RTL を少し足すだけで超えるので、余裕を作るなら複製の縮約（`mn_l1bm` の `rrn_rep`、`mn_l2bm` の `redrw`、LUT 換算 +538）を小さくするか、`rrn_rep` の前後にレジスタを入れる（今は命令メモリから書き込みの値まで、桁上げ鎖 3 本を含む 1 クロックの経路）。
4. **SDRAM を WP05 の推奨の 99 MHz で動かしていない**（判断と理由 15）。99 MHz を目標に配置配線した M2a（前の LED）では `sdr_ctrl`（WP05）の行の一致の判定が 88.7 MHz で届かず、54 MHz にした。LED の方針の版（54 MHz が目標）の見積もりは 100 MHz だったが、配置次第で、99 MHz では確かめていない。
5. **LM の深さ 256 長語**（4 PE の BSRAM の上限、契約 `LM_DEPTH`）: M2 の 247 本のうち 26 本が LM の番地 256 以上で E_RANGE（縮小 Rust も同じ語で範囲外）。`problems/challenge/20.fizzbuzz/answer.vsm` もこれ（語 9、LM0 の番地 2178 語）。L1BM 1024 / L2BM 2048 / DRAM 2^19 / PDM 2^17 長語を超える本（MV の nw が大きい本、`l1bmm` の ladr 1024 など）も E_RANGE。
6. `problems/challenge/20.fizzbuzz/lpha100.vsm` の E_RANGE（語 98、`mvd/n4096i01 $lc0 $p0@0` が L2BM の 0〜4095 を読む）は、縮小 Rust がこの .vsm を読めない（parse_error）ので Rust と突き合わせていない。L2BM の深さ（2048）を超えるので、規則どおりの E_RANGE と判断した。
7. 縮小トポロジの Rust Sim と公式の既知の食い違い（契約 §1）に当たる本は、M2 の回帰にはなかった（「pass b (rust differs)」0 本）。WP31 の L1BM の食い違い（`fmaxr` / `fminr` の丸めなど）は、コーパスの本では差になって表れない。
8. ボードの M2a は FP ALU と MAU を持たないので、M2 の回帰のうち 82 本が実機で E_UNSUPPORTED になる（RTL の同じ構成と同じ結果）。
9. `pemem` の単体試験は回していない（判断と理由 14）。

## 契約変更の要望

1. **§3 に複製規則を書いてほしい**（WP-3x の lead の判断の実装）: 「`REPLICA` = 1 では、存在しない MAB m は MAB m mod N_MAB の、存在しない L1B b は L1B b mod N_L1B の複製。縮約・結合・`l2bmi` の入力と `$lbi` の読み出しは複製元の値、書き込みは捨てる。n 個の同じ値の fadd は指数に log2 n を足す（正確で、丸めは 1 回）、iadd は n 倍、max / min / band / bor はそのまま、and / or は 0 でなければ 1」。あわせて「データの移動が閉じる本はどちらの規則でも公式と一致する」（M2 の回帰で 100/100）。

8. 縮小トポロジの正解（§3 (a)）を作る道具として `mncore/sim/regress/topo_rs`（`topo_dump`）を書いてほしい（WP06 の `sim_run --topology` と同じ `Sim::with_topology` を ndmp で出す）。

## 次の WP への申し送り

- **WP34（仮想 PE、Wave 5）**
  - `mn_mab_mem` は `mn_pe_lsu` / `mn_pe_store` の NPE = 4 だけになった。PE の状態（GRF / LM は `mn_pe_store` の BSRAM、T / マスク / `$mb` / `$nb` は `mn_pe_lsu` のレジスタ）は `subpe` で選ぶ。64 PE に広げるなら、`mn_pe_store` の BSRAM を SDRAM の窓に替え、`mn_pe_lsu` の PE ごとのレジスタ（NPE に比例）も SDRAM か BSRAM に移す必要がある。
  - SDRAM のバス（`sd_*`）の主は今 `mn_core` の中の `mn_mv` と、リセット後の消去（`SDCLR`）。仮想 PE を足すなら `mn_core` の中で調停する（`mn_mv` は MV の転送中とホストの読み書きのときだけ要求を出す）。SDRAM の 0xA0000〜0xFFFFF（3 MiB）は空き（PDM 0x80000〜、DRAM 0x00000〜）。ボードの SDRAM は 54 MHz（帯域は 99 MHz の約半分）。
  - LM の深さ 256 で E_RANGE になる本（FizzBuzz の解答を含む 26 本）は、LM を広げると比べられる。
  - 1 語の順序（`mn_core` の `S_JX` → `S_PE` → `S_L2P` → `S_L1C` → `S_L2C`）と、PE ごとの L1BM のポート（`ls_*` / `lr_*` / `lb_*`。PE は `cur_pe`）は、`mn_l1bm` の N_MAB を増やせばそのまま広げられる形（`mn_l1bm` は PE 番号 (m, p) でオペランドを受ける）。
- **WP40（統合と適合試験）**
  - `run.py --m2` が縮小トポロジの Rust Sim（`topo_rs`）と比べて分類する（pass b / pass c / E_RANGE as rust）。トポロジを広げるなら `topo_dump --topology` の引数と `run.py` の `TOPO_M2`、プローブ（PE の場所、L1BM / L2BM / DRAM の場所）を変える。
  - 実機は `fpga/top_m2/hwrun.py`（`--all`、RTL の表 `results<tag>.tsv` と照合）。機能別のビットストリームは INFO のフラグで RTL の表を選ぶ。
  - 縮小 Rust がパースできない本がある（`20.fizzbuzz/lpha100.vsm`、parse_error）。
  - `mnhost.py` は 2^17 行の `r` 行（2 MiB）の本も 1 本 15 秒ほどで流せる（行をまとめた）。
- **WP41（デモ）**
  - FizzBuzz: `mncompile/benchmarks/results/20.fizzbuzz/kernel.vsm` は M2 で縮小 Rust と一致（pass c。公式とは縮約の分だけ違う）、`problems/challenge/23.fizzbuzz-pe` は公式と一致（pass b）。`problems/challenge/20.fizzbuzz/answer.vsm` は LM の深さで E_RANGE（WP34 か LM の拡張が要る）。どれも FP ALU / MAU を使うので、今のボードの M2a では E_UNSUPPORTED。デモには面積の作業（MAU と M2 を 1 本に）か、機能別のビットストリームの切り替え（`hello_hw.py` の形）が要る。
  - "Hello, world!" は、MAU を使わない `mncompile/.../21.hello-world/kernel.vsm` なら M2a 1 本で DRAM n0 の 0〜1 番地に出る（ゼロ規則でも）。公式の問題の hello_world は複製規則と 2 本のビットストリームで出る。
- **WP42（公開）**: 判断と理由 1、3、4、15 と、契約変更の要望 2、3、6。
- **面積（WP35 の続き、または新しい WP）**: MAU を M2 に載せるには LUT 換算 約 4,300 を削る。候補は `mn_pe_lsu`（2,611。4 PE 分の T / マスクのレジスタと 128 ビットの選択）、`brd_host_if`（1,372）、`mn_l1bm`（1,765。RRN 2 の縮約の 4 レーン分）、`mn_fp_fma`（MAU の 2,471）。複製規則（+538）を載せる余裕も要る。M2a（LED の方針）は LUT4 72 %、MAU なしでも残りは約 600 LUT4 しかない。
- **WP05（SDRAM）**: `sdr_ctrl` の行の一致の判定（`h_addr` → `h_hit` → `h_stale` → `n_la` → `n_hit`、LUT 10 段）を 1 段レジスタで切れば、埋まったデバイスでも 99 MHz に届く見込み。
