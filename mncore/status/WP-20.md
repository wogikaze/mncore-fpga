### `mn_core` のインタフェース

ポートは `brd_host_if` のコア側（PROTOCOL.md §5）と同じ名前・幅で、そのままつなげる。`rst` には系のリセットと `core_rst` の OR を入れる。追加の出力は `core_trap[16:0]`（E_RANGE の詳細 {書き込み, メモリ 0 GRF0 / 1 GRF1 / 2 LM0 / 3 LM1, サイクル, 語アドレス}）だけ。

| パラメータ | 既定 | 意味 |
| --- | --- | --- |
| `IMEM_AW` | 9 | 命令メモリ 2^IMEM_AW エントリ（512 で BSRAM 12） |
| `IMEM_RD` | 0 | 1 で命令メモリを `RD_MEM`（空間 0）で読み戻せる（64bit × 7 の選択が増える） |
| `LM_AW` / `GRF_AW` | 9 / 8 | LM0/LM1 512 長語、GRF0/GRF1 256 長語（`mn_pe_mem`、BSRAM 8） |
| `CLEAR` | 1 | リセットの後で PE の状態を 0 にする（下記） |
| `FPALU` / `MAU` | 1 / 1 | 0 で FP ALU / MAU を外す（面積用。その命令は E_UNSUPPORTED） |
| `PE_LOC` | 0 | PE の位置（`n0c0b0m0p0`）。`$peid` などの固定値もここから作る |

- 命令メモリ（空間 0）: エントリ e のレーン k を長語 e*8+k に書く（PROTOCOL.md §3）。保存するのは {種類, jw} の 428bit で、レーン 0〜5 をレジスタにためてレーン 6 で 1 行を書く。**エントリは 7 レーンを順に書く**（`WR_IMEM` はそうする。マスクは 0xFF）。
- PE の空間（位置 `PE_LOC` だけ）: 1 LM0、2 LM1、3 GRF0、4 GRF1、5 T、0x10 OMR、0x11 BAR（`mn_pe_lsu` のホストポート）。それ以外の空間・位置は `mw_err` / `mr_err`。
- **リセット（`RESET` コマンド）で PE の状態を 0 にする**（`CLEAR = 1`）: GRF0/GRF1/LM0/LM1/T、OMR 1〜15、`$mb`/`$nb` に 1 クロック 1 長語で 0 を書く（1,562 クロック）。公式エミュレータの初期状態と同じになるので、ホストはプログラムごとに `RESET` するだけでよい。その間 `mw_ready` / `mr_ready` は 0（要求は待たされる）、`core_busy` は 0 のまま。その間に来た `RUN` はクリアの後で始める。フォワーディングレジスタは消さない（演算器が動く前に読むとエミュレータがエラーにする）。
- `RUN(start, count)`: エントリを順に実行する。
  - j 語 ll = 01 / 11: PE の 1 ステップ。ll = 00（nop）: 何もしない（wait 欄は下記）。ll = 10: `E_DECODE`、info 0。
  - m 語: MV がないので `E_UNSUPPORTED`、info 0x80（bit 7 が m 語の欄、欄 0 = valid）。valid = 0 の m 語は読み飛ばす。
  - 種類 00 / 11 のエントリ: `E_DECODE`、info 0x100 | 種類。命令メモリの外: `E_DECODE`、info 0x200。
  - 停止記録: `core_reason`（0 OK、1 E_RANGE、2 E_UNSUPPORTED、3 E_DECODE）、`core_pc`（止まったエントリ、OK なら次のエントリ）、`core_steps`（完了したエントリ数）、`core_info`（E_RANGE: エントリ番号、E_UNSUPPORTED: 欄番号 `MN_J_<欄>_IDX`、m 語は 0x80 + `MN_M_<欄>_IDX`）。
- wait（wd ≠ 0）: MV がないので待たずに通る（ll = 00 の語でも同じ）。公式エミュレータの挙動は下の「確かめたこと」2。

### `mn_pe_core` の動作

1 語を `mn_pe_lsu`（WP14）の手順（start → READ → EXEC）で実行する。

1. start: `mn_pe_lsu` が全アクセスの範囲を検査する。**この 1 クロックだけ imr を 0 にした語を渡す**ので、マスクで止まる書き込みも検査される（契約 §3。`mn_pe_lsu` 自体はマスクで 1 語も書かない書き込みを検査しない）。範囲外なら E_RANGE で、何も読み書きしない。
2. READ: rd_use（ALU の isela / iselb、MAU の a / b / c、L1BM の isel から求める。T は要求が要らない）のメモリだけを読む。
3. EXEC: サイクル c = 0〜3 について、
   - 収集: 使う入力（ALU の x / y、MAU の a / b / c）を、共有の 128bit のバス（$lr $ls $t $lm $ln、固定値、$mauf $aluf、$lbf / $mreadf = 0）から 1 クロックに 1 つずつポートレジスタに取る。
   - 発行: ALU（`mn_alu_cls` の cls_int なら `mn_alu_int`、cls_fp なら `mn_fp_alu`）と MAU にサイクル c を渡す。
   - 回収: 結果がそろったら `mn_pe_lsu` に渡し（res_valid / res_ready）、同時にサイクル c のフォワーディングレジスタを書く。
   収集と発行は回収より先に進む（ALU のパイプラインと、4 エントリの MAU の結果バッファが結果を持つ）。ステップ内の読み出しはすべてステップ前の値を見る（メモリは読み出しバッファ、T とフォワーディングレジスタのサイクル c は、サイクル c の回収のときにしか書かれない）。
- フォワーディングレジスタ: `$aluf` / `$mauf` は、その演算器が動いた直近のステップのサイクル c の出力をゼロフラッシュの後で持つ（`mn_pe_lsu` の zf_*）。ll = 11（noforward）と nop のステップでは変えない。`$mreadf` は 0（下の「確かめたこと」1）、`$lbf` は 0（L1BM がない）。
- 固定値オペランド: `$peid` = m*4+p、`$l1bid` = b、`$l2bid` = n*2+c、`$subpeid` = p、`$mabid` = m を ALU の精度のレーン幅（d/l 64、f/i/g 32、h/s 16）で複製、`$msb1` はレーンの MSB だけ 1（viz/core の read_alu_input と同じ）。
- 1 PE モードで扱えない語（範囲の検査の後で `E_UNSUPPORTED`。その語は実行しない: start の後は ll = 00 にした語を `mn_pe_lsu` に渡すので何も書かれない）: デコーダの未対応値（err_field）、`mn_alu_cls` の cls_bad（rounda / roundb / dmode）、msl / msr と bfn / bfe（MAB の他の PE が要る。欄 aluop）、行列の MAU（mmode）、?mwrite（mw）、L1BM（l1bm_bmode）と L2BM（l2bm_lwrite）の命令式、`FPALU = 0` / `MAU = 0` のときのその演算器の命令（aluop / enfma）。
- isel = 11（行列読み出し）の書き込みは 0 を書く（行列レジスタは書かれないので、公式でも 0）。

### 3. 公式エミュレータで確かめたこと（未解決として申し送られた点）

小さなプローブを公式 assemble3 と `gpfn3_package_main` で実行した（`gen_fixed.py` の試験にも入れた）。

1. **`$mreadf` は nop / noforward でない全ステップで更新される。** MAUC の欄はいつも行列レジスタの読み出しを表していて（`dmread $ly0 $nowrite` は nop と ll だけが違う、WP10）、?mread を書かない語（`zero $nowrite`、`ipassa`、`fvpassa`）でも `$ly0` の内容が `$mreadf` に入る。`dmwrite $lr0v $ly0` の後で `zero $nowrite; lpassa $mreadf $lls64v` とすると `3ff0000000000000` が読める（`$lx0` に書いた場合は 0）。**Rust Sim は ?mread のないステップで `$mreadf` を 0 にする**（machine.rs）ので、行列レジスタに書いたプログラムでは食い違う（契約 §1 の事態。どちらにも合わせていない）。1 PE モードでは行列レジスタに書けない（?mwrite は E_UNSUPPORTED）ので `$mreadf` は常に 0 で、公式と一致する。
2. **ll = 00 の語の wait は有効**（契約 §2 の暫定を確認）。MV を発行していないタグを待つと、`nop ; wait i01` でも `lpassa $lr0 $lr2 ; wait i01` でも、その語と後の語は実行されないまま終わる（d get はその時点の状態を出す。エミュレータは止まらずに終了コード 0）。先に `mvp/n64i01 ...` を発行しておけば、どちらも待った後で続きを実行する。RTL は MV がないので待たずに通る（WP20 の指示どおり）。この食い違いは、発行していないタグを待つ（壊れた）プログラムでだけ表れる。
3. **同じステップで T に書き、T 間接でアドレスを作る**と、読みも書きもステップ前の T を使う（`dvpassa $lr8v $t ; lpassa $lmt0v $ls0v` と `... ; lpassa $ls0v $lmt0v`）。RTL（`mn_pe_lsu` は start で LM のアドレスを決める）と同じ。
4. **同じステップで `$mb` / `$nb` に書き、LM0 / LM1 を使う語は assemble3 が拒否する**（`Instruction field conflict detected between lm0 and in_lm0`）。`$mb` の書き込みは LM0 のポートの欄を使うため。食い違いは起きない。
5. 単語の `d get`（`$m` `$r` など）は dtype（`getf` / `geth`）が要る。dtype なしの `d get $m1 2` はエミュレータが RuntimeError で止まる。
6. `$aluf` / `$mauf` を、その演算器のないステップの後で読むとエミュレータはエラーで止まる（`IALU is disabled`。Rust Sim と同じ）。RTL は前の値を持ったままにする（そのようなプログラムは公式で通らない）。
7. assemble3 が課す制約（RTL はこれに頼る）: 1 語で LM を読み書きするなら同じアドレス、1 つのメモリを 1 語で読めるのは 1 アドレスだけ（x と y を同じ GRF の別アドレスから読めない）、`dvfma` / `dvmul` は `u` か `d` が要る。
8. hello world（`problems/challenge/21.hello-world`）は L1BM・L2BM・MV を使い、出力が DRAM にある（`corpus.tsv` で pe1 = no）ので、1 PE のコアでは実行できない（L1BM の語で E_UNSUPPORTED になる。RTL では実行していない）。Welcome（`1.plus-one`）は回帰で一致している。

2. **`mn_pe_lsu` はマスクで止まる書き込みの範囲を検査しない**（契約 §3 は検査するとしている）。`mn_pe_core` は start の 1 クロックだけ imr = 0 の語を渡して検査させている。これは「`mn_pe_lsu` は start のクロックでだけ範囲を検査し、imr はその検査とマスクにしか使わない」という内部の作りに頼っている。`mn_pe_lsu` を変えるときはこの点を保つか、検査の方法を入力で選べるようにしてほしい（契約変更の要望 3）。未対応の語を実行しないために、start の後で ll = 00 にした語を渡すのも同じく内部の作り（ll = 00 なら EXEC で何も書かない）に頼っている。

4. **wait**: RTL は待たずに通る。公式は、発行していないタグを待つと止まったままになる（確かめたこと 2）。MV を実装するとき（WP33）は、完了したタグを覚えて、ll = 00 の語でも待つ必要がある。
5. **`$mreadf`**: 公式は毎ステップ行列レジスタを読む（確かめたこと 1）。Rust Sim と食い違う。1 PE モードでは影響しない。
6. 回帰の比較は、最後の状態（プローブ）とプログラム自身の `d get`（同じ場所は後勝ち）。同じ場所を途中で何度も `d get` するプログラムでは、途中の値は比べていない（WP02 の ndmp の決まり）。
7. 速さ: 回帰の平均で、実行する語 1 語あたり約 33 クロック（`mn_pe_lsu` の READ / EXEC の手順で 11 クロック以上、収集が入力 1 つにつき 1 クロック、ALU 4〜5 クロック、MAU 18〜21 クロック。h の MAU は 1 サイクル 4 レーンなのでさらに長い）。M1 には十分だが、速くするなら収集を 2 入力ずつにする、`mn_pe_lsu` の手順を短くする、などがある。
8. RESET はフォワーディングレジスタ（LUT RAM）を消さない。演算器が動く前に読むとエミュレータがエラーで止まるので、正しいプログラムには影響しない。
9. `fixed/all.scr` は 627 KB（27 本 × 初期値と 535 か所の期待値と命令）。大きすぎるなら初期値の数を減らす。
10. 回帰は iverilog（Verilator はモデルを作れない。上記）。

## 契約変更の要望

1. **§1 に Rust Sim と公式の食い違いを 1 件加えてほしい: `$mreadf`。** 公式は nop / noforward でない全ステップで、MAUC の欄が表す行列レジスタの読み出し（?mread を書かない語では `dmread $ly0`）の結果を `$mreadf` に入れる。Rust Sim（machine.rs）は ?mread のないステップで 0 にする。行列レジスタに書いたプログラムで差が出る（例は「確かめたこと」1）。Sim の修正は WP06 か後続で、行列は WP30 が扱う。
2. **§2 の「ll = 00 の語でも wd（wait）は有効とする（暫定。WP20 で確認）」から暫定を外してほしい。** 公式で確認した（ll = 00 でも 01 でも、待つタグの MV が完了するまで後の語を実行しない。発行していないタグなら最後まで実行しない）。
3. **§3 のマスクで止まる書き込みの検査について、`mn_pe_lsu` との関係を決めてほしい。** 今は `mn_pe_core` が start の 1 クロックだけ imr = 0 の語を渡して検査させている（未解決の点 2）。案 1: このやり方を `mn_pe_lsu` の約束として書く（「jw は start の後で ll と imr だけを変えてよい」）。案 2: `mn_pe_lsu` に入力を足す（WP14 の範囲）。あわせて、E_RANGE の info は「命令メモリのエントリ番号」（窓に分けて積むときは窓の中の番号で、ホストが窓の先頭を足して語番号にする）と書いてほしい。
4. **§7 / PROTOCOL.md に次を加えてほしい。**
   - `RESET` は PE の状態（GRF0/GRF1/LM0/LM1/T、OMR、`$mb`/`$nb`）を 0 にする（`mn_core` の `CLEAR = 1`、約 1,560 クロック。その間 `mw_ready` / `mr_ready` は 0）。PROTOCOL.md の「アーキテクチャ状態を消すのは RESET だけ」の具体化で、ホストはプログラムごとに `RESET` すればよい。
   - STATUS の info: E_UNSUPPORTED は欄番号（j 語は `MN_J_<欄>_IDX`、m 語は 0x80 + `MN_M_<欄>_IDX`）、E_DECODE は 0（ll = 10）、0x100 | 種類（エントリの種類が 00 / 11）、0x200（命令メモリの外）。
