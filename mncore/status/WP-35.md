### PE 番号つきの `mn_pe_lsu`（lead の追加依頼、WP30 の契約変更の要望 1）

作業の途中で main に WP30（4 PE の時分割）と WP31（L1BM）がマージされたので、`git merge main` で取り込んでから行った（WP30 / WP31 は担当のファイルを変えていないので衝突なし）。

- パラメータ `NPE`（1、2、4。既定 1）。**PE 番号は既存の入力 `subpe`**（MAB の中の PE 番号。`j<madpe>` が使うのと同じ番号）にした。
  - ステップの PE は start のクロックの `subpe` で、done まで保つ（内部のレジスタ `pe_q`。start の後で `subpe` が変わってよい）。
  - ステップの間は、ホストポートの T / OMR / BAR は PE `subpe` に行く（呼ぶ側はそのとき `subpe` にホストの PE を出す。LM / GRF のホストアクセスは従来どおりストアへ行き、ストアの PE は呼ぶ側が `mn_pe_store` の `pe` に渡す）。
  - **別の入力 `pe` を足さなかった理由**: ポートを足すと、それをつながない既存の実体（`mn_pe_mem`、WP30 の `mn_mab_mem`、どちらも担当の外）で verilator の PINMISSING になり、`core` / `mab` の lint が通らなくなる。`subpe` は WP30 の `mn_mab_mem` がすでにステップの PE（`pe_q`）をつないでいる入力で、意味も同じ。PE が 4 を超える設計（WP34 の仮想 PE）では別の入力が要るので、そのときは実体と一緒に足す。
- T: `mn_pe_treg` に `NPE` と入力 `pe` を足し、LUT RAM のアドレスを {PE, サイクル} に（16 深さに収まるので RAM16SDP4 は 32 のまま）。T 間接用の写し `tind` は 4 × NPE 個の 12 ビットのレジスタ（LUT RAM にすると 4 サイクルを同時に読むため 4 倍の RAM になるので、フリップフロップにした）。
- マスクレジスタ: {PE, エントリ}（NPE = 4 で RAM16SDP4 4 → 16）。`$mb` / `$nb`: NPE 組。リセットで全部 0。
- 面積（yosys、`mn_pe_lsu` 単体、RBS = 1）: NPE = 1 は LUT 換算 3,041（変わらない）、**NPE = 4 は 3,482（+441: LUT +345、FF +218、RAM16SDP4 +12）**。WP30 のコンテキストストア（LUT 495 + ALU 42、BSRAM 2、1 PE ステップあたり 3〜35 クロック）がいらなくなる。`mn_pe_lsu` のステップのクロック数は NPE によらない（`pemem` で 12.95 クロック / ステップ）。
- `mn_mab_mem` の側（NPE = 4 で使い、`subpe` に `q_idle ? hp_pe : pe_q` をつなぎ、T / OMR / BAR のホストアクセスを `mn_pe_lsu` に戻す）は WP37 の担当なので変えていない。

- 回帰 260 本の RTL シミュレーションのクロック数の合計は 85,750（WP20 の `results.tsv` は 79,876、+7.4 %）。増えたのは主にシフト命令（例: `mncompile/.../4.mul7` 243 → 443 クロック）。

## 未解決の点

1. **LUT4 70 % にはわずかに届かない見込み（最終 70.9 %、約 190 サイト超過）。** nextpnr の LUT4 は「yosys の LUT + nextpnr の ALU + 8 × RAM16SDP4」で、nextpnr の ALU は yosys の ALU より**桁上げ鎖 1 本あたり約 1.8 個**多い（最初の配置配線: 鎖 165 本で +292）。最終の RTL は鎖 153 本（うち 6 ビット以下が 61 本）で、この分が約 270 サイト。70 % まであと約 190 サイト。候補（見積もり）:
   - 短い鎖を論理式にする: `mn_alu_int` / `mn_fp_alu` の残りシフト量の 3 ビット減算（16 本）、`mn_pe_lsu` の READ の計数器（4 ビット × 8 本）、`brd_host_if` の `kk` / `lane` / `m56`、UART の `bitn` など。約 −60〜−100。
   - `mn_alu_int` のシフトを「その場の回転 + 保持マスク」から「左右のシフト（埋め込みつき）」にして保持マスクをなくす: 約 −40〜−140（試算の幅が大きい）。
   - 担当の外: `mn_top_1pe` の LED の引き延ばし（22 ビット × 4 と 25 ビットの計数器、約 120 サイト）、`mn_pe_core` のフォワーディングレジスタと MAU の結果バッファ（RAM16SDP4 97 個 = 776 サイト。4 深さで使っているので 4 分の 3 が空き）。
   - FMA の窓（143 ビット）を狭める案（WP12、WP20 の案 D）は、検討の結果やめた: 「大きい方を窓の上に置く」形では積（90 ビット）の位置合わせシフタが新たに要り、加算器・絶対値・正規化の幅の削減（約 300）より高くつく。今の「c だけを動かす」形は、公式の規則（積を捨てる閾値と c の格子）のもとでは効率がよい。
2. **floor / ftoi と整数のシフトは遅くなった**（最大 14 クロック / サイクル）。回帰の RTL のクロック数は合計 +7.4 %（シフトの多いプログラムで最大 +82 %）。27 MHz の実機では UART が律速なので、実行時間への影響は小さい（下の実機の時間）。4 PE の時分割（WP30）では 4 倍効くので、速さが要るならここを 2 段（8 / 1 → 16 / 4 / 1 など）にする余地がある（LUT は増える）。
3. **`mn_pe_lsu` の read-modify-write は 1 メモリずつ**になった（そのサイクルのビートが増える）。半語マスクのときだけ起き、`pemem` の 516 ステップ中 8 ステップ。
4. `brd_host_if` の `PBUF_AW` は 7〜15 で使える（生成する本体 88 バイトが pbuf に入ること）。従来も 7 未満では INFO が壊れていた。
5. 試験のベクタ（`mncore/sim/vectors/`）と回帰の公式キャッシュは生成物で、別の worktree から写して使った（コミットしていない）。
