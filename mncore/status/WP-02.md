### ndmp の細目（契約 §4 で決まっていなかった点）

`ndmp.py` の冒頭に書いた。要点:

- アドレスは 16 進 4 桁。PDM と DRAM だけ 8 桁（文字列順 = アドレス順にするため）。
- LM/GRF は長語アドレス（= 語アドレス >> 1）。奇数の語アドレスへの長語アクセスは、公式も揃えた長語を読む（確認済み）。
- 単語アクセスの d get（`d getf $m0 ..`）は別の空間 `LM0W LM1W GRF0W GRF1W`（語アドレス、値は 32bit）。
- T は `2 * サイクル + k`（k = 0 が MSB 側の長語）。`$lt` は MSB 側だけ、`$llt` は両方。
- OMR（マスクレジスタ）は `エントリ * 4 + サイクル`、値は 4bit。
- L1BM の 2 長語アクセス `$llb<a>` は長語 a と a + 4 の組（公式で確認。viz/core の blocks.rs と同じ）。
- 同じ場所を複数回 `d get` したら後勝ち。
- ヘッダの後に `# key: value` のメタデータ（src、kind、testcase、probe、producer）を置く。比較では無視する。

## 契約変更の要望

1. **§4 ndmp の細目を契約に入れてほしい**（「ndmp の細目」の節の内容）。特に:
   - アドレスの桁数（4 桁、PDM/DRAM は 8 桁）。比較ツールは数値で読むので桁数は比較結果に影響しないが、文字列順をアドレス順にするため。
   - 追加の空間 `LM0W LM1W GRF0W GRF1W`（単語アクセス）と `OMR`、T のアドレス `2 * サイクル + k`、L1BM の `$llb` が a と a + 4 の組であること。
   - 同じ場所の複数回の `d get` は後勝ち。途中の値を比べたいときは、`d get` の位置でプログラムを分けて別々に比べる。
2. **§4 の例の `L1BM n0c0 ...` は `L1BM n0c0b0 ...` の誤りと思われる。** L1BM は L1B ごとにあり、公式も `L1BM(n0c0b0,..)` と出す。
3. **§1 / §4 PDM の扱いを決めてほしい。** 公式の `d get $p` は PDM ではなく DRAM の内容を出す（`testdata/pdm_dget.vsm` で確認。L2BM → PDM → L2BM の往復は成立するのに `$p` は 0 を返す）。Rust（golden_dump）は本当の PDM を出す。案: 「PDM 空間は比較から外す（`ndiff --spaces` で除く）」か「PDM 空間は公式の `$p` の出力（= DRAM）と定義する」。WP02 は勝手に決めず、現状は食い違いとして一覧に出している。upstream の difftest_prog も PIU を比較から外している。
4. **§1 の「Rust Sim は公式と全問題で一致を確認済み」は、submodule の commit（e011bf9）では成り立たない**（未解決の点 1）。「MV の n128 転送を除き」と書き換えるか、WP06 で `2b9e595` の MV の変更を直すかを決めてほしい（`2b9e595` より前に submodule を戻すと、DAR / DRAM 間接の対応も失うので勧めない）。
