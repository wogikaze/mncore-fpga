### `mn_alu_int` のインタフェース

| ポート | 向き | 意味 |
| --- | --- | --- |
| `clk`、`rst` | 入 | 単一クロック、同期・正論理のリセット |
| `in_valid` / `in_ready` | 入 / 出 | 要求。`in_ready = !out_valid \|\| out_ready`（全段がそろって進む） |
| `pe_aluc_dmode[1:0]`、`pe_aluc_aluop[4:0]`、`pe_aluc_is_unsigned`、`pe_aluc_rounda`、`pe_aluc_roundb`、`pe_aluc_isela[3:0]` | 入 | ALUC の欄。名前は j_flat.yaml と WP10 の `mn_dec_j` の出力と同じ（そのままつなげる）。`iselb` は使わない |
| `imm32[31:0]` | 入 | 即値ペイロード（`mn_dec_j` の `imm32`）。aluop = 11111 のときだけ使う |
| `x[127:0]`、`y[127:0]` | 入 | ALU の 2 入力（1 サイクル = 2 長語）。bit 127 が 1 語目の MSB。入力元の選択（`$lr`、`$peid`、`$msb1`、フォワーディングなど）は呼び出し側 |
| `cls_int`、`cls_fp`、`cls_xpe`、`cls_none`、`cls_bad` | 出 | 振り分け（ALUC 入力からの組み合わせ出力、`in_valid` と無関係）。必ずどれか 1 つが 1 |
| `out_valid` / `out_ready` | 出 / 入 | 結果 |
| `z[127:0]`、`flags[3:0]` | 出 | 結果の 2 長語と、`$omr` に書くマスクフラグ（bit 3 が MSB 側の要素） |
| `out_err` | 出 | 受け付けた演算が `cls_int` でなかった（そのとき `z`、`flags` は 0） |

パラメタ `IREG`、`PREG`、`MREG`（既定はすべて 1）で段の間のレジスタを入れる。レイテンシは `1 + IREG + PREG + MREG` クロック（既定 4）、スループットは毎クロック 1。

| 段 | 内容 |
| --- | --- |
| 0 →（IREG） | 振り分け、制御語のデコード、`r` の丸め、imm / zero のバス |
| 1 →（PREG） | 加算器（add/sub/inc/dec と max/min の比較）、シフト量とマスク、ローテータの 0〜2 段 |
| 2 →（MREG） | ローテータの 3〜5 段、結果の選択、「出力が 0」以外のフラグ |
| 3 → 出力レジスタ | 「出力が 0」のフラグ（ゼロ検出） |

### 実装の要点（公式エミュレータの挙動。ベクタで確認）

- 長語を 16bit × 4 の区画に分け、精度に応じて 1 / 2 / 4 区画を 1 レーンとして SIMD で処理する。2 長語動作をしない命令は MSB 側の長語だけを計算し、LSB 側の長語は x の LSB 側（`r` 付きなら 0）をそのまま出す。passa / zero / imm は 2 長語を出す。
- 加算器は 69bit の 1 本。区画の境目に 1 ビットずつ挟み、(1, 0) で桁上げを通し、(sub, sub) で切って次のレーンの桁上げ入力にする。max/min の比較も同じ加算器（減算）の桁上げで行う。
- シフトは「レーン内の右ローテート（6 段）＋保持マスク」。左シフトは `w - s` の右ローテート。`s0 = y mod 2w`、バレルは `s0 mod w`、論理・算術シフトは `s0 >= w` で全部押し出す。マスクは区画単位の比較と 16bit の温度計符号で作り、桁上げ鎖を使わない。
- フラグ（SDM 表 3.11）: add/sub/inc/dec は符号ありで「結果 ≥ 0」、`u` 付きで「桁あふれなし」（加算は桁上げなし、減算は借りなし）。max/min は「x を選んだ（等しい場合を含む）」。packbit は「y の MSB が 0」。not/and/or/xor/lnot/シフト/passa は「レーンが 0」。zero/imm は 0。
- `u` が効くのは add/sub/inc/dec のフラグ、lsr（論理シフト）、max/min（符号なし比較）だけ。ほかの `u` 付きは `u` なしと同じ（WP03 の観察どおり、ベクタで一致）。
- passa と packbit は浮動小数点の精度（d/f/h）と機械語が同じ（dpassa = lpassa）なので、この ALU で全精度を扱う。`fpalu` の passa / packbit の全ファイル（`h` の `.r` を含む）でも一致した。
- `r` の丸め（`mn_alu_rnd`）: `h = 符号 | clamp(E - 96 + c, 0, 63) << 9 | RNE(仮数 23 → 9bit)`（WP03 で特定した公式の式）。`E + c` と 96 / 159 の比較は指数のビットの論理で行い、桁上げ鎖を使わない。
- imm: `u` なしは即値を 4 語、`u` 付きは 1・3 語目に並べる。imm の語では dmode、rounda、roundb、isela が即値のビットなので、丸めも振り分けもそれらを見ない。

### 振り分け（`mn_alu_cls`）

上から順に判定する。

| 条件 | 出力 |
| --- | --- |
| aluop = 11111（imm / immu） | `cls_int` |
| `rounda` か `roundb` が 1 で dmode ≠ 10 | `cls_bad`（assemble3 は受理するが、エミュレータが `ialuc.rounda can be used only with half-word` で止まる。WP03） |
| aluop = 10001 / 10010（msl / msr） | `cls_xpe`（WP30） |
| aluop = 11101、is_unsigned = 1、isela = 0101（zero） | `cls_int` |
| dmode = 11 | aluop = 00000 → `cls_none`（ALU を使わない語）、11110 → `cls_fp`（gbfn）、ほか → `cls_bad` |
| aluop が 00000〜01111 か 10011（packbit） | `cls_int` |
| それ以外（rsqrt、relu 系、lrelu 系、fmax/fmin、floor/ftoi/bfn、zero 以外の 11101 = hbfe） | `cls_fp`（WP13） |

- LUT は LUT1〜LUT4 の合計、ALU は桁上げ鎖のセル（1 個が LUT 1 個分の場所）、MUX2 は MUX2_LUT5〜8、FF は DFF 系。pnr LUT4 はハーネス（入力のシフトレジスタと出力の XOR 木を含む）の配置配線後の数。
- DSP と BSRAM は使わない。全体（LUT4 20,736）に対して、既定の構成は LUT と ALU を合わせて約 11%。
- `mn_alu_rnd` は単体で 1 個あたり LUT 112、ALU 60（`mn_alu_int` は x と y に 1 個ずつ）。

経緯:

- 最初の版（ローテータを平坦に書き、レジスタは入力側 1 段だけ）は LUT 3,168、Fmax 58.9 MHz だった。クリティカルパスはシフト量 → ローテータ → 結果の選択 → ゼロ検出 → フラグ。
- 既定の `synth_gowin` は abc9 で 8 入力までの LUT（MUX2_LUT5〜8 で組む）を使う。6 段のローテータを平坦に書くと、段がまとめられて LUT が約 2 倍になる（ローテータ単体で、平坦 1,314、`-nowidelut` 615、段ごとに `keep_hierarchy` 720）。そこで段を `mn_alu_rot_stage` に分けた。
- 段を 4 つに分け、シフト量とマスクと加算器を段 1 に、ゼロ検出を最後の段に回した。段の間のレジスタで abc9 がまとめられる範囲も区切られるので、LUT も 3,168 から 2,142 に減った（FF は 349 から 908 に増えた）。

## 未解決の点

- **zero と hbfe/n の判別**: aluop 11101 を zero とみなす条件を「is_unsigned = 1 かつ isela = 0101」にした（assemble3 の出力に合わせた）。`uhbfe/<n>` に `$peid` を与えるような語はこの条件に当たってしまうが、そのような語を assemble3 が出すか、エミュレータがどう扱うかは確かめていない。
- **dmode = 11 の扱い**: gbfn 以外の ALU 命令で dmode = 11（ALU を使わない語を除く）を `cls_bad` にした。assemble3 がそのような語を出すことはないと見ているが、エミュレータの挙動は確かめていない。
- **`r` を半語以外に付けた語**: `cls_bad` を出すだけで、停止（E_UNSUPPORTED）にするのは呼び出し側。WP10 のデコーダはこの組み合わせを未対応としていない（下の要望）。
- **msl / msr は実装していない**（WP30 の担当）。`cls_xpe` を出す。
- **Fmax**: 既定の構成で 124 MHz（最小 117 MHz）。コアの目標周波数は決まっていないので、足りなければ段を増やす（段 1 の加算器とローテータを分けるなど）。逆に低い周波数でよければ `PREG = 0` などで段とレイテンシを減らせる（上の表）。段 0 の入力は、呼び出し側でレジスタから与える前提（BSRAM の出力を直接つなぐと、clock-to-out 2.26 ns が段 0 に加わる）。
- `keep_hierarchy` の付いた階層は nextpnr-himbaechel がそのまま読めた（ハーネスの配置配線は階層付きの JSON で行った）。最上位の合成フローで階層を平坦化しない限り、効果は残る。

## 契約変更の要望

1. **§6 合成のオプション**: 既定の `synth_gowin`（abc9 + 8 入力までの LUT）は、マルチプレクサの多い論理で LUT を増やす（この ALU で `-nowidelut` に比べ 14〜27%、ローテータ単体で 2.1 倍）。Fmax は `-nowidelut` でも同等以上だった（上の表）。最上位のビルドで `-nowidelut` を使うか、全体で比べて決めることを提案する。資源の予算に効くので lead の判断がほしい。あわせて、RTL に `(* keep_hierarchy *)` を付けてよいか（この WP では `mn_alu_rot_stage` に付けた）を §6 に書いてほしい。
2. **§2 未対応の値**: ALUC の `rounda` / `roundb` が 1 で dmode ≠ 10 の語は、エミュレータが実行時に止まる。FPGA でも `E_UNSUPPORTED pe_aluc_rounda`（または roundb）にするのがよいと考える。デコーダ（WP10）の `unsup_vec` に入れるか、PE（WP14）が `cls_bad` を変換するか、どちらかを決めてほしい。同様に「dmode = 11 で gbfn と nop 以外」も `cls_bad` にしている。

## 次の WP への申し送り

- **WP14（PE）**
  - つなぎ方: ALUC の欄と `imm32` は `mn_dec_j` の出力をそのままつなぐ。`x`、`y` は入力元を選んだ後の 2 長語。`cls_*` は `in_valid` と無関係に出るので、`cls_int` なら `mn_alu_int`、`cls_fp` なら WP13 の ALU、`cls_xpe` なら WP30 の経路へ `valid` を振り分ける。`cls_none` の語は ALU を動かさない。
