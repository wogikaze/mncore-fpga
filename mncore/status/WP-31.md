### 境界のポート（詳細は `mncore/rtl/l1bm/README.md`）

PE の番号 (m, p) と サイクル c をポートで明示する。時分割の PE コア（WP30）でも実体の PE でも同じに使える。

- 語の欄: `mn_dec_j` の `ll` と `l1bm_*` 12 欄（`gwrite` / `gadr` を除く）。start から done まで保つ。
- 欄からの組み合わせ出力: `use_src`（PE → L1BM のオペランドが要る）、`lbf_upd`（`$lbf` を更新する語）、`chk_trap` / `chk_addr`（E_RANGE）、`chk_unsup` / `chk_field`（E_UNSUPPORTED と欄番号）。
- 手順: `start` → `src_*` の書き込み（全 PE・全サイクル）と `res_req` / `res_valid` / `res_data`（必要な PE・サイクル）を任意の順で → `commit` → `done`。
  L1BM と `$lbi` は commit の後にだけ書くので、その語の読み出しはすべて書き込み前の状態を見る。
- `$lbf`: 読み出し `lbf_r*` → `lbf_rdata`（組み合わせ回路）、書き込み `lbf_w*`（コアがゼロフラッシュ後の値を書く）。
- ポート B: 契約 §6 のメモリバス（ホストの空間 6 と、WP32 の L2BM 側）。

### 公式エミュレータで確かめた意味（要点）

参照モデル `l1model.py` を機械語の欄で書き、プローブ（全 64 PE と L1BM を `d set` / `d get`。アセンブラが作らない組み合わせは、アセンブル後に欄を手で変えた語）で公式と照合した。
最終的に、試験の 96 本すべてで公式と一致する（N_MAB = 1 向けの 49 本は、MAB 1〜15 が 0 を送るモデルでも一致）。

1. **lwrite = 0 の語は、`me` に関係なく L1BM → PE の値を L1BM から読む。** 並びは bmode と wl。揃っていない ladr もそのまま足す。
2. **lwrite = 1 の語は、L1BM → PE の値を `$lbi` から読み（折り返し）、PE → L1BM の転送をする。**
   - 折り返しの読み出しの並びは、**最後に `$lbi` を書いた転送**の bmode・wl・ずらし量で決まる。読み出す語の欄（`l1bmm $lbi ...` の語は bmode = 00、me = 0、isel = 111）は使わない。
   - isel = 111 の語（折り返しの読み出しだけの語）も値 0 の転送をして、`$lbi` を 0 で上書きする（noforward なら上書きしない）。
   - L1BM は me = 1 のときだけ書く（`me` は L1BM の書き込みの許可）。bmode = 00 は 01（16x1）と同じ。
3. **l1bmd の MAB のずらし**: アセンブラは `-4 × shift mod 64` を `ladr[5:0]` に入れる。使うのは `ladr[5:2]` だけで、分配は位置 `(L + 4m + p) mod 64` を読み、結合は PE (m, p) の値を `(4m + p − L) mod 64` に書く。`$lbi` にはずらさずに書く。
4. **`$lbf`**: 公式は実行した全語（L1BM の欄が既定値の語でも、暗黙の `l1bmp $lb0` の読み出しで）更新する。アセンブラはそのような語の後の `$lbf` の読み出しを拒否するので、RTL は L1BM の欄がある語だけで更新する（「未解決の点」1）。
5. **縮約の精度**（rrn ベクタにない形）: 拡張（e）は max / min にも効き、仮数を残したまま指数だけ付け替える（0 → 0、63 → 255、他は +96）。丸め（r）は fadd では縮約の中の丸め、max / min では ALU の `r` の丸め（指数の飽和、WP03 の r_round）。`hmax` / `hmin`（ext と round_out の両方）は 16bit レーンのまま。
   L1BM への並びは常に wl に従う（拡張した 2 長語を wl = 0 で書くと 1 長語目だけ、丸めた 1 長語を wl = 1 で書くと 2 長語目は 0）。
6. d に e / r を付けた縮約と、整数の d に e を付けた縮約はエミュレータが異常終了する（E_UNSUPPORTED にした）。
7. 折り返しの読み出しは、アセンブラが「直前の PE → L1BM の転送」を求める（`Reg->L1BM operation must precede L1BM turnaround`）が、間に L1BM でない語や nop があってもよい。公式はその間 `$lbi` を保つ。`$lbi` の初期値は 0。

UNKNOWN.md の A 節の 3 項目（`l1bm_me`、`l1bm_ladr` と `l1bmd+<n>`、`l1bm_dmode` / `ext` / `round_out`）は、上の 2.・3.・5. で意味が決まった（「契約変更の要望」3）。

## 未解決の点

1. **`$lbf` の更新（公式と RTL の差、アセンブルしたプログラムには出ない）**: 公式は、L1BM の欄がすべて既定値の語（ALU だけの語など）でも、暗黙の `l1bmp $lb0`（`L1BM[c]` の放送）で `$lbf` を更新する（手で欄を変えた語のプローブ。`python mncore/sim/tb/l1bm/probe_lbf.py` で再現できる）。
   RTL は L1BM の欄のある語だけで更新する。アセンブラは、L1BM → PE の転送のない語の後の `$lbf` の読み出しを拒否する（`Check 'ialu_op->a()' failed`）ので、アセンブルしたプログラムでは違いが出ない。
   公式に合わせるには、全語で 16 回の結果の取り出し（または `L1BM[0..3]` の写しと 1 ビットの印、FF 約 260）が要る。lead の判断を求める。
2. **E_UNSUPPORTED にした組み合わせ**（どれもアセンブラは作らない）: bmode = 11 の縮約（公式は何かを書くが並びを調べていない）、lwrite = 0 の縮約、整数の縮約の round_out = 1（未確認）。d に e / r を付けた縮約と整数の d に e を付けた縮約は、公式が異常終了する。
3. **Rust Sim（viz/core）と公式の食い違い**（契約 §1。RTL は公式に合わせた。Sim は直していない）。
   - (a) `fmaxr` / `fminr`（max / min に `r`）: 公式は単精度の結果を ALU の `r` の規則で半精度に丸める。Rust の `blocks.rs` は単精度の結果の下位 16bit をそのまま並べる（コードを読んだ結果。公式はプローブ rx15 / rx16 / rx18 / hx6 で確認）。
   - (b) `fmax $..e`（max / min に `e`）: 公式は拡張で仮数を残す（指数 63 の値は仮数付きの無限大のまま比べる）。Rust は `float::decode` / `encode` で正規化する（指数 0 → +0、無限大の仮数を消す）。指数 0 か 63 の半精度が入力にあると結果が違う（プローブ rx10 / rx11 / rx13）。
   - (c) `$lbi` の保持: 公式は PE → L1BM の転送のない語の間 `$lbi` を保つ。Rust は次の語で読み出しをエラーにする（WP02 の `research/experiments/resched/matmul-sweep/37/c2.vsm` と同じ原因）。
   - (d) 折り返しの読み出しだけの語（`l1bmm $lbi ...`）は、公式では値 0 の PE → L1BM の転送もして `$lbi` を上書きする。Rust は上書きしない（アセンブラは折り返しの読み出しを 2 語続けて書くことを許さないので、アセンブルしたプログラムには出にくい）。
   - (e) `$lbf`: 上の 1. の点で Rust は RTL と同じ（公式と違う）。
   - SDM 3.6.8.20 の擬似コード `src_mab = (mab + mabdiff) % 16` は符号が逆で、同じ節の例と Rust（`mab - mabdiff`）と公式が一致する。
4. **面積**: `RRN` = 1 は LUT 換算で約 4,000（全体の 19%）。1 PE 構成ですでに LUT4 75% なので、M2 では `RRN` = 2（N_MAB = 1 専用、12%）か 0（8%）を選ぶか、機能別のビットストリーム（WP-3x の方針）にする必要がありそう。
   ソースバッファ（SSRAM 32）は、`$lbi` の折り返しと L2BM 側の読み出しを「書き込みの前」に保つためのもの。コアが「全 PE の res を取ってから src を渡す」順序を守れるなら省ける（今は持っている）。
5. **ポート B と L2BM 側の順序**は単体では試していない（ポート B は初期化と照合に使っただけ）。WP32 / WP37 で L2BM 側と同じ語で使うときの順序（L2BM 側の読み出しは commit の前、書き込みは後）は README に書いた。
