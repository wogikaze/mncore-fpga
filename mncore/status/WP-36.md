### 公式エミュレータで確かめた行列の動作（RTL が実装するもの）

`probe_mat.py fields`（166 例。アセンブル後の語の MAUC 欄を書き換えて実行）、`probe_mat.py num` / `ext`、`gen_mat.py` の直接試験で確かめた。参照モデルは `matref.py`。

**行列レジスタ**: X / Y の 2 面、各 16 物理行 × 8 語（32 ビット）。精度ごとの実体はなく、viz/core と同じ配置（d の要素 (i, j) = 物理行 4i の語 2j, 2j+1、f / g (i, j) = 物理行 2i の語 j、h (i, j) = 物理行 i の語 j/2 の半語 j%2）。別の精度で読むと、この配置どおりに見える。リセットで 0。

**MAUC 欄の意味**（UNKNOWN.md の A 表の 3 行への反映案。契約変更の要望 1）:

| 欄 | mw = 0（?mwrite なし） | mw = 1（?mwrite あり） |
| --- | --- | --- |
| `readh`（131） | 転置読み出しの面 = readh ? X : Y。行列 MAU の面 = readh ? Y : X | 書き込みの面 = readh ? X : Y。転置読み出しの面と行列 MAU の面 = readh ? Y : X（書き込みと反対の面） |
| `ma`（122..125） | 転置読み出しの列 | 書き込みの行 |
| `{signa, signc, passa, zeroc}`（126..129） | （MAU 命令の欄） | 転置読み出しの列（MAU 命令がないので空いている欄を使う。assemble3 は ?mwrite + ?mread でここに列を書く） |
| `mdw_side`（130） | 転置読み出しには効かない（hmread は常に 2 列）。d の行列 MAU では u（0）/ d（1）: u は出力の行 0, 1、d は行 2, 3 だけを計算し、ほかの行は c を出力の精度で出す（`dmfmau` / `dmfmad`。`probe_mat.py num d` で確認。RTL は d の行列 MAU を持たない） | h の書き込みで 1 サイクル 2 行（`$ll`）。f / d の書き込みには効かない |
| `dmode`（116） | 転置読み出しの精度（11 g は f と同じ配置） | 書き込みの精度 |

- 同じ語の中で、書き込む面は読む面（転置読み出し・行列 MAU）と必ず違う。assemble3 は同じ面を指すと `conflict readh mwrite` / `conflict readh mau` で拒否し、?mwrite・行列 MAU・?mread の 3 つは同居できない。したがって語の中の読み書きの順は結果に影響しない（RTL は ?mwrite を通常のパスの各 PE のステップで書く）。
- h の転置読み出しの列と、2 行書き込み（mdw_side = 1）の行は偶数に切り捨てる（bit 0 を見ない）。assemble3 は 2 行書き込みの奇数行（`hmwrite $llr40v $llx3`）を通す。
- 転置読み出しは **nop / noforward 以外の全ステップ**で行われ、`$mreadf` を更新する（WP20 の確認の続き）。?mread のない語（ALU だけの語、ベクトル MAU の語）でも欄が表す読み出しになる（例: `fvpassa ; fmread $lx4`、欄だけ readh = 1 にした `fvpassa`）。ゼロフラッシュ（`/0101`、zero_sel = 11）は `$mreadf` にもかかる。書き込みマスクはかからない。
- ?mwrite の入力は MAU の b（iselb、signb、extb）。d / f の e（精度拡張）は、ゼロと無限大の符号を残して仮数を 0 にする（`-0` は `0x8000…`）。h の `r` は ALU の `r` と同じ丸め（WP13 の `r_round`）。

**行列 MAU（?mfma / ?mmul）の数値**（`probe_mat.py num`。SDM 4.5 の細部）:

| | d | f | g | h |
| --- | --- | --- | --- | --- |
| 加数の格子 `G = Ep − K` の K | 86 | 39 | 34 | **26** |
| 積を捨てる `lead(c) − Ep ≥ T` の T | **57** | （結果に表れない） | （結果に表れない） | **30** |

- Ep = (ca − bias) + (cb − bias)。ca / cb は行と x のブロックの指数欄の最大（共通指数）。ca か cb が 0 なら内積は 0 で、c は格子に揃えない。そうでなく ca か cb が全 1 なら結果は +∞。
- 内積は厳密（f と d は SDM 4.3 と同じ部分積の省略、f は下位 5 × 5 ビットの積を捨てて両方が 0 でなければ 2^8 を足す。g は仮数欄の上位 18 ビット）。c は格子に揃え（格子より下はジャム、2 桁以上下なら捨てる）、1 回だけ丸める。
- f / g は結果が c と同じ単精度なので、T の規則は結果に表れない（RTL は持たない）。
- **h の拡張表現（指数欄 0 = 共通指数 − 6）の積**は 6 / 12 ビット右シフトして丸めてから足されるが、公式の丸めは最近接偶数丸めと一致しない例がある（単独の積で 6 ビットの 92 %、12 ビットの 94 % が一致。余りだけでは決まらず、オペランドに依存する）。RTL は最近接偶数丸めで実装した（未解決の点 2）。

### 行列ユニットの構成（`mn_mab_mat`）

`mn_mab` の 4 PE の時分割（WP30）の上に置いた。行列 MAU の語は検査だけのパスから始まり、通常のパスで PE 0〜3 を順に実行する。

| 動作 | いつ | どうやって |
| --- | --- | --- |
| x の収集（?mfma） | 検査だけのパスの PE p、サイクル c | MAU の a（`$t`、`$aluf` などを含む）を `mg_*` で受け、x の BSRAM の {p, c} に書く。行列 MAU の語には必ず検査だけのパスを付ける（`prechk`） |
| ?mwrite | 通常のパスの PE p の発行 | MAU の b を受け（h の `r` は収集の `mn_alu_rnd` で丸めた値）、PE p の列（行の語 2p, 2p+1）を 2 語（2 行書きは 4 語）書く。書く面は語の中で読まれないので、検査だけのパスで集める必要がない |
| ?mfma / ?mmul | 通常のパスの PE p の発行 | 出力の行ごとに、行列の語と x の語を読み（1 項 7 クロック、f は 3 回の乗算で 15）、48 ビットで累算し、`mn_mab_mrnd` で c を足して丸める。結果は MAU の結果として返す（`$mauf`、isel 00、フラグ） |
| 転置読み出し | 通常のパスの各サイクルの回収 | 2 語（d / f / g）か 4 語（h）読み、ずらし入れで 128 ビットを作る。isel 11 の書き込みに使い、フォワーディングのある語では `$mreadf`（BSRAM）に 4 語で書く（ゼロフラッシュの半語ごとの許可 8 ビットを掛ける）。リセット後に ?mwrite がまだなければ、読まずに 0 で答え、`$mreadf` も書かない（0 のまま） |
| `$mreadf` の読み出し | 収集（ALU の x が `$mreadf`） | BSRAM から 4 語読む（収集はそれを待つ） |

- BSRAM は 3 ブロック（行列と `$mreadf` / `$mauf` の 512 × 32 が 1、x の 512 × 64 が 2）。DSP 1（MULT18X18）。
- 読み出しの順番待ちは 1 本（回収の読み出し > `$mreadf` の読み出し > 行列 MAU）、書き込みも 1 本（リセット後の消去 > `$mreadf` / `$mauf` の書き込み > ?mwrite）。
- MAT = 1 でも、ベクトル MAU がある構成は `$mauf` と MAU の結果の LUT RAM を共用する。ない構成（MAUF = 1）は行列ユニットが MAU の結果のレジスタと `$mauf` を持つ（LUT RAM を足さない）。その代わり、行列 MAU は前のサイクルの回収を待ってから次のサイクルを始める。
- 指示書の「?mwrite は検査だけのパスで 4 PE の入力を集めてから書く」は、上の理由（語の中で書く面を読まない。公式で 166 例を確認）で通常のパスで書く形にした。範囲外（E_RANGE）の語は、LM を読む ?mwrite なら検査だけのパスで、GRF だけなら PE 0 の開始時の検査で止まり、どの PE の ?mwrite も書かない（`e_range_mwrite` で確認）。
- 指示書の「行列 MAU は `mn_fp_fma` を逐次に使い回す形を第一候補」は採らなかった。ブロックフロートの内積は項ごとに丸めずに足す（d の積は 104 ビット）ので、1 回ごとに丸める `mn_fp_fma`（LUT 換算 約 3,000、DSP 8）を項ごとに使っても一致しない。整数の積和（DSP 1）と最後の 1 回の丸め（`mn_mab_mrnd`、LUT 換算 約 900）にした。

## 未解決の点

1. **d の行列 MAU（dmfma / dmmul）は実装していない**（MAT = 1 でも E_UNSUPPORTED `pe_mauc_dmode`）。コーパスに使う本はない（行列の 122 本は g / h / f だけ）。公式の規則（格子 K = 86、積を捨てる T = 57、u / d の行）は `matref.py` に入れ、`probe_mat.py num d` で公式と一致を確かめた（2,048 試験、32,768 要素）。実装するなら、累算器を 92 ビット、丸めの窓を約 150 ビット（倍精度の出力と倍精度の c）に広げ、項ごとの乗算を 18 ビットのタイル 8 回（仮数欄 52 ビットの下位 16 × 16 ビットの積は省いて 2^30 を足す。SDM 4.3）にする。LUT 換算で約 +800 の見込み。
2. **h の拡張表現の積の丸め**は公式と完全には一致しない（上の「公式エミュレータで確かめた行列の動作」）。RTL は最近接偶数丸め。コーパスで拡張表現を使う本（`14.mat-sq` など）は、整数のデータで拡張表現の積の捨てるビットが 0 になるため一致している。公式の規則は乗算器の部分積の作りに依存しているとみられ（SDM 4.5 も「乗算器出力の詳細に立ち入る必要があるため省略」）、`probe_mat.py ext` の観測（下位ビットの値だけでは決まらない）から先は分かっていない。
3. **面積**: 行列ユニットは LUT 換算で約 2,100〜2,300、`mn_pe_core` の側を含めたボードのトップの増分は +2,400〜2,800。M1 は配置配線で LUT4 72 %、BSRAM 78 %。ベクトル MAU と行列（M3）は yosys で 75.3 %、FP ALU 全部（FPALU = 3）と行列は 75.1 % と、どちらも目安をわずかに超える。M2（WP37）で行列を載せるなら、ほかのユニットとの組み合わせを選ぶか、行列ユニットをさらに削る必要がある（下の申し送り）。
4. **速さ**: 行列 MAU は逐次で、hmmul / hmfma の 1 語は約 9,400 クロック（4 PE 分）。27 MHz で 0.35 ms 程度で、実機ではホストの転送のほうが長い。速くするなら項の処理をパイプラインにする（いまは 1 項 7 クロック。1〜2 クロックにできる）。
5. ?mwrite の後は、`$mreadf` の更新（転置読み出し 2〜4 回と、フォワーディングの語では 4 語の書き込み）が毎ステップ入る（上の「速さ」）。行列を使う本だけの費用。
6. 行列レジスタは RD_MEM / WR_MEM の空間を持たない（ホストからは見えない。公式の `d get` にもない）。
7. 指示書の「?mwrite は検査だけのパスで集める」「`mn_fp_fma` の使い回し」とは違う作りにした（成果物の「行列ユニットの構成」）。
8. `fixed/all.scr` は 1.4 MB（17 本 × 4 PE の照合と初期値）。
