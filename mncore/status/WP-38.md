### `mn_top_multi`（`mn_top_m2` との違い）

1. **PDM / DRAM を消すのは RESET コマンドだけ。** `mn_core` は `SDCLR` = 0 にし、上位が RESET の `core_rst` の立ち上がり（電源投入の後の最初の `core_rst` は除く）で DRAM（2^19 長語）と PDM（2^17 長語）に 0 を書く。その間は SDRAM のバスを専有し、コアの MV とホストの空間 8 / 9 は待つ。構成（メンバーの読み込み、ボタン S1）では消さないので、プログラムの途中で別のメンバーを書いても PDM / DRAM は残る。
2. **ユニットのないメンバー（`UNITS` < 2、`SDRAM` = 1）も PDM / DRAM のホスト空間を持つ。** コアに MV がないので、上位が `mn_mv` のホストの口と同じ検査（loc 0、深さ）と番地（`PDM_BASE` / `DRAM_BASE`）で SDRAM に橋渡しする。リフレッシュも続く。
3. **`SDRAM` = 0 のメンバー**は制御器を持たず、構成の後に SDRAM を self refresh に入れる（27 / 2 MHz のクロックで NOP、PRECHARGE ALL、CKE を下げた AUTO REFRESH。約 30 LUT）。次のメンバーの制御器は CKE を上げて抜け、初期化し直す（PRECHARGE、AUTO REFRESH、MRS: データは残る）。PDM / DRAM の空間は持たない（INFO の深さ 0）。
4. `UNITS` = 1 のスタブ: `mn_l2bm` は L2BM の語に `chk_unsup`（E_UNSUPPORTED `l2bm_lwrite`、PE の範囲検査の後）、ホストの L2BM は範囲外。`mn_mv` は valid な m 語に E_UNSUPPORTED（info 0x80）、wait は完了なし（WAIT）。`mn_core` はそのまま（ファイル一覧の差し替え）。
5. LED は契約 §7 の方針（LED 0 だけをデューティ 1/1024 で常時点灯）。

### 計画（`mnplan.py`）

- **語の必要（caps）**: `L1`（L1BM の欄が既定値でない、isel 10 の書き先、`$lbf` を読む）、`L1R`（L1BM の縮約 rmode）、`L2`（gwrite / L2BM lwrite）、`MV`（valid な m 語、wd ≠ 0 の語。ll = 00 でも）、`MAU`（enfma で mmode 0）、`MAUF`（`$mauf` を読む: MAU か MAT のあるメンバー）、`FP1`（floor / ftoi）・`FP2`（fmax / fmin）・`FP3`（rsqrt、relu、lrelu）、`BFN`、`MAT`（行列 MAU f / g / h、?mwrite、?mwrite のある本での行列の読み出し）、`NONE`（d の行列 MAU、DAR の命令: どのメンバーでも E_UNSUPPORTED）。判定は `mn_alu_cls`、`mn_pe_core`（`fp_here`、`u_nma` など）、`mn_l1bm`（`use_src`、`lbf_upd`）、デコーダの `grp` と同じ。
- **ホストが読み書きできない状態**（語が読む・書く）: `$aluf`（ALU のある語、noforward を除く）、`$mauf`（MAU / 行列 MAU）、`$lbf`（L1BM の欄のある語）、`$lbi`（lwrite = 1 の語: 面 0 は常に、面 1 は wl = 1 のとき、最後に書いた転送の並び。読むのは isel 10 の書き先を持つ語と、その `$lbf` が後で読まれる語）、行列レジスタ。オペランドの選択（ALU の isela / iselb、MAU の isela / b / c、L1BM の isel）は、その演算が実際に読むときだけ数える（`mn_pe_core` の `rd_use` と同じ）。
- **生存解析**: プログラムは直線なので後ろ向きに 1 回。境目 b で生きていて、かつ b より前の語が書いた状態があれば、b では切り替えられない（一度も書かれていない状態はリセット後の値で、構成の後も同じなので生きていないとみなす）。
- **区間**: 切り替えてよい境目のうち、1 つのメンバーがその間の語をすべて実行できる最も遠いものまでを 1 区間にする（貪欲。最少の区間数になる）。候補のメンバーが複数なら、読み込み済みのもの、次に `set.json` の順（SDRAM のある MAU を SDRAM のない MAUF3 より先に）。どのメンバーも実行できない語（または、手前のどの境目でも状態が生きている語）があれば、そこまで最も遠くまで進めるメンバーに残りを任せ、ボードはその語で E_UNSUPPORTED で止まる（1 本のビットストリームと同じ止まり方）。

### 状態の引き継ぎ（`mnrun.py`）

| 状態 | 方法 |
| --- | --- |
| PE 4 個の GRF0 / GRF1 / LM0 / LM1（各 256 長語）、T、OMR 1〜15、BAR（`$mb` / `$nb`） | 区間の終わりに RD_MEM で 4,196 長語を読む。次のメンバーは構成で 0 になっているので、0 でない長語だけ WR_MEM で書く |
| L1BM（1,024 長語）/ L2BM（2,048 長語） | 書かれた可能性がある（L1BM / L2BM / MV の語、d set）ときだけ、そのメンバーが持っていれば読む。持たないメンバーの間はホストの写し（その間の d set / d get も写しに対して）。持つメンバーに戻ったら 0 でない長語を書く |
| DRAM / PDM | SDRAM に置いたまま（上の 1、3）。ただし構成の間は SDRAM がリフレッシュされず、ビットが少し化ける（実機の項: 1 回の読み込みで 12.6 Mbit のうち 3 ビット）。そこで PDM / DRAM の d set / r / d get はホストが順番どおりに保留し、MV の語を含む区間の直前か、プログラムの終わりに、SDRAM のあるメンバーでまとめて実行する（MV の語のない区間は PDM / DRAM に触れないので順序は保たれる）。PDM / DRAM が消去の 0 だけのはずのときは、そのメンバーを RESET してから（状態を書き戻す前に）実行する。終わりに d get が残っていて、いまのメンバーに SDRAM がなければ、SDRAM のあるメンバーをもう 1 回読み込む。PDM / DRAM が切り替えをまたいで中身を保つ必要があるのは、MV の語か書き込みの後に切り替えがあり、その後でまた使う場合だけ（M2 の回帰の 247 本にはない） |
| MV のタグの完了数（`mn_mv_tags`） | 実行した語からホストが数え（valid な m 語で +1、2 で飽和、wait で 0）、MV のあるメンバーに入ったら mmode 111 の m 語（何もしないがタグを数える、WP33 / WP37）を数だけ流す |
| `$aluf` `$mauf` `$lbf` `$lbi`、行列レジスタ | ホストが読み書きできない。生きていない境目でだけ切り替える（計画） |
| MV の転送中、L2BM の DAR の連続 | RUN は MV の完了を待って終わるので、境目で転送中のものはない。DAR はどのメンバーにもない（`L2_DAR` = 0） |

1 区間の手順: メンバーを読み込む（読み込み済みなら省く）→ 1 Mbaud でつなぎ INFO でメンバーを確かめ、2 Mbaud に → （最初の区間は RESET）→ 状態を書く → 区間の語を窓（512 語）ごとに IMEM に書き、d / r 行で RUN を分けて実行（`mnhost.execute_program` と同じ）→ 次の区間があれば状態を読む。停止（E_RANGE / E_UNSUPPORTED / E_DECODE）でプログラムを終え、WAIT では RUN と d set をやめて d get は読む（`mnhost.py run` と同じ）。

## 判断と理由

1. **組は「載るもの」から選んだ。M2 のユニットと MAU を同じ語で使う本は、切り替えでは救えない。** 指示書の例（M2 + MAU、M2 + FPALU + BFN、M2 + MAT）はどれも載らない（WP37: M2 + MAU は LUT 換算 95.6 %）。さらに、語ごとに要るユニットを調べると（テストの 1）、76 本が M2 のユニットと MAU / FP ALU を同じ語の中で使う。語の中の読み書きの順序（全部読んでから書く）とフォワーディングレジスタの受け渡しがあるので、語を分けて別のビットストリームで実行することはできない。そこで、試算（資源の表）で載る範囲で、救える本が最も多い組にした: M2a（整数、L1BM、L2BM、MV）、MAU（1 MAB + MAU）、MAUF3（MAU + FP ALU の FPALU 3。SDRAM なし）、L1MAU（L1BM + MAU。L1BM の縮約なし、SDRAM なし）、複製規則の M2aR。L1BM の縮約（RRN 2）を入れた L1MAU（SDRAM なし）と、SDRAM を持つ MAUF3 は配置できなかった（LUT4 74〜76 %、DFF 67 %）。SDRAM を持つ L1MAU、FPALU 1 / 2 の MAU は、yosys の試算で上限を超える（資源の表）。これで E_UNSUPPORTED は 82 本から 27 本になるが、0 本にはならない（受入基準の未達。未解決の点 1）。
2. **既存の RTL を変えずに引き継いだ。** ホストが読み書きできない状態のうち、MV のタグの完了数は、何もしない m 語（mmode 111。WP33 / WP37 が公式で確認した「タグは数える」）を流せば戻せる。フォワーディングレジスタ（`$aluf` `$mauf` `$lbf`）、`$lbi`、行列レジスタは、計画が「生きていない境目」でだけ切り替えて避けた。読み書きの口（デバッグ用の空間）を足すと `mn_pe_core`（PE とサイクルごとの 128 bit の LUT RAM）と `mn_l1bm` を変えることになり、WP34 が大きく変える `rtl/core/`・`rtl/pe/` と衝突する。救える本は最大 10 本（いまの組で状態が生きているために止まる本）で、そのうち何本かは後の語でユニットの不足でも止まるので、今回は足さなかった（契約変更の要望 4 に案）。
3. **L1BM だけのメンバーはファイル一覧の差し替えで作った。** `mn_core` の M2 = 1 は L1BM / L2BM / MV を一緒に置く。`mn_core` にユニットごとのパラメータを足す代わりに、同じポートのスタブ（`fpga/multi/stub/`）を `files_l1.txt` で本物と差し替えた。`rtl/core/` を変えないため。スタブは L2BM の語と m 語を E_UNSUPPORTED にする（`tb_multi` の u1 / u1n で確認）。
4. **PDM / DRAM を構成で消さない上位（`mn_top_multi`）を新しく作った。** `mn_top_m2` は電源投入（構成）でも DRAM / PDM を消す（`mn_core` の `SDCLR` はリセット全部に反応する）ので、切り替えのたびに消える。`mn_core` は `SDCLR` = 0 にし、RESET コマンドのときだけ上位が消す（電源投入の後の最初の `core_rst` は除く）。デザイン ID は 0x05 にした（`mn_top_m2` の 0x04 と RESET 以外の振る舞いが違うため。契約変更の要望 1）。
5. **SDRAM は構成の間にビットが化けるので、PDM / DRAM の行は MV の語の直前まで保留した。** 実機で、リフレッシュのない時間と化けたビットを測った（実機の項）: 同じメンバーを読み直すだけ（構成の数秒）で 12.6 Mbit のうち 3 ビット、リフレッシュなしで 28 s 置くと 0.15 % の長語が 1 ビット化けた。PDM / DRAM を切り替えをまたいで正しく保つことは期待できないので、実行器は PDM / DRAM の d set / r / d get を、MV の語を含む区間の直前かプログラムの終わりまで保留し、SDRAM のあるメンバーでまとめて実行する（MV の語のない区間は PDM / DRAM に触れないので結果は同じ）。消去の 0 しかないはずのときは、そのメンバーを RESET し直す（構成で化けた 0 を消す）。これで、M2 の回帰の本はどれも PDM / DRAM の中身を切り替えをまたいで保つ必要がなくなった。残るのは「MV の語の後に切り替え、その後でまた PDM / DRAM を使う」本で、回帰にはない（未解決の点 2。対策の案は、切り替えの前に SDRAM を self refresh に入れる口: 契約変更の要望 3）。
6. **SDRAM の制御器を持たないメンバー（`SDRAM` = 0）は、SDRAM を self refresh に入れる。** 制御器と PDM / DRAM の口は LUT 換算で約 1,000（非同期 FIFO の RAM16SDP4 を含む）あり、これを外すと MAUF3 と L1MAU が載る。外したメンバーが読み込まれている間も SDRAM の中身を保つため、上位の約 30 LUT の順序回路が PRECHARGE ALL と self refresh への移行を出す（SDRAM のモデルで命令の誤りがないことを確認、実機の項で保持を確認）。
7. **一度も書かれていない状態は生きていないとみなした。** リセットの後の値（`$lbi` は 0。フォワーディングレジスタはユニットが動く前に読むと公式エミュレータが誤りにする）は、構成の後のメンバーでも同じなので、引き継がなくてよい。これがないと、`$lbi` をリセット後の値のまま読む本（14.exp など）で、最初の書き込みより前の境目がすべて使えなくなる。
8. **計画はボードなしで回せるようにした**（`mnplan.py`）。回帰の表には、全ユニット入りの RTL との比較（as rtl）に加え、計画が予想する結果（RTL の結果、またはどのメンバーも実行できない語での E_UNSUPPORTED）との照合（as_expect）を出す。
9. **INFO だけではメンバーを決めきれない**（L1BM の縮約の有無、SDRAM の有無は深さでわかるが `L1_RRN` は出ない）。`mnrun.py` は INFO（デザイン ID、フラグ、L1BM / L2BM / DRAM の深さ）で読み込んだメンバーを確かめ、能力は `set.json` から取る。

## 未解決の点

1. **受入基準の「ユニットの不足による E_UNSUPPORTED が 0 本」は未達**（実機の回帰で 27 本が残る。WP37 の 82 本から 55 本減った）。原因は面積: M2 のユニットと MAU / FP ALU を同じ語で使う本（76 本）を実行するには、それらを 1 本に載せるしかない。いまの組で救えないのは、L1BM の縮約 + MAU（4 本）、FP1（floor / ftoi）と L1BM / MAU（6 本）、FP2（fmax / fmin）と MAU（1 本）、FP3 と L1BM と MAU（3 本）、L2BM と MAU（3 本）、隠れた状態が手前のすべての境目で生きている（10 本）。面積の作業（申し送り）か、隠れた状態の口（契約変更の要望 4）が要る。
2. **PDM / DRAM は切り替えをまたいで保たれない**（構成の数秒でビットが化ける）。実行器は PDM / DRAM の行を MV の語の直前まで保留して避けたが、「MV の語で DRAM に書き、切り替え、後でその DRAM を使う」本は正しく動かない可能性がある（M2 の回帰にはない）。対策は契約変更の要望 3。
3. 切り替え 1 回に、ビットストリームの読み込み（`openFPGALoader` で 3.5〜20 s、回帰の中央値 5.4 s。PC の負荷で大きく変わる）と状態の読み書き（約 1.4 s）がかかる。読み込みの大半は `openFPGALoader` 自身（起動、.fs の解析、SRAM の消去と書き込み）。回帰の読み込み 96 回のうち 59 回（395 s）は、SDRAM のない L1MAU で終わる 30 本のもの（終わりに PDM / DRAM の d get を読むための M2a の読み込み 30 回と、本の始めの L1MAU の読み込み 29 回）。MV の語を実行していなければ PDM / DRAM の中身は RESET の 0 とホストの d set だけで決まるので、ホストの写しで答えれば省けるが、実機から読むことを優先してそうしなかった。
4. 複製規則の L1BM だけのメンバー（L1MAU の REPLICA 版）は作っていない。複製規則で L1BM と MAU を同じ語で使う本は E_UNSUPPORTED になる。
5. **組は全命令を覆っていない**（指示書の作業 1）。FP ALU の floor / ftoi / fmax / fmin（FPALU 1 / 2）、BFN、MAT を実行できるメンバーがない。M2 の回帰の 247 本は BFN / MAT を使わず、FP1 / FP2 の語はほとんど MAU や L1BM と同じ語にある（判断と理由 13）。行列や bfn の本を回すなら、WP36 の M1 相当（`mn_top_multi` の UNITS 0、MAT 1、BFN 1）などを `set.json` に足す（申し送り）。
6. **複製規則の M2 の回帰（247 本）は実機で回していない**（複製規則は hello_world だけ）。ゼロ規則の回帰の後、ボードを WP34 に渡した（22:54 にロックを消し、22:55 に WP34 が取った）。計画の予想（ボードなし）: 複製規則ではメンバーが M2aR / MAU / MAUF3 になる（L1MAU はゼロ規則）ので、L1BM と MAU が同じ語の本を救えず、E_UNSUPPORTED 65 本。RTL の複製規則の表（`results_m2_replica.tsv`）で公式と食い違う 49 本（WP37 の M2a-R の実機でも 49 本）は、規則の差なのでそのまま残る。M2aR は種 2 でコア 27.72 MHz（27 MHz に対して余裕 0.7 MHz）、LUT4 74.6 % とぎりぎり。

## 契約変更の要望

1. **§7 / PROTOCOL.md: デザイン ID 0x05 = `mn_top_multi`（WP38、ビットストリームの組のメンバー）。** INFO のフラグは 0x03 / 0x04 と同じ（bit 3..2 FPALU、bit 4 MAU、bit 5 BFN、bit 6 MAT、bit 7 REPLICA）。ユニットは空間の深さで示す: L1BM（0x06）が 0 でなければ L1BM の単位、L2BM（0x07）が 0 でなければ L2BM と MV、PDM / DRAM（0x08 / 0x09）が 0 なら SDRAM の制御器を持たない（そのとき SDRAM は self refresh）。**RESET コマンドで PDM / DRAM を 0 にし、構成（電源投入、ボタン S1）では消さない**（0x04 は両方で消す）。INFO に L1BM の縮約の有無（`L1_RRN`）を出す場所がないので、組の定義は `fpga/multi/set.json` に置いた。INFO にユニットの能力を出すなら、空き（offset 19 の bit 1 は「RUN スタブ」）ではなく INFO の版を上げて欄を足すのがよい。
2. **§7: 複数のユニットを要する本の実機での実行は `mncore/tools/host/mnrun.py`**（`hwrun.py` は 1 本のビットストリーム）。組（`fpga/multi/set.json`）は §6 の資源の表に載せてほしい（nextpnr の LUT4、Fmax コア / SDRAM）: M2a（UNITS 2）71.8 %、30.3 / 94.0 MHz。M2aR（同、複製規則）74.6 %、27.7 / 85.7 MHz。MAU（UNITS 0 + SDRAM）69.9 %、44.5 / 89.6 MHz。MAUF3（MAU + FPALU 3、SDRAM なし）68.6 %、44.1 MHz。L1MAU（L1BM + MAU、縮約なし、SDRAM なし）74.1 %、40.4 MHz。あわせて、**配置できなかった構成**（MAU + FPALU 3 + SDRAM: LUT4 74 % / DFF 67 %、L1BM（縮約あり）+ MAU: yosys 76.4 %）も上限の目安として載せるとよい。
3. **§6 の SDRAM: 構成の間は SDRAM がリフレッシュされず、数秒でビットが化ける**（実測: 同じビットストリームの読み直し 1 回で 12.6 Mbit のうち 3 ビット、28 s で長語の 0.15 %）。ビットストリームを切り替えて PDM / DRAM（や将来の仮想 PE の状態）を保つときは、切り替えの前に SDRAM を self refresh に入れる口（例: 設計固有の空間 0x12 への書き込みで、制御器を止めて PRECHARGE ALL と SELF REFRESH ENTRY を出す）を上位に足すか、ホストが読み出して書き戻すこと、を書いてほしい。今回は `mnrun.py` が PDM / DRAM の行を MV の語の直前まで保留して避けた（判断と理由 5）。
4. **フォワーディングレジスタと `$lbi` の読み書きの口（今回は足していない）**: 将来、切り替えの境目を自由にするなら、設計固有の空間に `$aluf` / `$mauf` / `$lbf`（PE × サイクル × 128 bit）と `$lbi`（2 面 × 位置 × サイクル、最後の転送の並び 9 bit）を出す案。`mn_pe_core` の `u_aluf` / `u_mauf`（`mn_ram_lut`）と `mn_l1bm` の `u_lbf` / `u_lbi0` / `u_lbi1` にホストの読み書きのポートを足すことになる。いまの組で救える本は最大 10 本。
