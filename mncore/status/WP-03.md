### 期待値の作り方（ブラックボックス方式）

- viz/core のロジックはコピーしていない。使った公開 API は `vsm::parse`、`run::Sim::exec`、`Machine` の PE メモリ（`MemWrite::poke` / `MemRead::peek`）、`pes[].mask`、`blocks.l1bm` / `l2bm`、`PeId`。
- 1 命令の VSM（例: `iadd $llr0v $lls0v $lln0v $omr1`）を Sim の構文解析器で読み、入力を GRF0 / GRF1 / LM0 に置いて `exec` し、LM1 とマスクレジスタ 1 を読む。1 回の実行で 4096 PE × 4 サイクル = 16,384 行を評価する。
- 照合では同じ命令と同じメモリ内容を `d set` / 命令 / `nop/3` / `d get` の VSM にし、flat でアセンブルしてエミュレータで実行する。
- `float::vfma` / `decode` / `encode` は、入力値を作るとき（打ち消しの c など）、`vectors_fixed` から外す行の判定（`round_twice`）、テスト（命令経由の結果と `float::vfma` の一致）にだけ使った。期待値には使っていない。

## 未解決の点

### Sim と公式エミュレータの食い違い（Sim の修正が必要と考える）

いずれも、`--work` の `<op>.mismatch.txt` に全行（ベクタの値と公式の値）が出る。
ベクタの期待値は `--official-expect` で公式に合わせ済み。Sim 側の修正は未着手で、修正案をここに残す（submodule は変更していない）。

1. **`r_round`: ALU の `r` オプション（単精度→半精度）の丸め**（SDM 3.6.12.19）
   - 公式の結果は次の式で、`fp/cvt_f2h` の照合した全 1,442 行と一致した。
     `h = 符号 | clamp(E - 96 + c, 0, 63) << 9 | (RNE(仮数 23bit → 9bit) & 0x1ff)`。E は単精度の指数欄、c は仮数の丸めの繰り上がり。
   - つまり、0 への切り捨てや ∞ の仮数の消去をしない。-0 は 0x8000、下にあふれた値は指数 0 で丸めた仮数が残り、∞ と上にあふれた値は指数 63 で仮数が残る。
   - Sim の `round_bus`（`machine.rs`）は `encode(HALF, decode(SINGLE, x))` なので、下にあふれたら +0、∞ の仮数は 0、-0 は +0 になる。
   - 例: `0x80000000` → 公式 `0x8000`、Sim `0x0000`。`0x307fdfff` → 公式 `0x01ff`、Sim `0x0000`。`0xffc00001` → 公式 `0xff00`、Sim `0xfe00`。
   - MAU の h の入力丸め（`exta`/`extb`）では、変換後の値が 0 や ∞ として扱われるため差が見えなかった。
2. **`ext_mul`: MAU の精度拡張した a / b の積**（d と f の fma、mul）
   - 公式は拡張した値どうしを正確に掛ける。例: `dvmuld`、a = `bf800001`（単精度を拡張、符号反転で +1+2^-23）、b = `bff0000000000001` → 公式 `bff0000020000001`（正確な積の丸め）、Sim `bff0000020000081`。
   - Sim の `compute_vec(_pe)` は拡張オペランドを低い精度で `decode` した `Val` のまま `float::vfma` に渡す。`mul_exact` は「仮数の下位 16bit（倍精度）/ 5bit（単精度）どうしの積を省いて補正する」処理を、拡張前の短い仮数の下位ビットにかけてしまう。`align_c` の格子の計算（`ea + m`）もずれる。
   - 修正案: 拡張したオペランドを演算の形式で `decode(f, encode(f, v))` し直す（`rnd` と同じ扱い）。add と passa では不一致は出なかった。
3. **`fvr_flags`: `fv*r`（SDM にない単精度の出力丸め）のマスクフラグ**
   - 公式は半精度 2 個の結果について bit 3、bit 2 に 1 ビットずつ（正なら 1）、bit 1、0 は 0。Sim の `mau_flags` は 2 要素を 2 ビットずつにする。z は一致する。
4. **`round_twice`: 出力丸め付きの加算で、もう一方の加数がごく小さい場合**
   - SDM 4.3 は「縮減後の精度に直接丸める」と書き、Sim もそうしている。公式は、縮減後の精度でちょうど同点になる値に小さい加数が付くと、それを無視して偶数丸めにする。
   - 探査の結果（c=1+2^-24 に 2^-k を足す `dvfmaur` など）: `dvfmaur` は 2^-54 まで効き 2^-55 から無視、`fvfmar` は 2^-25 まで効き 2^-26 から無視（どちらも元の出力精度の LSB の 2 ビット下まで）、`hvfmar`（積 1.5 付近）は 2^-29 まで効き 2^-30 から無視。丸めない形（`dvfmau`、`fvfma`、`hvfma`）では 2^-105 / 2^-47 まで効いた（Sim と同じ）。
   - 規則を確定するには追加の探査が要る（とくに h）。全行の照合で該当したのは 10 行。
   - fp unit では、元の出力精度での結果が縮減後の精度の同点から 1 ulp 以内の行を「該当しうる行」として `vectors_fixed` から外した（照合で見つかった 4 行はすべてこの条件に入る。テストあり）。

### そのほかの観察

- **アセンブラは `r` をどの精度でも受理するが、エミュレータは半語（dmode=10: h と s）以外では実行時に止まる**（`[invalid argument exception] : ialuc.rounda can be used only with half-word`）。Sim はエラーにせず実行する。`r` 付きは h と s だけを生成した。
- アセンブラは SDM で `u` を付けられない ALU 命令（not、and、passa、lsl、packbit、dmax、relu、floor、rsqrt、bfn など）にも `u` を受理し、`is_unsigned=1` を出す。生成した `u` 付き（`sdm=no`）はすべて公式と一致し、結果は `u` なしと同じだった。
- `ugbfn` はアセンブラが拒否する（`udbfn`、`ufbfn` は受理）。`uhbfn/<n>`、`uhbfe/<n>` はアセンブラが受理するが、Sim の構文解析器が `/<n>` をマスクとして読んで失敗するので、生成していない。
- `gv*`（疑似単精度のベクトル演算）はアセンブラが受理しない。`imm` / `immu` は LM0 に書けない（即値と LM0 のアドレス欄を共有）。
- 精度拡張の入力を 2 長語アクセス（`$llr0ve`）で読んでもよく、使うのは上位の要素だけだった（`ext_mul` 以外は一致）。
- RRN の縮約（`hfadd` の 2 段丸め、±∞ の混在、符号違いの max/min を含む）は全 186,396 行が一致した。L1BM の `e` / `r` 付きと `l2bmr@<集合>` は作っていない。

## 契約変更の要望

1. **§1 の食い違いの扱い**: lead が案 (b)（該当行の期待値を公式エミュレータの出力にし、RTL は公式に合わせる）を採用した。`--official-expect` として実装済み（上の「追加作業」）。
   - 契約 §1 に「Sim と公式が食い違う行は、vecgen の `--official-expect` で公式の出力を期待値にする。ヘッダに `disputed=` と `expect=official` を残す」と追記してほしい。
   - Sim の修正（上の「修正案」）は今後の課題として残る。直した後は `--official-expect` の `replaced` が 0 になるはずなので、その確認で修正の正しさも確かめられる。
2. **§5 `.vec` 形式の追記**: 1 行目のヘッダに、`unit`、`op` のほか、機械語の欄（`dmode`、`aluop` など）、`sdm`、`disputed` / `excluded`、`seed`、`edge`（先頭の境界値の行数）、`rows` を `key=value` で並べた。行ごとに変わる命令の欄（`ra`、`rb`、`signa`〜`extc`、`pe`）は列にした。§5 の例と互換だが、この拡張を契約に書いてほしい。ファイル名は `<unit>/<op>.vec`（`/` を除き、`r` 付きは `.r.vec`）。
3. **§5 vectors_fixed**: 「各 unit から 50 行ずつ」を「各ファイルから 50 行ずつ」と解釈した（1 ファイル 1 命令なので、unit 単位では全命令を覆えないため）。合計 1.5 MB。少なくしたい場合は `fixed --rows` で減らせる。
4. **§2 のフィールドの並び**: 「CSV の列を順に連結すると j 語と一致する」は j 行の列の並びについては正しいが、j 行の並びは CSV ヘッダ（auto_stride の i 語）の並びと MAUC で異なる。フィールド名の対応は WP01 の確定に合わせるよう明記してほしい（下の申し送り）。

## 次の WP への申し送り

- **全体**: 使い方と列の意味は `mncore/vecgen/FORMAT.md`。テストベンチは 1 行目を読み飛ばし、`|` の左右を `%h` で読めばよい。`{x_hi, x_lo}` が 128bit のバス（bit 127 が最初の語の MSB）。フラグは bit 3 が MSB 側の要素。
  ベクタは `--official-expect` をかけたものを使う（`expect=official`）。`disputed=` の付いたファイルは、公式の挙動が Sim と違う所を含むので、RTL は公式の挙動（下の各 WP の注意）で実装する。
- **WP11（整数 ALU）**: `alu/*.vec`（`.r.vec` は s の `r` 付きで SDM にない形。期待値は公式の `r` の丸め（未解決の点 1.）に合わせてある）。2 長語動作でない命令（passa、zero、imm 以外）は、結果の LSB 側の長語に x の LSB 側の長語がそのまま入る（SDM 表 3.9 のとおりで、公式でも一致）。シフト量は 2w で割った余り。`u` は add/sub/inc/dec のフラグ、lsr、max/min だけに効く（ほかは `u` なしと同じ結果を公式で確認）。`zero` は isela=0101、`imm` / `immu` は即値を 4 語 / 1・3 語目に並べる。
- **WP12（FP コアと MAU）**: `fp/*.vec` は `z = fma(a, b, c)` に直接与えられる（mul の c=+0、add の b=1.0 を列に書いてある）。`mau/*.vec` は MAUC の制御ビットを行ごとに持つ。h の `exta`/`extb` は単精度からの丸め（`r`）、`extc` は拡張（`e`）。`dvfma[ud]`/`dvmul[ud]` は `pe` 列の位置で乗算するかが決まる。`ext_mul` と `round_twice` の行の期待値は公式の出力にしてある。精度拡張した a・b は拡張後の値どうしを正確に掛ける（部分積の省略は効かない）こと、出力丸め付きの形ではごく小さい加数を捨ててから丸めること（未解決の点 4. の範囲で確認）を RTL で実装する。`fv*r` のフラグは半精度 1 個に 1 ビット。
- **WP13（FP 系 ALU）**: `fpalu/*.vec`。floor と ftoi は aluop=11110 を iselb（110 / 111）で区別、bfn の h は iselb=9-n。bfn/bfe の行は 1 MAB 分（4 PE の入力と結果）。`r` の丸めは公式の式（上の 1.）で実装する。h の `.r.vec` の期待値はこの式に合わせてある。rsqrt の表は Sim の `float_rsqrt` と公式が一致した。
- **WP31 / WP32（L1BM / L2BM）**: `rrn/*.vec` は全行が公式と一致した。入力の並びは FORMAT.md。
- **WP10（デコーダ）/ WP01（スキーマ）**: flat の j 語での MAUC の位置（1,645 命令から一意に決まったもの）:
  dmode 116..117、enfma 118、round_out 120、signa 126、**signc 127**、passa 128、zeroc 129、mdw/side 130、exta 132、extb 133、extc 134、**signb 135**、isela 136..138、iselb 139..141、iselc 142..144。
  mmode、mw、ma、readh は検体で常に 0 だったので、位置は 119、121、122..125、131 と推定（未確定）。ALUC は 145..161 で CSV の並びどおり（dmode、aluop、is_unsigned、rounda、roundb、isela、iselb）。
- **lead / WP06**: Sim の修正点は「未解決の点」の 1.〜4. と、`r` を半語以外で受理してしまう点、`uhbfn/<n>` を解析できない点。
