### わかったこと（要点）

1. **CSV ヘッダの順は flat の j 行に当てはまらない**。ヘッダ（95 名）は auto_stride の i 語の並びで、j 行（110 列）とは列の数も順序も違う。
   - 差は 15 列ではなく、`wadri` / `radri` / `adri`（計 6 列、54bit）が消え、cycle1〜3 のアドレス 18 列（180bit）、予約 2 列（162..165）、L1BM の 4bit 欄 1 列が増える（95 − 6 + 18 + 2 + 1 = 110）。
   - rfc0 / rfc1 は `wadr, wwl, rwl, radr`、MAUC は `…, ma, signa, signc, passa, zeroc, mdw/side, readh, exta, extb, extc, signb, isel…` の順。
   - 各列の名前は、両モードで受理された語で auto_stride の名前付き列と値が全語一致することで決め、プローブ（符号反転、精度拡張、マスク、`j<madpe>` など）で意味を確かめた。
2. cycle1〜3 のアドレス欄の名前は `pe_rfc0_wadr_c1`、`pe_rfc0_radr_c1`、`pe_rfc1_wadr_c1`、`pe_rfc1_radr_c1`、`pe_lm0_adr_c1`、`pe_lm1_adr_c1`（c2、c3 も同様）。単位は単語。
3. **`ll`（先頭 2bit）**はエミュレータで確認した: 01 通常、11 noforward、00 nop（他の欄が立っていても何も書かない）、10 はエミュレータが停止。
4. **L1BM の 187..190 と 191..194**: 2024 年版 assemble3 は同じ値を両方に書くが、エミュレータは前者を MAB 番号、後者を縮約 opcode として読む。名前を `l1bm_mabadr` と `l1bm_opcode` に分けた。
5. `zero_sel` は isel と同じ符号（00 MAU / 01 ALU / 10 L1BM / 11 行列読み出し）。縮約 opcode は fadd 0000、max 0001、min 0010、iadd 1000、band 1001、and 1010、bor 1100、or 1101。MV の縮約転送では {destid の bit0, srcid} が opcode になる。
6. 即値の配置は Scrapbox の j 列どおり。全 32bit を 1bit ずつプローブして確認した（`tests/data/imm_probe.*`）。imm の語では LM0 を使えない（assemble3 が拒否）ので、LM0 の欄はすべて即値として扱ってよい。
7. `pe_mrc_ifsel` は「$omr に書くのが MAU 命令式なら 1」、`$mb` / `$nb` の書き込みは LM0 / LM1 の欄の組み合わせ（write=1、maadj=0、madpe=11）で表す。

## 未解決の点

UNKNOWN.md の A 節。主なもの:

- 行列レジスタの制御（`pe_mauc_readh`、`pe_mauc_mdw_side`、読み出し時の `pe_mauc_ma`）の正確な意味。`readh` は「書き込み先 `$lx` / 積で `$ly` / 読み出し元 `$lx` のとき 1」という観測則（例外なし）までは確定。
- `l1bmd+<n>` の L1BM アドレスの符号化、`l1bm_me` の意味、L1BM 縮約の ext / round_out を単独で立てたときの動作。
- 縮約でない L2BM 転送で `l2bm_opcode` に常に 1100 が入る理由。
- MV: `@n.m` の n と m の意味、`indirect=1` のときの `adra` の符号化、L2BM⇔PDM・PDM→PDM での `adra` / `adrb` の一般則。
- assemble3 `--ll-mode`（cold / hot / mix）が実機で何を切り替えるか。

いずれもビット位置は確定しており、decode / encode と往復検証には影響しない。

## 契約変更の要望

1. **§2 の命名例**: `l1bm.mabadr/opcode → l1bm_mabadr_opcode` は auto_stride の欄。flat では同じ CSV 名の列が 2 つ（187..190、191..194）あり、エミュレータの解釈どおり `l1bm_mabadr` と `l1bm_opcode` に分けた。例を `pe.mauc.mdw/side → pe_mauc_mdw_side` などに差し替えてほしい。
2. **§2「フィールドの出所」**: 「CSV の列を順に連結すると一致する」に加えて、「CSV ヘッダは auto_stride の並びで、flat の j 行の列名には使えない。列名は `spec/isa/j_flat.yaml` の `csv_col` で引く」と明記してほしい。
3. **§2 / §7 の `.asm` の行**: assemble3 の出力には `j` / `m` / `d` のほかに `r` 行（.vsm に書かれたデータ行の素通し）が現れる。WP02（ndmp 変換）と WP04（ホストツール）の対象に `r` 行を加えるか、扱いを決めてほしい。
4. **§7 の停止理由**: `ll=10` はエミュレータが停止するので `E_DECODE`、`rsv_162` / `rsv_164` が 0 以外なら `E_UNSUPPORTED <field>` とする案を提案する（WP10 の `unsupported` 出力の基準）。
5. **CLAUDE.md の環境**: このリポジトリの git 設定（`core.autocrlf=true`）では submodule の `.vsm` が CRLF でチェックアウトされ、assemble3 は `Trailing letter after location` で失敗する。assemble3 に渡す前に CR を除く（`mnisa/assemble_corpus.sh` はそうしている）旨を書くか、submodule 側に `.gitattributes` を置くことを提案する。

## 次の WP への申し送り

- **WP10（RTL デコーダ）**
  - `j_flat.yaml` / `m.yaml` の `fields` をそのまま使える。`pos` は左端 = MSB、Verilog では `jw[425-pos]`。値 v の bit k は `jw[425-(pos+width-1-k)]`。
  - 4 サイクル分のアドレスは `cycle_addr`、即値の組み立ては `imm_layout`（segments の `bits` / `pos` / `replicas`）を使う。
  - **imm の語（`pe_aluc_aluop=11111`）では `pe_lm0_write` / `pe_lm0_isel` / `pe_lm0_adr` / `pe_lm0_tregadr` / `pe_lm0_maadj` / `pe_lm0_madpe` / `pe_lm0_wl`（と cycle1〜3 の LM0 アドレス）と ALUC の dmode / rounda / roundb / isela / iselb が即値ペイロード**。LM0 の制御として解釈してはいけない。imm の語では LM0 は出力先にも他の命令式の入力にも使えない（assemble3 が拒否する）ので、LM0 を止めればよい。
  - `ll=00` は語全体を nop にする（他の欄を見ない）。`ll=11` は noforward。`ll=10` は不正。
  - `l1bm_mabadr` と `l1bm_opcode` は別々に読む（2024 年版 assemble3 は同じ値を両方に書くが、意味は別）。`enum_when` は enum が意味を持つ条件。
  - 期待値の生成: `verify_corpus.py` を一度実行すると `mncore/tools/mnisa/build/corpus/out/*.flat.asm` にコーパスの全語が残る。`mnisa.decode()` の出力を期待値に使える。
- **WP14（PE メモリとアドレス）**
  - flat のアドレスはすべて単語単位（GRF 9bit = 512 語、LM 12bit = 4096 語）。LM0 / LM1 はサイクルごとに読み書き共通の 1 アドレス。
  - `$mb` / `$nb`（ベースアドレスレジスタ）への書き込みは write=1、maadj=0、madpe=11、wl=00 の組み合わせ。
  - 語長欄（`pe_rfc*_wwl` / `rwl`、`pe_lm*_wl`）は使わない語でも 01 になることが多い。write・isel・入力セレクタと合わせて解釈すること。
- **WP02 / WP04**: `.asm` に `r` 行が現れる（上の契約変更の要望 3）。`mnisa.asm_io` は種別 `r` として保持する。
- **全体**: assemble3 に `.vsm` を渡すときは CR を除くこと。
