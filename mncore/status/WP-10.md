### インタフェース

`mn_dec_j`（入力 `jw[425:0]`、`jw[425-pos]` が pos）:

| 出力 | 意味 |
| --- | --- |
| 110 欄 | j_flat.yaml の `name` そのままの名前。生の値（ll でゲートしない） |
| `exec` / `nop` / `noforward` | ll が 01 か 11 / ll = 00 / ll = 11 |
| `cyc_rfc0_w`、`cyc_rfc0_r`、`cyc_rfc1_w`、`cyc_rfc1_r`（36bit）、`cyc_lm0`、`cyc_lm1`（48bit） | `cycle_addr` の 4 サイクル分を `{c3, c2, c1, c0}` で束ねたもの。cycle c は `cyc_x[w*c +: w]` |
| `is_imm`、`imm32[31:0]` | aluop = 11111 と、`imm_layout` で組み立てた即値。imm / immu の区別は `pe_aluc_is_unsigned` |
| `grp[14:0]` | 発行グループのフラグ（下表）。ビット番号は `MN_J_GRP_*` |
| `unsup_vec[109:0]` | 欄ごとの「未対応の値」フラグ（ビット番号 = YAML の欄番号 `MN_J_<欄>_IDX`） |
| `err_kind[1:0]`、`err_field[6:0]` | `` `MN_DEC_OK `` / `` `MN_DEC_E_DECODE ``（ll = 10）/ `` `MN_DEC_E_UNSUPPORTED ``。`err_field` は最初（番号が最小）のフラグの欄番号 |

`mn_dec_m`（入力 `mw[81:0]`）: 12 欄（`mv_valid` など）、`mv_unsup_vec[11:0]`、`mv_err_kind`、`mv_err_field[3:0]`。

発行グループ（`exec` でゲート。WAIT だけは ll ≠ 10 でゲート）:

| ビット | 名前 | 条件 | 根拠 |
| --- | --- | --- | --- |
| 0 | ALU | aluc の (dmode, aluop) ≠ (11, 00000) | ALU のない語はコーパスで全語 (11, 00000, isela 1000, iselb 111)。その語で ALU の結果を書く語はない |
| 1 | IMM | aluop = 11111 | |
| 2 | MAU | `pe_mauc_enfma` | enfma = 0 の語で MAU の結果を書く語（isel = 00、ifsel = 1 の $omr）はない |
| 3 | MW | `pe_mauc_mw` | `?mwrite` |
| 4 | L1BM | L1BM の欄（gwrite / gadr を除く）のどれかが nop 語と違う、または PE への書き込みが isel = 10 | `l1bm_me` は $lbi を使う式では 0 になる（下記） |
| 5 | L2BM | `l1bm_gwrite`、`l2bm_lwrite`、`l2bm_darsend`、`l2bm_darwrite` のどれか | どれも 0 の語では L2BM の全欄が nop 語の値（コーパス全語） |
| 6 | WAIT | wd ≠ 0（ll = 00 の語でも有効） | `nop ; wait i01` は ll = 00、wd = 01 になる |
| 7〜11 | WR_T、WR_GRF0、WR_GRF1、WR_LM0、WR_LM1 | 各 write。LM0 は imm の語と $mb を除く。LM1 は $nb を除く | |
| 12、13 | WR_MB、WR_NB | write = 1、maadj = 0、madpe = 11 | `$mb` は wl = 00、`$lmb` は wl = 01 |
| 14 | WR_OMR | omr ≠ 0 | |

未対応の値の規則（YAML から生成。期待値は mnisa の `enum_applies` / `enum_name` で計算）:

- ll = 10 → `E_DECODE`（field = ll）。
- ll が 01 / 11 のとき:
  - `rsv_162` / `rsv_164` ≠ 0。
  - enum 表が全値を挙げていない欄で、enum が当てはまる（imm の語のペイロード欄は除く、`enum_when` が成り立つ）のに表にない値 → `E_UNSUPPORTED <欄>`。
- 対象の欄:
  - j: `pe_rfc0_wwl`、`pe_rfc0_rwl`、`pe_rfc1_wwl`、`pe_rfc1_rwl`、`pe_lm0_wl`（imm 以外）、`pe_lm1_wl`、`pe_aluc_isela`（imm 以外、1111）、`rsv_162`、`rsv_164`、`l1bm_opcode`（rmode = 1）、`l2bm_bdmode`、`l2bm_opcode`
  - m（valid = 1 のとき）: `mmode`、`tmode`、`dmode`
- ll = 00 の語は検査しない（エミュレータは nop の語の他の欄を無視する、UNKNOWN.md C.1）。
- コーパスの全語で、どのフラグも立たないことを確かめた。

## 未解決の点

1. **行列の読み出し（`?mread`）には専用の欄がない**。
   - `gmread $ly0 $nowrite` は nop と ll・`pe_mauc_dmode` だけが違い、`dmread $ly0 $nowrite` は ll だけが違う。
   - そのため、発行グループに MREAD を置けない。`$mreadf` をいつ更新するか（毎ステップか）はエミュレータで確かめる必要がある（WP20）。
2. **`nop ; wait` の語は ll = 00**。
   - assemble3 は `nop ; wait i01` を ll = 00、wd = 01 として出す。wait と並べられるのは nop だけ（`nop ; lpassa …` などは拒否）。
   - デコーダは WAIT を ll = 00 でも立てる。
   - エミュレータが ll = 00 の語で wd を見ることは確かめていない（assemble3 の出力からの推定）。
3. **UNKNOWN.md A の `l1bm_me` の記述は不正確**。
   - 「L1BM 命令式を含む語で常に 1」とあるが、ターンアラウンドレジスタ `$lbi` を使う式では 0 になる。
     - 例: `l1bmm4@1 $lr0 $lbi` → bmode = 10、lwrite = 1、me = 0
     - 例: `l1bmm4 $llbi $llr12 …` → lwrite = 1、me = 0
   - コーパスの 132 本に現れる。
   - me は「L1BM の記憶へのアクセス」を表すと読める。デコーダの L1BM フラグは me に頼らない定義にした。
4. **ll = 00 の語は未対応の検査をしない**（上記の方針）。assemble3 が出さない語なので、実際のプログラムには影響しない。
5. **使われない欄の値も検査する**。
   - 例: write = 0 の語の `pe_rfc0_wwl = 11` も `E_UNSUPPORTED` にする（保守的）。
   - assemble3 は出さない値なので、コーパスには影響しない。
6. **意味が未確定の欄（UNKNOWN.md A）は未対応扱いにしていない**。`readh`、`mdw_side`、`ma`、`l1bm_ladr` の `+n`、`l2bm_opcode` = 1100、m の `adra` / `indirect` など。コーパスで普通に使われるため。意味は各ユニットの WP が実装時に決める。
7. このリポジトリは `core.autocrlf=true` なので、生成物と `.memb` は CRLF でチェックアウトされる。
   - `gen_dec.py --check` と `--check-fixed` は CRLF を LF にそろえてから比べる。
   - iverilog の `$readmemb` も CRLF で問題なかった。

## 契約変更の要望

1. **§2 の命名**: m 語の欄は、Verilog のポート名を `mv_<name>` にした（例: `mv_priority`、`mv_adra`）。
   - `priority` は SystemVerilog の予約語で、`iverilog -g2012` も verilator も `.v` を SV として読むため。
   - 「m の欄は `mv_` を付ける」と明記してほしい。
   - j の欄は yaml の `name` のままで、予約語との衝突はない（`gen_dec.py` が検査する）。
2. **§2 の ll**: 「`00` nop」に「ただし wd（wait）は ll = 00 の語でも有効（`nop ; wait iXX`）」を加えてほしい。
3. **§7 の STATUS**: `E_UNSUPPORTED <field>` の `<field>` は、デコーダの `err_field` を使うことを提案する。
   - 値は YAML の欄番号で、j は 0..109、m は 0..11。
   - 名前は `MN_J_<欄>_IDX` / `MN_M_<欄>_IDX` で引ける。
   - j と m の区別は 1bit 足す。
   - WP04 の `PROTOCOL.md` にこの符号化を入れてほしい。
4. **UNKNOWN.md（WP01 の担当）の修正**: 未解決の点 2（wait は ll = 00 の語にも入る）と 3（`l1bm_me` = 0 の L1BM 式がある）を反映してほしい。
5. **§5**: 小さな固定ベクタとして `mncore/sim/vectors_fixed/dec/` に 240 KB をコミットした（j の 1 行が 2,740bit のため）。この大きさで問題ないか確認してほしい。

## 次の WP への申し送り

- **WP20（PE コア）**
  - `mn_dec_j` は組み合わせ回路。パイプラインのレジスタはコア側で置く。
  - ll の扱い:
    - `exec = 0` の語では、WAIT 以外のグループが 0 になる。
    - `err_kind ≠ OK` なら停止する（ll = 10 は `E_DECODE`）。
    - `noforward` の語では、書き込みは行い、`$aluf` などと `$lbi` は更新しない。
  - WAIT は ll = 00 の語でも立つ。
  - `grp[MN_J_GRP_ALU]` / `MAU` / `L1BM` / `L2BM` が、その語で動く演算器の目安。
  - `$mreadf` の更新条件はフィールドから決まらない（未解決の点 1）。
  - m 語は `mn_dec_m`。`mv_err_kind ≠ OK` なら停止する。
- **WP14（PE の記憶）**
  - 4 サイクルのアドレスは `cyc_*`。
  - imm の語では `pe_lm0_*` と `cyc_lm0` がペイロードなので、LM0 を動かさない。`grp[WR_LM0]` は 0 になる。
  - `$mb` / `$nb` は `grp[WR_MB]` / `grp[WR_NB]`。語長は `pe_lm*_wl`（$lmb で 01）。
- **WP11 / WP13（ALU）**
  - `MN_J_PE_ALUC_ALUOP_<名前>` などの enum 値を `` `include "mn_jfields.vh" `` で使える。
  - 即値は `imm32` と `pe_aluc_is_unsigned`。長語は imm なら `{x, x}`、immu なら `{x, 0}`（UNKNOWN.md C.7）。
