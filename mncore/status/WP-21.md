### `mnhost.py run` の修正（WP20 の申し送り）

- `r` 行（DRAM の初期データ）は、DRAM のない設計では読み飛ばして数だけ出す。
- 実装していない空間（INFO の深さ 0）・位置の `d set` / `d get` は飛ばし、深さを超える部分は切る（`d get $lm0 2048` は 512 長語だけ読む）。`d set` で捨てた長語は警告で数を出す。
- `$omr` の `d get` を扱う（空間 0x10。エントリ 0 は全 1、16〜31 は固定パターン）。OMR は PE の空間がある設計にあるものとした（INFO には 0〜15 の空間しか載らない）。
- ndmp の単位を公式のダンプの正規化（WP02 の `norm_gpfn3.py`）に合わせた: 単語アクセスは `LM0W` などに単語アドレスと 32bit の値、T は `2 × サイクル + k`、OMR はエントリ × 4 + サイクル。同じ場所は後の `d get` が勝つ。
- `RUN` が誤りで止まったら終える。E_RANGE の info は窓の中のエントリ番号なので窓の先頭を足して語番号で出す。
- `rtl/board/PROTOCOL.md` §6 と INFO のデザイン ID（0x02）を合わせて直した。

## 未解決の点

1. **全部入り（FPALU = 1）と FPALU = 2 は配置できない。** nextpnr の HeAP の legaliser が最初の反復で「Unable to find legal placement for all cells, design is probably at utilisation limit」で止まる。シード 1・2、`--placer-heap-no-ctrl-set`、`--placer-heap-beta 0.75`、`--placer-heap-cell-placement-timeout 0`、`--no-tmdriv`（シード 3）のどれでも同じ。`--placer sa` は nextpnr が落ちた（0xC0000005）。
   - `--debug-placer` で見ると、何度も置き直されるのは、ALU（キャリーチェーン）の出力を D に直接受ける FF（`mn_pe_lsu` の LM アドレスのラッチ `m0a_l` / `m1a_l`、`brd_host_if` のタイムアウト計数 `tmo`）だった。原因の特定まではしていない。
   - 実測の境目: WP20 の RTL の FPALU = 0（LUT4 77%、DFF 61%）は置けたが、FPALU = 2（LUT4 77%、DFF 62%、ALU が 254 多い）は置けない。FPALU = 3（LUT4 75 %、DFF 62 %）は置けた。**この設計では LUT4 75 % 前後が実用上の上限**とみてよい。
   - 全部入りを載せるには、FPALU = 1 を LUT4 83 % → 75 % 程度（LUT 換算で約 −1,600）まで減らす必要がある。候補: WP14 の案 C（`mn_pe_lsu` の縮小、−1,000〜1,500 の見積もり）、WP12 の案 D（加数の位置合わせ窓、−500〜800）、`brd_host_if` の縮小（INFO / STATUS の生成、16〜32bit の計数器。単体で 2,262）、フォワーディングレジスタ `$aluf` / `$mauf` を 1 つの LUT RAM にまとめる（RAM16SDP4 64 → 32、書き込みデータの選択が増えるので差し引き約 −250）、MAU の結果バッファを外す（WP20 の案 G、−260、MAU が遅くなる）。
2. `FPALU = 3` で外した命令（floor / ftoi / fmax / fmin）を使う 3 本（`13.mod3`、`14.exp/main`、`14.exp` の kernel）は実機では `E_UNSUPPORTED`。bfn（1 本）は MAB の 4 PE が要る（WP30）。
3. hello_world は 1 PE では動かない（L1BM・L2BM・MV。WP20 から変わらない）。
4. 速さ: 27 MHz で 1 語あたり約 33 クロック（WP20）に、READ の直列化のぶん（読むメモリが 2 つ以上の語で数クロック）が加わる。Fmax は 56 MHz なので PLL で 54 MHz にすることはできるが、`brd_host_if` の `CLK_HZ` と UART の分周を合わせる必要があり、M1 では行っていない。
5. 命令メモリの読み戻し（`IMEM_RD`）は面積のために外した。
6. `top_1pe` の unit は UART のビット単位のモデルで駆動するので遅い（負荷のないときで約 3 分、他の重い処理と並べると約 9 分）。560 語の窓の切り替えは既定の台本では回さず、実機の回帰で確かめた。
7. INFO には空間 0〜15 の深さしか載らないので、`mnhost.py` は OMR（0x10）を「PE の空間がある設計にはある」とみなしている。

## 契約変更の要望

1. **§6 の資源の項に、WP21 の実測を載せてほしい。** トップ全体（host_if を含む）で、最終の RTL の FPALU = 0 が LUT4 71 %（14,872）、DFF 57 %、BSRAM 23、DSP 8、Fmax 56 MHz。FPALU = 3 が LUT4 75 %（15,582）、DFF 62 %、Fmax 48 MHz。FPALU = 1 は LUT 換算 16,900（nextpnr の LUT4 83 %）で配置できない。**nextpnr-himbaechel ではこの設計の配置の上限が LUT4 75〜77 % 程度**なので、予算は 75 % を上限にするのがよい。
2. **§6 に「RAM16SDP4 は CFU を 1 つ使う（nextpnr の集計で LUT 8 個と DFF 6 個の場所。DFF の分は WP21 で RAM16SDP4 を 96 個減らしたとき DFF が 576 減ったことから）」を書いてほしい。** 4 深さで使うと 4 分の 3 が無駄になる。浅いメモリをいくつも置くときは 16 深さにまとめる（WP21 の共有読み出しバッファ）。
3. **§7 / PROTOCOL.md: デザイン ID 0x02 = `mn_top_1pe`**（PROTOCOL.md には反映済み）。また、INFO に設計固有の空間（0x10 OMR、0x11 BAR）の深さを載せる手段がない。版 2 で載せるか、「PE の空間があれば OMR 16 エントリ、BAR 2 長語」と決めてほしい。
4. **§4 / §7: `mnhost.py run` の ndmp を WP02 の単位に合わせた**（単語アクセス → `LM0W` など、T、OMR。PROTOCOL.md §6 に反映済み）。WP04 の「単語アクセスはその長語を 1 行で出す」は廃止。
5. 実機の回帰の標準として `python mncore/fpga/top_1pe/hwrun.py --all --fpalu <n>` を使えるようにした。M2 以降の実機確認にも使えるよう、契約か工程表で名前を挙げてほしい。

## 次の WP への申し送り

- **実機の使い方（M1 のビットストリーム）**: ロックを取る → `python mncore/fpga/top_1pe/build.py --program`（既定は FPALU = 3。20〜25 分。作り済みなら `--fs mncore/fpga/top_1pe/build/FPALU3/top_1pe.fs`）→ `python mncore/tools/host/mnhost.py info`（デザイン 0x02）→ `python mncore/tools/host/mnhost.py run X.asm -o X.ndmp` または `python mncore/fpga/top_1pe/hwrun.py --all`（`--fpalu` の既定も 3）→ ロックを消す。`hwrun.py` の前に `python mncore/sim/regress/run.py`（公式の結果のキャッシュ）と、FPALU ≠ 1 なら `run.py --define TB_FPALU=<n>`（RTL の期待）が要る。`hwrun.py` はロックのファイルがないと動かない。
- `mn_top_1pe` と `build.py` の既定は FPALU = 3（置ける中で最も大きい構成）にした。
- **WP30（MAB）**: 1 PE で LUT4 71〜75 % なので、4 PE をそのまま並べることはできない。仮想 PE（WP34）か演算器の時分割が前提になる。`mn_pe_core` は `mn_pe_lsu` の `RBS = 1`（読み出しは 1 メモリずつ）と、収集のときの丸め（FPALU ≠ 0）を使っている。
- **WP34（仮想 PE）**: `RBS = 1` はストアの遅延によらない（下位のメモリの応答がすべて返ってから次のメモリを要求する）。`tb_pemem` の遅いストアで確かめた。
- **WP14 / WP12 / WP04（lead）**: 全部入りを載せるには約 −1,600 LUT 換算が要る（未解決の点 1）。大きい部品は `mn_pe_lsu`（LUT 3,067）、FMA（LUT 2,605 + ALU 509）、FP ALU（約 2,640）、`brd_host_if`（2,262）、`mn_alu_int`（約 1,620）。
- **WP02**: `mnhost.execute_program()` は `norm_gpfn3.py` と同じ単位のレコードを返す。`hwrun.py` は `run.py` の `keep_record` で比べる。
